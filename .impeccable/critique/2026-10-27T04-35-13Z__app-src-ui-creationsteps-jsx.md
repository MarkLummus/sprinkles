## Priority Issues

- **[P1] After a refused Save, a one-sided target's Required stands under the wrong field.** Measured (WebKit 1366; Chromium the same at its widths): a target with label "temp" and an empty value draws Required at x 324, y 964, 211.3 × 15, under the value field, while it is the standing `.field-requirement`; press Save and the same word is rendered as `.field-error` and moves to x 111, under the filled "temp" field (the value field at x 324 has nothing under it). A target with an empty label and "4 °C" is right in both forms (x 111) only because the first column is the grid's default. **Why it matters:** D-10 says Required under the empty field; at the one moment the maker is being refused, the word points at the field that is filled. The cause is in the stylesheet: `notebook.css` 243 to 255 place `.target-chip__label-field + .field-requirement` and `.target-chip__value-field + .field-requirement` in columns 1 and 2, and `.field-requirement` in row 2; the refused press renders the message with the `field-error` class (as every other refused message does), which none of the three rules name, so it takes the grid's first free cell. **Fix:** `/gsd-fast`: the three selectors read `:is(.field-requirement, .field-error)`; then run `11-board-steps.mjs` (pB1) and look at the chip after a refused press. No board draws a one-sided target (11-06 SUMMARY), so the sketch does not change. **Suggested command:** /impeccable fix (through `/gsd-fast`).
- **[P2] "Version 1 · Version 1 · Latest": a first version left at its default name says its name twice, on four surfaces.** Measured: the page's identity line 18/600 "Version 1 · Version 1 · Latest" at 1366, 744 and 393; Home's lead block "Vanilla / Version 1 · Version 1"; the print foot "Vanilla · Version 1 · Version 1 · DNZV-BEFJ" (12 px, 0.02em, under a 1 px rule); the edit ceremony's own caption reads "Version 1 · editing" once. `versionIdentity` (lineage.js 58 to 62) prints "Version {n} · {versionLabel}" and the create draft's default Version name is "Version 1" (draft.js 575), so the ordinal and the label are the same words.
