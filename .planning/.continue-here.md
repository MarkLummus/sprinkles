## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| A narrow artboard is not a narrow viewport | The 393 board linked the app's stylesheet and rendered with the rail, the two-column Sheet and the 48px gutter, because the canvas does not put an artboard in a viewport of its own width; it clipped twice and every ingredient wrapped. | blocking | Narrow boards carry the app's `@media` bodies unwrapped in the helmet style (`.planning/canvas-generators/phone-forced.css`) and restate `--gap-page`. Height is measured locally with the stylesheet inlined (gsd-browser, root at `height:auto`, read scrollHeight), never guessed; the frame gets headroom for Caveat, which the local render cannot load. |
| Regenerating the source drops an earlier edit | Rebuilding the `SHEET` fragment to add the tab row silently lost the Method → Instructions rename on all fourteen boards; Mark had already approved the rename. | blocking | Every canvas change is a change to `gen.py`, never a one-off patch of an output file. After a regenerate, grep the outputs for every approved change before publishing (Instructions, style 6 table, the chip, the hand, the folds, no Carried forward). |
| Publish refused after a page save | Mark saves the canvas constantly (moving boards, notes); every publish that follows conflicts even when the sent files are unchanged. | advisory | Read the artifact's bare URL (no path) after the refusal, then publish; re-read `project/canvas.json` right before any publish that sends the index; never `force`. |
| Auto-reply promises the wrong thing | Comment auto-replies promised a create/edit form that does not exist, "older log groups" that do not exist, and a flex fix for a table-column problem. | advisory | Read the thread, act from the boards and the briefs, then post one correcting reply with `acknowledge_duplicate` before resolving. |
| Arguing against my own drawing | I drew the stacked as-made (alternatives 2 and 4) then argued against stacking; Mark called it. | advisory | When drawing alternatives on request, say up front which one I would not choose and why, and do not lean towards it in the thread reply. |
