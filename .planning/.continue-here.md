# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each was discovered through actual failure this session.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **`resize_window` does not relayout the viewport in claude-in-chrome** — Both assessments hit this. The tool returns "Successfully resized" while `innerWidth` stays at its original value and only `outerWidth` drops; `matchMedia('(max-width: 759.98px)')` stays `false` and a screenshot confirms the old layout. Any responsive measurement taken after a bare `resize_window` is wrong. — **Mitigation: use the same-origin iframe proxy.** Inject an `<iframe>` at the same route, set its width, and read `iframe.contentWindow.innerWidth` / `matchMedia` inside the frame. This is the project's own established technique and it resolves media queries correctly. Phase 4 is print CSS and media queries, so this constraint is directly load-bearing for the next work.

- [ ] CONSTRAINT: **Scripted `.focus()` does not set `:focus-visible`** — A first probe reported "no focus indicator" on every control and that conclusion was false. Focus rings are real and measure 2px solid ink at 17.16:1. — **Mitigation: drive real keyboard Tab presses before concluding anything about focus styling.** Never report a focus-ring defect from a scripted focus call.

**Do not proceed until all boxes are checked.**
