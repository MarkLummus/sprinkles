## Phase Goal

**As a** home ice cream maker, **I want to** open the churned olive oil recipe in Sprinkles and read it whole — its twelve ingredient rows, its method, its target bands, its authored notes, and its balance figures with the basis they rest on — **so that** I can work from the app instead of the printout.

*Provenance: a mechanical restatement of the ROADMAP `**Goal:**` line for Phase 1, which is not itself written in user-story form. Actor from PROJECT.md's persona; outcome from the phase's own success criterion 4. Run `/gsd mvp-phase 1` to restate the ROADMAP Goal line itself.*

<objective>
Turn the skeleton's semantic regions into the Formulation Cookbook spread the confirmed brief describes, and finish the seeded content so the page carries the sheet's method and its authored notes.

Purpose: this is the slice that makes the page readable as a recipe rather than as a data dump. It also lands the design authority in the right order — the Impeccable direction contract is written into the brief before any visual token exists in code, so nothing about the world is invented by a builder ahead of the record that fixes it.

Output: the direction contract in the brief, a token layer implementing it, the completed version record, and the method and authored notes on screen.
</objective>

The contract closes these seven items, and only these, each stated as a decision with a concrete value rather than a suggestion:

1. **Type.** The working text face with true italics used for the headnote and method prose, and the grotesk with tabular numerals used for the ingredient table and every figure. Give each as a full CSS font stack, plus the type scale: running head, recipe name, version line, headnote prose, table body, figure value, deviation words, small print. Tabular numerals must be switched on for the table and the figures so gram columns and figure values align on the decimal.
2. **Colour, four roles only.** Ground (cool text-paper), ink (print black), pen blue (everything recorded — unused in this phase, defined so Phase 2 does not invent it), and one bookcloth colour that identifies the book in running heads and section tabs and never carries state. Give exact values. State that no fifth colour is defined, that the scheme is light only because the scene forces it (a kitchen table in the evening and a black-only laser printer), and that colour never signals status, verdict, or uncertainty anywhere on this surface.
3. **Spacing scale.** The step values, and which step separates the spread's regions.
4. **Rule drawing.** Weights for the graduated rule's baseline, its graduations, its band edges, and its tick; and the hatch pattern that draws an authored target band. Plan 01-03 consumes these values; it must not choose them.
5. **Focus treatment.** How a focused balance figure and its contributing ingredient rows change appearance: weight and outline only, never position and never colour, per the brief's carried raise that state changes weight and outline and that nothing moves on selection or hover.
6. **Plain-language block names.** The visible name each region of the spread wears: the headnote, the ingredient table, the formulation note, the method, the margin. Every block wears its name, per the brief's carried raise.
7. **What stays open after this contract.** Name them so a later phase does not read silence as a decision: whether authored notes copy into a child version by default or by explicit choice (Phase 3 decides — the binder's Mexican Chocolate v3 is the recorded failure mode of silent copying); whether the version strip shows the batch count per version (Phase 2 decides); and the product-level text-contrast standard, which is undecided above the AA floor the requirements set.

**Binding constraint on the type choice:** faces must be system stacks or self-hosted files inside `app/`. No font is loaded from a third-party origin, and neither is any script, stylesheet, or other asset — Sprinkles is local-only under TRUST-01 and IMP-01, and a font request is a network request that carries a page view with it. If a self-hosted file is chosen, commit the file under `app/public/` and reference it with a local font-face rule.

Then write `app/src/styles/tokens.css` defining every value above as a CSS custom property on the document root, and import it ahead of `app/src/styles/app.css`. Rewrite `app/src/styles/app.css` so every colour, face, size, spacing value, and rule weight it uses reads through a custom property — no literal colour and no literal face survives in a stylesheet or a component. Apply the contract to what already exists: the recipe list, the headnote, and the ingredient table.

Do not decide anything the contract does not list. In particular: no rating control, no stars, and no label for Optimize, Scale, or Template (D12 leaves those open), and no colour-coded status of any kind.
