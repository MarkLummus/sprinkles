## Phase Goal

**As a** home ice cream maker, **I want to** open the pen on a version I have already churned, change it with the old values struck beside the new ones, and save the result as a next version that names its parent and my reason, **so that** I can develop the recipe without touching the record of what I actually made.

*Provenance: as recorded in `03-01-PLAN.md` — a mechanical restatement of the ROADMAP `**Goal:**` line, not a new story. Run `/gsd mvp-phase 3` to make the ROADMAP line itself a user story.*

<objective>
Put the reason on the page that makes the change, and make every version of a recipe reachable from every other.

Purpose: this is the requirement the churn-log audit produced. The reason for a change is almost never on the page that makes the change, and the one time the app gave Mark a field he wrote a properly formed delta with the previous value in it. It also answers the Phase 2 design debt directly: saving lives where the version is named, at the top of the page, not at the foot of the longest column. And it discharges FORM1-03 by adding nothing — the save path never learns what a band is.

Output: the ceremony in full in `Headnote`; the lineage line; `VersionStrip`; the recipe list grouped to one row per recipe; the running head as the link home and a real `No recipe found`.
</objective>

Add `blockedSaveMessage(penFields, version, versions)`, a pure function returning the one message that blocks the save, or `null` when nothing does, in a fixed order so the maker is told about one thing at a time: a blank or whitespace-only version line returns `a version needs a line`; a line that collides through `versionLineUnique` returns `another version already has this line`; an active row whose grams field is empty returns that row's own message, built as the row's ingredient name followed by ` needs an amount, or remove the row`, taking the first such row in the version's authored order. `blockedSaveMessage` never looks at a band, a deviation or an advisory. FORM1-03 is discharged by that absence, not by a rule that permits it.

**`app/src/ui/Headnote.jsx`.** In `developing` mode the headnote carries, in this order and in this tab order: the version line field (blank; the value the pen opened on beneath it as `was 50 g oil · 800 g`; required); the reason field in the text face (blank, optional, a textarea sized for a short paragraph); the citation — `citableBatches` rendered as a list where each batch is one tap, labelled by `formatRecordDate` of its churn date, with **none chosen by default** and a way to un-choose, or the words `no batch to cite` in ink when the parent has no batch; then `Save as a new version`, then `Save over this version` when and only when the version has no batch recorded against it, then `Cancel`. The blocked-save message renders in words immediately beside the save controls, from `blockedSaveMessage`, and the save controls stay operable — the block is stated, not hidden behind a disabled control the maker cannot ask why about.

Nothing here is pre-filled. There is no default reason, no default citation and no default version line: the app never writes a judgement in the maker's voice, and it never summarises the maker's own changes into a reason for them. A blank reason saves.

A figure outside its band changes nothing on this page: no extra control, no confirmation, no acknowledgement, no differently-worded save. The words beside the figure already say what is outside.

In `reading` mode, a saved child's headnote carries the lineage line beneath its version line, in the text face: `from 50 g oil · 800 g, after the batch of 2 Aug 2026`, where the parent's line is a link to `/recipe/{parentVersionId}` and the batch is a link to `/recipe/{parentVersionId}/batch/{citedBatchId}`.
