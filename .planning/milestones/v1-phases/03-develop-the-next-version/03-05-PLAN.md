## Phase Goal

**As a** home ice cream maker, **I want to** open the pen on a version I have already churned, change it with the old values struck beside the new ones, and save the result as a next version that names its parent and my reason, **so that** I can develop the recipe without touching the record of what I actually made.

*Provenance: as recorded in `03-01-PLAN.md` — a mechanical restatement of the ROADMAP `**Goal:**` line, not a new story. Run `/gsd mvp-phase 3` to make the ROADMAP line itself a user story.*

<objective>
Fill the margin's empty advisory slot with the four structural advisories the version's own data already supports, each stating what it was computed from and none of them saying whether any of it is good.

Purpose: FORM2-02, and the last of the phase's requirements. These are not new math to invent — the earlier attempt's definitions exist as evidence and every number the brief cites is independently reproducible from the seed data already in this repo. Two of the four need genuine rework rather than a straight port: the hydration advisory must also name a method step whose typed target reaches the hydration temperature, and the estimated-exposure advisory must report per figure rather than as a flat list.

Output: `advisories.js` with the four; `DerivedAdvisories.jsx` in the margin between the batch record and the authored notes; the empty `advisory-slot` placeholder finally replaced.
</objective>

**`app/src/domain/advisories.js` (new).** Open with the pure-module header every domain file uses — no framework, no DOM, no store import — and say in the header that the four definitions are reimplemented from the old-sprinkles slice's `advisories.js`, read as evidence and never imported, per D-05. Give every exported function the doc-block treatment `batch.js` uses, citing D-05 and FORM2-02.

Export one function, `buildAdvisories(version)`, returning an array of `{ key, words, basis }`, in the fixed order `sub-scale`, `ultra-pasteurised`, `hydration`, `estimated`, holding only the advisories that are **true of the version as it stands**. Filter through `activeRows` and `activeSteps` before computing anything: a removed row must never reach an advisory, for the same reason it must never reach `computeBalance`.

*Sub-scale amounts.* The rows under the scale's resolution are the active rows whose `grams` are above zero and below `equipment.scaleResolutionG` — for the churned version, guar gum at 0.48 g and lambda carrageenan at 0.16 g against a 1 g resolution. The master blend is every active row whose ingredient `category` is `stabilizer`, each multiplied by `equipment.batchesAhead`: locust bean gum 4.16 g, guar gum 1.92 g, lambda carrageenan 0.64 g, 6.72 g in all, with a take for this batch of 1.68 g. Name the under-resolution rows, the blend's parts, its total, and the take. Basis: the scale's stated resolution and the equipment profile's batches-ahead figure. Return nothing when no active row is under resolution.

*Ultra-pasteurised mass.* Sum the active rows whose embedded ingredient carries `heatTreatment` equal to `ultra-pasteurised` — whole milk 370.4 g plus heavy cream 252.8 g, 623.2 g — and state it against the batch's own computed mass through `formatGrams`, which for the churned version reads `799.7 g`. The brief's illustrative phrasing says "of 800"; 800 g is the batch size the recipe is named for, while the rows sum to 799.68 g, so state the computed mass rather than the nominal one — this app does not round the maker's rows to a number they did not type. Name each contributing row and its grams. Basis: heat treatment recorded on each ingredient. Return nothing when no active row carries the treatment.

*Gum hydration against the hold.* For each active row whose embedded ingredient has a `hydrationC` above `version.process.pasteuriseC`, name the ingredient, its hydration temperature and the hold — locust bean gum at 82 °C against a 69 °C hold. Then scan the active steps for one whose typed target reaches it: read each target's `value`, take a leading decimal number where the string also carries a Celsius mark, and treat the step as a match when that number is greater than or equal to the hydration temperature — step 2's `85 °C` matches. Name the first matching step by its number and its target. There is no formal grammar for a target's value; it is free text. A value the parser cannot read (a range such as `80–85 °C`, or `room`) is simply not a match: the advisory omits the step clause and still states the temperatures. Never throw, and never guess a number out of a string it could not parse. Basis: the ingredient's recorded hydration temperature, the version's pasteurisation setting, and the step's typed target.

*Estimated-data exposure.* Call `buildFigures` over the active-row version and keep every figure whose `estimatedRowNames` is non-empty, naming the figure by its `label` and listing those rows. **Do not rescan the ingredient library**: `figures.js` already decides which rows make a figure rest on estimated or unreviewed data, and building this independently is exactly how the advisory and the rules come to disagree. For the churned version this reports four figures — PAC, POD, MSNF and Total solids — where the brief's parenthetical names three; the parenthetical is illustrative and Total solids genuinely rests on estimated MSNF, so the derived answer is the right one. Basis: the per-field basis recorded on each ingredient. Return nothing when no figure has an estimated row.

*The fifth advisory is not built.* `equipment.minFillG` is read by nothing in this module. Batch mass against the machine's minimum fill is held for SCALE-01, which owns machine capacity and forbids asserting a safe fit (D-05). Say so in a comment beside the sub-scale advisory so a later reader knows the omission was decided, not overlooked.

*Wording.* Every advisory states what was computed and what it was computed from, and stops. No advisory is worded as a verdict or an instruction: it never says a value is correct, fixed, guaranteed, safe, better, worse, too much or too little, never calls anything a problem, never uses the imperative, and never says anything about how the ice cream will taste, melt or feel. Assemble the words from computed parts with their labels, the way `describeDeviation` assembles its own sentence, rather than pasting raw numbers into a template.
