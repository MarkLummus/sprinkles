<objective>
Close G-03-14: stop a removed step and the live step beside it rendering the same numeral in the same voice, so the coverage cue's "still used by step N" points at exactly one step.

Purpose: every number the app prints is already correct under D-UAT-4 — the diagnosis verified the arithmetic in six configurations against the real seed. The defect is typographic. `displayNumberFor` (Method.jsx:105-109) numbers a live step by its position in the current map and a removed step by its position in the baseline map, and returns a bare integer that records nothing about which frame answered; both the pen (:146-148) and show-changes (:320-322) emit that integer into a byte-identical unmarked span, and `.method-step__n` (app.css:483-487) has no removed or struck variant. Removing the step at baseline position k shifts the next live step into current position k, so the two numerals are always equal and always adjacent — guaranteed, not incidental, with the single exception of removing the last step. The pen's " removed" label sits in the other grid column, below a text input and a textarea, so it is neither adjacent to the number nor associated with it. The same duplicate reaches the ingredient table's selector, where a cell can read "2 … + 2" — two different steps, both numbered 2, six characters apart.

Output: one rule for what a removed step's number says in each state, applied at every site that says it, and a test that checks the union instead of the halves.
</objective>

## What this plan is closing

`03-UAT.md` gap **G-03-14** (test 14, minor), under Mark's binding ruling **D-UAT-5**: a removed step's margin number is struck in show-changes, keeping the parent number it had per D-UAT-4, and suppressed in the pen — the empty margin the pen already uses for a step removed before it opened. Live steps read 1, 2, 3 in their new order in both. The coverage cue keeps naming the covering step by its current display number. The step selector option and the orphaned-row flag must not present a removed step's number as if it were a live one.

<flagged_assumptions>
**The selector option and the orphaned-row flag adopt suppression, not a mark.** D-UAT-5 rules that neither may present a removed step's number as if it were live, and leaves the treatment open. Both surfaces exist only in the pen, and D-UAT-5 has already ruled that the pen suppresses. A `<option>`'s text cannot be reliably struck across browsers, and the flag is a sentence in small print where a struck numeral would read as a typo. So both drop the number and name the removed step by its lead-in alone — which is exactly what `OrphanedRowFlag` already does for a step with no position in either version, so the change makes one existing branch the only branch rather than inventing a treatment. The result is a rule that can be stated in one line: **in the pen a removed step has no number, anywhere**. The alternative considered and rejected was moving the number to the front behind a word ("removed step 2: …"), which keeps a numeral on screen that the margin beside it no longer prints.

**The split-step reference beside a suppressed selector is correct and stays.** With step 2 removed, whole milk's cell renders its selector for the removed primary allocation and "+ 2" beside it for its live split into what is now step 2. Once the option's number is dropped, that "+ 2" names one step and one step only. It is left exactly as 03-10 wrote it; nothing here changes what a live reference prints.

**The struck margin number is the same stroke, not a fourth one.** `app.css:366-374` documents the Strike Rule as one stroke for every "not in force" meaning across the app and names "a removed row or step" as one of them, so the meaning already exists and no new token is needed — `--rule-strike` and `--gap-strike` are already declared. The new rule is a modifier of `.method-step__n` rather than a reuse of `.struck-value`, because `.struck-value` also carries a right margin for sitting immediately before the value that replaced it, and a margin number has nothing beside it. `.method-step__prose--struck` (app.css:529-531) is the precedent for a scoped modifier of this kind.
</flagged_assumptions>
