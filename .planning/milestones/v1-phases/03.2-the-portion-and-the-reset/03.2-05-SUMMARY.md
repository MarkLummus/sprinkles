**Both unfiltered `.join(' + ')` sites in `IngredientTable.jsx` now apply the opposite-but-correct rule for a blank portion — the As-made column drops it (a blank means "matched the plan"), the pen substitutes the stored amount (a blank means "keep this amount") — closing the phase's one verification gap (CR-01) with four full-string test assertions that were watched to fail first.**

## Accomplishments

- `formatAsMadeReading` filters unwritten portions out before joining and returns `null` (not `''`) when nothing survives the filter — a partially-recorded split row reads a clean `120` or `100 + 50` instead of a dangling `120 + ` or `100 +  + 50`; an all-blank as-made row reads as no as-made at all, on screen and to a screen reader.

## The two fixed expressions, in prose

- **`formatAsMadeReading` (As-made column, D-10) — filter, do not substitute.** It maps each portion to `asMadeForPortion(batch, row.id, i)`, drops any element that is `null` (the explicit `!== null` test from `asMadeForPortion` is preserved, so a written `0` survives), and joins only what remains. When nothing survives — the row's as-made key is present but every portion is unwritten — it returns `null` instead of the joined empty-string list, so `AsMadeCell` renders nothing and `rowAccessibleLabel`'s existing `asMadeValue !== null` guard drops the `as made` clause entirely. A blank here means "the maker matched the plan"; the plan's own grams are never substituted in — only dropped, never filled.
- **The pen's `changedGrams` (D-01) — substitute, do not filter.** For each draft portion whose typed string is blank (empty or whitespace-only after `.trim()`), it substitutes that portion's own stored amount (`row.portions[i].grams`, coerced to a string) instead of the blank; every other portion's typed string is announced unchanged. A blank field here means "keep this portion's own amount" — exactly the rule `currentGramsValue` three lines above it, `draftVersion` in `RecipePage.jsx`, and `handleSaveBatch` all already apply via `parseGramsDraft(...) ?? portion.grams`. The two sites differ because the two blanks mean opposite things, not because one implementation is more correct than the other — this is the plan's own "shared-helper question, answered: no helper" reasoning, reaffirmed by the fix.

## Fixture/assertion adjustment

One Task 1 assertion needed a scope correction while turning it green (not a fixture change — the fixture itself was correct): the all-blank-portions case originally asserted `not.toContain('as made')` against the *whole* rendered markup. The total row legitimately carries its own `as made X grams` phrase whenever `hasAsMadeLayer` is true — which it is here purely because `openBatch` is non-null, independent of this particular row's own reading. That phrase is correct, pre-existing behavior (the total row's own accessible name), not a leak from this row, so asserting the whole markup failed on a clause the scenario never claimed to test. Fixed by scoping both assertions (`ink-text`, `as made`) to the row's own `tbody` section via the file's existing `sectionMarkup` helper. This is exactly the class of adjustment the plan's own action text anticipated ("if a fixture produces an extra clause... fix it, and record which one and why in the SUMMARY") — recorded here as directed.
