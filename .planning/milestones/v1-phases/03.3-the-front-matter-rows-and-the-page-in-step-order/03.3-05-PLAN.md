Close G-03.3-2: with the uses checklist open in a step's pen, the first Escape
currently closes the whole plan pen instead of only the checklist, because
the scoped Escape handler is attached to the `<fieldset>` alone while focus,

  <action>
    Root cause (confirmed from source, matches 03.3-UAT.md's own diagnosis): `handleUsesKeyDown` (Method.jsx ~123-131) is attached only to `<fieldset className="method-step__uses" onKeyDown={handleUsesKeyDown}>` (~287-291). The `change`/`done` button (`usesControlRef`, ~276-284) that opens/closes the checklist sits in a sibling `<p className="method-step__uses-line">`, outside the fieldset. Clicking `change` leaves focus on that button, so an Escape pressed there never reaches the fieldset's own handler and bubbles straight to RecipePage's document-level listener, which cancels the whole pen (D-24 applies only if the draft is dirty; an untouched pen closes outright).

    Fix: wrap the existing `<p className="method-step__uses-line">...</p>` block and the conditionally-rendered `<fieldset className="method-step__uses">...</fieldset>` in one new wrapping element (a plain `<div>`, no new CSS rule needed — both children keep their own margin-based rules from app.css lines ~930-938 and ~903-920 unchanged, since neither rule depends on being a direct child of `.method-step__body`). Move `onKeyDown={handleUsesKeyDown}` from the `<fieldset>` onto this new wrapper div. Guard the handler itself so it only acts while the checklist is actually open: add `if (!usesOpen) return;` as the first line of `handleUsesKeyDown` (before or after the existing `if (event.key !== 'Escape') return;` check — either order is correct since both must hold). Keep `event.stopPropagation()`, `setUsesOpen(false)`, and `usesControlRef.current?.focus()` exactly as they are — only the element the handler is attached to, and the open-gate, change.

    This makes the first Escape (focus on `change`, or anywhere inside the fieldset, checklist open) stop at the wrapper and close only the checklist, refocusing `change`. The second Escape (checklist now closed, `usesOpen` false) makes the wrapper's handler a no-op, so the keydown event continues bubbling to `document`, reaching RecipePage's own Escape handler exactly as it did before this fix, respecting D-24's unsaved-ink rule unchanged.

    Do not touch the fieldset's own children (`legend`, the checkbox `<label>` loop) or the `usesNames` computation above it.
  </action>
