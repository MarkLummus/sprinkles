# Phase 03.3 Plan 05: Scope the uses checklist's Escape to a wrapper covering the button and the fieldset Summary

**Moved Method.jsx's uses-checklist Escape handler off the `<fieldset>` alone and onto a new wrapper `<div>` covering both the `change`/`done` button and the fieldset, gated on `usesOpen` so a closed checklist's Escape no-ops and bubbles to the pen's own listener — closing G-03.3-2, confirmed live by Mark.**

## Accomplishments

- Root-caused and fixed G-03.3-2: `handleUsesKeyDown` was attached only to the `<fieldset className="method-step__uses">`, but the `change`/`done` button that opens the checklist (`usesControlRef`) sits in a sibling `<p className="method-step__uses-line">` outside that fieldset. Clicking `change` left focus on the button, so Escape pressed there bypassed the scoped handler entirely and reached RecipePage's document-level listener, cancelling the whole pen.
- Wrapped the uses-line paragraph and the (conditionally rendered) fieldset in one new wrapper `<div onKeyDown={handleUsesKeyDown}>`, so the handler now covers both the opener and its disclosed content regardless of which one holds focus.
- Added `if (!usesOpen) return;` as the first line of `handleUsesKeyDown`, ahead of the pre-existing `if (event.key !== 'Escape') return;` check, so a closed checklist's Escape is a true no-op — it continues bubbling to RecipePage's own document-level Escape listener unchanged, respecting D-24's unsaved-ink rule for the pen itself.
- Kept `event.stopPropagation()`, `setUsesOpen(false)`, and `usesControlRef.current?.focus()` in `handleUsesKeyDown`'s body exactly as they were — only the element the handler is attached to, and the open-gate, changed.
- Live-verified by Mark (2026-09-10): with the checklist open, the first Escape closed only the checklist and returned focus to `change`; the second Escape closed the pen. Both matched the expected behavior exactly — no further gap.

## Decisions Made

- Used a plain wrapper `<div>` with no new CSS rule — both the uses-line paragraph and the fieldset keep their own pre-existing app.css margin rules unchanged, since neither rule depended on being a direct child of `.method-step__body`.
