# Phase 03.3 Plan 06: The version row's right-hand stack, acts group, and fork-focus fix Summary

**Rebuilt VersionRow's right-hand stack against sketch 003 variant B (Version region label, a Written/From-version+Why/From-batch dl, and a descendants-only Later disclosure fed by a new descendantVersions domain function), relocated the Record opener beside Next version with a deterministic fork-landing-focus useEffect, and — per Mark's live review — fixed the pen's "no batch" absence text to read in the ordinary field face instead of inheriting the From-batch label's uppercase small print.**

- **Tasks:** 3 (2 code tasks, 1 human-verify checkpoint — now closed, live, with one requested fix)

## Accomplishments

- Added `descendantVersions(versions, versionId)` to `domain/lineage.js`: a pure recursive walk returning the whole descendant subtree (children and their own descendants), matching the sketch's own `renderTree` semantics rather than direct children only.
- Rebuilt VersionRow's right-hand stack: a visible `<h2 className="region-name">Version</h2>`, a `<dl className="version-row__meta-list">` carrying Written (root) or From version + written date (child), Why (un-gated so a root version also states "no reason recorded"), From batch (when cited), and a Later count that discloses `VersionStrip` scoped to `descendantVersions` of the current version — replacing the old unconditional full-recipe `VersionStrip` call.
- Moved the `recordButtonRef`/`wasRecordingRef`/`useEffect` trio verbatim from `BatchRow.jsx` into `VersionRow.jsx`; VersionRow's acts group now renders "Next version" and "Record another"/"Record batch" side by side, wired through the same `openBatch`/`onStartRecording` references RecipePage already passed to BatchRow. BatchRow no longer references either.
- Fixed G-03.3-1: replaced `autoFocus={focusDevelopOnMount}` on the Next version button with an explicit `useEffect(() => { if (focusDevelopOnMount) developButtonRef.current?.focus(); }, [focusDevelopOnMount])` — deterministic regardless of the native `autoFocus` attribute's timing relative to React's commit phases on a fresh router-keyed remount.
- Live review by Mark against the sketch (2026-09-10) confirmed the Later disclosure cards, Show changes as a text control, the label-over-control pen fields, and the fork's landing focus all match — with one requested fix.
- **The fix:** the pen's From batch field, when the version has no batch to cite, rendered its absence text (`no batch to cite`) in the same uppercase small-print face as the "From batch" label itself, because `.headnote__citation span` (a bare-tag selector) matched both the label span and its sibling `.ink-text` absence span. Scoped the rule to `.headnote__citation span:first-child` and shortened the text to `no batch` (matching the sketch's own select-option wording). No new token added.

## Decisions Made

- Kept "no batch" (not "no batch to cite" or the sketch's bare option wording variant) as the pen's absence text, per Mark's explicit live-review instruction.
- Scoped the uppercase label styling with a `:first-child` CSS selector rather than introducing a new class name for the label span — the narrowest fix, leaving the established `.headnote__version-field span`/`.headnote__reason-field span` pattern (which have no second sibling span, so never hit this bug) otherwise untouched.
- VersionStrip's call site now feeds `descendantVersions` of the current version, not every version of the recipe — a deliberate, sketch-faithful, reversible behavior change per the plan's own `<reversibility>` note.
- Deferred to Impeccable (see below): the Opener and Save/Save-as nomenclature question raised during live review is explicitly out of scope for this fix and was not touched.
