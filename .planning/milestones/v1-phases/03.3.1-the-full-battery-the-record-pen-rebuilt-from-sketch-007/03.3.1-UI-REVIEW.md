# Phase 03.3.1: UI Review (Impeccable audit)

**Score: 15/20 (Good)** — full findings in the Impeccable critique snapshot linked above.

This is the project's Impeccable audit method (per `.claude/skills/gsd-ui-review/`, which shadows
the generic GSD 6-pillar audit for this project). Advisory only — does not block phase
verification. Findings are phrased as brief revisions for `/gsd-quick`, `/gsd-quick-batch`, or a
future phase plan, per the project's Impeccable-decides / GSD-executes working agreement.

## Verdict

Pass, with two real bugs found and fixed live during this audit (Home/End keyboard support,
`.axis-mark__stop` box-sizing — both already committed as part of Task 3's browser conformance
pass, `1dbef3c`). The battery's internal geometry, token discipline, and picked-state affordances
all measured true on a real browser at 1280/768/700px. One structural gap remains open: the
record pen's outer frame is not capped to the contract's 640px width.

## Findings (most severe first)

1. **[P1] Pen width uncapped** — `--pen-w` (640px) is declared in `tokens.css` but not applied to
   any selector; the pen renders at its container's full width (measured 1013px at 1280px
   viewport). Fix needs a recording-mode class on `.batch-margin` (`BatchRow.jsx`) so the
   already-shipped full-width read view is untouched. Suggested: `/gsd-quick`.
2. **[P2] True 393px unverified** — this session's browser environment could not resize below
   ~500px; the contract's zero-overflow claim rests on the responsive formula's arithmetic plus a
   ~500px measurement, not a direct 393px read. Suggested: human UAT on a real device.
3. **[P2] Pre-existing overflow, not this surface's** — the ~500px overflow measured traces to
   `.recipe-band`/`.vmeta` (the version front-matter band), already tracked in STATE.md's
   Blockers/Concerns. No action owed by this phase.
4. **[P3] A few contract-named elements still unstyled** — `.defects-row__caption`,
   `.tasting-head`, `.note-block`, `.melt-block` render as plain text, matching this phase's own
   "unstyled until named" precedent. Suggested: `/impeccable typeset` in a later pass.

## What's working

- Full token discipline: every new geometry value is a named custom property; zero bare px
  outside documented breakpoint preludes.
- The picked-state affordance (bold + underline + outline, never colour) is real on screen,
  confirmed via `getComputedStyle`, including the carried P3 filled-control underline drop.
- The removal/undo lifecycle speaks the contract's exact words to the correct live region on
  every path tested, and the undo payload survives the 760px arrangement crossing by construction
  (React state, never a captured DOM reference).
