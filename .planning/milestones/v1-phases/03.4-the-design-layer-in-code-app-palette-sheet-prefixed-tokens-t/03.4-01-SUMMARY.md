## Decisions Made

- Task 1's `tdd="true"` tracer ran as a write-harness-first pattern, not classic RED/GREEN: the plan's own `<behavior>` block states both `tokens.test.js` tests must pass on the tree **before** any rename (that is what proves the harness works), so the RED phase's "must fail first" rule does not apply here — this plan's frontmatter is `type: execute`, not `type: tdd`, so the strict plan-level TDD gate enforcement in `tdd.md` is not in scope; the task-level `tdd="true"` attribute was honored by splitting the work into a test commit and a feat commit.
- A boundary-anchored regex (`(?<![\w-])--name(?![\w-])`) proved more robust than a literal `var(--name)` string replace for the bulk Task 2/3 renames: it matches a bare token name identically whether it sits inside a CSS declaration, a `var()` read, a quoted JS string, or a JS regex literal's escaped `var\(...\)` — one script pass handled every syntax shape without special-casing test-suite regex literals separately.
- `--c` (RecipeList.jsx's inline per-row hue, set via React's `style` prop) is excluded from `tokens.test.js`'s declared-token universe via a documented allowlist, since it is genuinely never declared in any stylesheet and is out of this plan's rename scope (Jar-world files, RESEARCH.md Pitfall 4).

### Documented Acceptance-Criterion Discrepancy (not a code defect)

Task 3's acceptance criterion `grep -c "var(--app-size-label)" app/src/styles/home.css` **returns 2, not the literally stated 1**. `--size-home-label` (the pre-existing "12px, the versions/batches micro-label" token, already read once by `.home__tally-label`) is renamed to `--app-size-label` by this same task's geometry rename, and the task's own instruction — "Move `.home__import-errors` onto the App's own 12px size token **now that one exists**" — directs the import-errors rule onto that identical token. Both reads are correct and intentional; forcing a literal count of 1 would require either not renaming `--size-home-label` (contradicting the explicit rename list) or inventing a duplicate 12px token for `.home__import-errors` alone (contradicting the shared-token-reuse principle the plan repeatedly states). The underlying design intent — one App label-size token, shared by both its callers — is fully satisfied; only the specific numeric assertion undercounts a pre-existing consumer.
