<decisions_recorded>
Open questions this plan settles, with the reason:

1. **The rail becomes the bottom tab row at the existing `(max-width: 759.98px)` step** (RESEARCH.md open question 1). D-16 says the breakpoint follows the existing ladder; 759.98px is the ladder's touch step, is already the only condition home.css carries, and is in the seven-condition allowlist app.css is pinned to. The board's "390" names the viewport Mark reviewed, not a new literal — a new literal would also have to widen that allowlist.
2. **Import and Export lift into the Shell** (RESEARCH.md open question 2, assumption A4). D-09 puts the tools row in the header, which persists on every route including placeholders; leaving the handlers in Home would make them work on one route only. The Shell owns the file input, the two handlers and the import-error list, and hands routes below it a store-revision counter through the Outlet context so Home reloads after a successful import without a page reload.
3. **Search is a link in the tools row to `/search`, which renders the same placeholder page** (D-13's first option, made honest by D-10's grammar). A control that does nothing is a keyboard trap and an accessibility defect (UX1-01); a link that says the place is not built yet is the same promise the five destinations make. No search is built either way.
4. **Placeholder wording:** the place's name as the page title, then one sentence — "{Place} is not built yet." Plain words, sentence case, no article, no apology.
5. **The shell gets its own stylesheet, `app/src/styles/shell.css`, with its own contract suite.** home.test.js pins every home.css rule to the `.home` root class, so shell chrome cannot live there without weakening that pin; app.css is the Sheet stylesheet with a pinned media allowlist and no radius, fill or transition. A third stylesheet keeps one root class per file and gives the App's chrome the same token discipline home.css already has.
6. **One source of truth for the places.** Shell.jsx exports a `PLACES` array of `{ path, name, slug }`; the rail, the bottom tab row and router.jsx's placeholder routes all read it, so a place cannot exist in the rail and not in the router.
7. **Colour is set by a modifier class, never by an inline style.** Each place's rail item carries `shell__place--{slug}`, and shell.css maps that class to the destination's accent and text companion. No `style` attribute appears in Shell.jsx.
8. **More is a `<details>` disclosure.** It is keyboard-operable and open/closed without any JavaScript; the alternative is a hand-rolled menu with focus management this phase does not need.

   > **Note (2026-09-22, plan 11, G-03.4-3):** this decision reasoned about *opening* — keyboard operability, no focus management — and never about *dismissal*. Per the HTML spec a `<details>` toggles only via its own `<summary>`'s activation behaviour, so "open/closed without any JavaScript" necessarily meant "never closes on selection". UAT test 3 found this at 393px on 2026-09-22 (More stayed open after choosing any of its five items, and stayed open across the navigation an item triggered). Plan 11 moves the open state into React while keeping the `<details>` element, closing it on item activation and on route change, following History.jsx's HistoryDisclosure precedent.
</decisions_recorded>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a chosen file -> the local store | The maker picks a JSON file; its contents are parsed and validated before reaching IndexedDB. This boundary moves component but does not change behaviour |
| an imported record -> the DOM | Text from an imported record renders on Home and on the recipe page |
| the URL -> the router | A typed or bookmarked path reaches the layout route and its children |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.4-07 | Tampering | the import handler, moved into Shell.jsx | high | mitigate | the handler moves verbatim: the same JSON parse inside try/catch, the same `importStore` validation, the same "nothing is replaced or cleared" behaviour on rejection. No validation is re-implemented, weakened or bypassed during the move, and the errors still render as text |
| T-03.4-08 | Information Disclosure | export | low | accept | export writes a local object URL and clicks an anchor; no upload, no network, no external service — unchanged behaviour (D-15) |
| T-03.4-09 | Elevation of Privilege (rendering) | imported text reaching the DOM through new shell markup | high | mitigate | no `dangerouslySetInnerHTML` anywhere in Shell.jsx or Placeholder.jsx; import errors render as React children, which escape as text |
| T-03.4-10 | Spoofing | a link to a place that does not exist | low | mitigate | every place in the rail resolves to a real route; an unbuilt place says so in one sentence rather than rendering an empty page that looks broken (D-10) |
| T-03.4-11 | Denial of Service (usability) | the fixed bottom tab row covering page content | medium | mitigate | the shell's main column carries a bottom padding equal to the tab row's height below the step, pinned by shell.test.js |
</threat_model>
