## Accomplishments

- `RecipeList.jsx` gains a `STANDING_WORDS` lookup over `lastEvent.js`'s exported `NOT_YET_CHURNED`/`AWAITING_TASTING`/`TASTED` constants — never a hand-spelled string — so a row's standing word can never disagree with the action `RowActions` renders beside it (T-03.4-G07). `RecipeRows` renders the word in its own `.home__standing` element, after the recipe name and before the tally, exactly where board 170 draws it (line 93).
- `home.css`'s `.home__row` reads the board's own five-column desktop template — `grid-template-columns: auto 1fr var(--app-col-standing) var(--app-col-tally) auto` — with the standing and tally areas each spanning both identity rows, as the rail already did. `.home__meta` moves into the tally area and switches from a row to a column so the marks sit on one line with the count beneath them (board line 94-100); `.home__count` gains tabular numerals. Two new App geometry tokens, `--app-col-standing` (120px) and `--app-col-tally` (132px), carry the two column widths, each commented with the board line they come from.
- Below the 759.98px step, the row's phone form pairs the identity column with the standing on one line, then the tally and the actions each on their own line beneath — the rail and the tally are kept at this width per the recorded decision (DESIGN.md's rail-on-every-list rule and UX1-03's in-words count), even though board 171 draws neither.
- `HomeLead` is rebuilt to the board's own order (board 170 lines 49-79): the destination rod (the same `.home__rail` class and decorative attribute the rows use), a `.home__lead-identity` element wrapping the existing place/name/meta paragraphs untouched, a `.home__lead-next` column rendered only when the newest batch carries a Next time note — holding a `.home__lead-caption` reading "Next time" (the App label role, never the hand) and the existing hand-classed note — and `RowActions` over the same entry, so the lead's action is always the one its own row shows.
- `home.css`'s `.home__lead` is rewritten from a bottom-divider block into a bordered, radiused flex row: a hairline App rule border in the App text colour, the new `--app-radius-lead` token (its own name, apart from `--app-radius-action`, even though both read 10px today), a shared-scale column gap and padding. Lead-scoped child rules keep the rod from shrinking, give the identity and Next time columns an equal flexible share with a zero minimum width, and size the actions to their own content. Below the touch step the lead stacks into a column with its children stretched, its own rod hidden (board 171's lead block draws no rod at all, unlike the row's), and its border and radius surviving the step.
- Full suite: 1119 passed, 0 failed (up from 1104 at plan start — 15 new tests across both tasks). Build succeeds, 126 modules transformed. `grep -c "@media"` still returns 1 for `home.css` — the file grew no second condition. The hand role class (`app-hand`) still appears exactly once in `RecipeList.jsx`.
