# Phase 03.4 Plan 13: Device UAT is served from the build, and neither wait — the store opening nor Home's own reads — is spent on a blank page

**Closed the code half of G-03.4-1: a two-phase render in main.jsx paints an `.app-boot` line before IndexedDB is ever awaited, Home shows a `.home__loading` line instead of nothing while its own reads are in flight, and `.claude/CLAUDE.md` now says device UAT is served from the production build and why.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 3
- **Files modified:** 8 (.claude/CLAUDE.md, main.jsx, app.css, binder.test.js, RecipeList.jsx, RecipeList.test.jsx, home.css, home.test.js)

## Accomplishments

- **The standing rule, written down (Task 1):** `.claude/CLAUDE.md`'s Conventions gained two lines inside the existing GSD markers: device UAT is served from `npm --prefix app run build && npm --prefix app run preview -- --host`, never the dev server (the dev server's cold-load cost was measured at 64 requests / 6.22 MiB against the build's 3 requests / ~134 KB gzipped), and only one Vite process per workspace — two sharing one optimised-deps cache can turn a stale request into a 504 and a full client reload.
- **A boot line before the store opens (Task 2):** `main.jsx` now creates the React root once and renders a single `.app-boot` paragraph through it before awaiting the seed. On failure, the store-open message renders through that same root and class instead of a direct `textContent` write, and the throw is kept. On success, the app renders through the same root. The seed stays awaited before `<App />` renders — no route reads an unseeded store. `.app-boot` was added to `app.css`'s prelude, beneath the body rules, reading the grotesk face, the meta size, the secondary text colour, and the page gutter as padding — all four from tokens, `.app-hand`'s own role-class precedent. `binder.test.js` pins the rule (every declared value a `var()` read) and that `main.jsx` carries the class exactly twice (the boot line and the failure line).
- **Home says it is loading (Task 3, TDD):** `RecipeList`'s early `return null` became a branch inside the existing return — the one `.list-page`/`.home` wrapper and its title stay in place in both states; beneath the title, a `.home__loading` paragraph before the store's two reads resolve, or the body it renders today once they do. `home.css` gained a top-level `.home__loading` rule (outside both media blocks), reading the meta size and secondary text colour from tokens, with `.home__empty`'s own top margin. `home.test.js` pins the rule; `RecipeList.test.jsx` pins the loading render itself.
