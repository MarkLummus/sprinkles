# Phase 03.4: The design layer in code: App palette, Sheet-prefixed tokens, the hand, and Home - Context

**Gathered:** 2026-09-21
**Status:** Ready for planning

<domain>
## Phase Boundary

The design layer approved on 2026-09-21 lands in code. `app/src/styles/tokens.css` carries the approved App palette under DESIGN.md's `app-` names, every Sheet-frame token under the `sheet-` prefix (with the contract suites following), the five `app-*-text` companions, and the hand (Caveat, with its forced-colours and print fallback). Then Home is rebuilt as the side-navigation design on the canvas: a lead recipe block, recipe rows that each carry their next action, a rail of the five destinations, a tools row, and placeholder pages for the places that do not exist yet. The retired jar and recipe palette are removed as the phase's last step.

Not in this phase: any Sheet-frame change (spread, batch log, print sheet keep their treatment); the Notebook, Recipe book, Idea log, Ingredients or Kitchen pages themselves; Search; pinning; the hand anywhere but Home's lead block.

</domain>

<decisions>
## Implementation Decisions

### Prefix scope and retirements
- **D-01:** Every Sheet-frame token takes the `sheet-` prefix: the four colour roles (`--sheet-ground`, `--sheet-ink`, `--sheet-pen-blue`, `--sheet-bookcloth`), both faces, every `--type-*` / `--leading-*` role and the Sheet's own geometry (`--col-*`, `--field-w-*`, `--stop-*`, `--track-*`, `--pen-w`, `--vmeta-min`, `--rhist-*`, `--caption-*`, `--seg-*`, `--axes-*`, the mark, strike, hatch and select tokens). `app.css`, `history.css` and the three contract suites (`columns.test.js`, `binder.test.js`, `cross-cutting.test.js`) are renamed with them, and every suite stays green. — **Reversibility:** costly — the rename touches every consumer in `app.css` (2567 lines) and every test pin; undoing it is the same sweep in reverse.
- **D-02:** Shared sizes stay unprefixed and context-free: the spacing scale (`--gap-*`, `--gap-page`), touch (`--touch-*`), rule weights (`--rule-*`), the focus outline tokens and the prose measure. One value app-wide, per the shared-size rule from 03.3.1.1. The App reads them by their bare names; it never reads a `sheet-` token except `--sheet-pen-blue` for the hand.
- **D-03:** App tokens take DESIGN.md's frontmatter names with the `app-` prefix: `--app-notebook`, `--app-recipe-book`, `--app-idea-log`, `--app-pantry`, `--app-ingredients`, `--app-kitchen`, `--app-blue`, the five `--app-*-text` companions, `--app-background`, `--app-surface-subtle`, `--app-text`, `--app-text-secondary`, `--app-divider`. The existing `--home-ground/ink/mute/rule` map onto `--app-background/text/text-secondary/divider` and disappear. App geometry (`--size-home-*`, sprinkle sizes, radii, `--rule-home-*`, `--duration-home`) also becomes `app-*`.
- **D-04:** The jar (`--jar-*`), the twelve `--recipe-hue-*`, `recipe-colour.js` and its test, and the row's `--c` custom property are removed as this phase's LAST step, after every other change has landed and before Phase 4 begins. Nothing else reads them.

### What active work means
- **D-05:** Active work is recency: a recipe's last event (version saved, batch recorded, tasting added), newest first. Every recipe is active in this phase; there is no stored flag.
- **D-06:** Home shows one lead recipe, the most recently touched, as a larger block; the other active recipes follow as rows. With one recipe in the store there is no list beneath.
- **D-07:** The continuation action follows the standing, as drawn on the canvas board "The action follows the standing" (version 170): not yet churned → Record a batch; awaiting tasting → Record a tasting (secondary Continue developing); tasted → Next version (secondary Adapt); ready to make (a Recipe book version) → Print and make (secondary Develop in Notebook); saved idea → Develop in Notebook. One filled action per row in the companion blue with white label; the secondary is the same blue as outline. In this phase every stored recipe lives in the Notebook, so only the Notebook standings appear; Ready to make and Print and make arrive with the Recipe book.
- **D-08:** Empty Home (no active work): one sentence that nothing is in progress, then Recipe book and Idea log lead. A store with no recipes follows the canvas board "First arrival — empty shelf".

### Shell and destinations
- **D-09:** The shell is the side navigation as drawn on the canvas board "Pick up where you left off — side navigation" (version 170): a header with the wordmark and tilted sprinkles and a tools row top-right (Search, Import, Export as icon-and-word links); a 224px left rail with Home, a divider, Notebook / Recipe book / Idea log, a divider, Ingredients / Kitchen. Each place has a line icon in its destination accent and its name in that colour's text companion (Kitchen's indigo needs none); no colour bar. The active place sits on the subtle surface; Home's icon and word take the app-blue text companion. — **Reversibility:** reversible.
- **D-10:** All five destinations are links. An unbuilt place opens a page with the shell intact (rail and tools row), the place's name as its title, and one sentence saying it is not built yet. Nothing is listed there.
- **D-11:** Every recipe row carries its next action(s) per D-07 at its right edge. The row is a block with the recipe name as the link (a link cannot hold buttons); the versions word is dropped from the row; the batch tally (hollow sprinkles in the row's destination colour) stays; the place name above the recipe name reads in the text companion.
- **D-12:** The lead recipe block stays above the list even though every row carries its action; the lead recipe also appears in the list.
- **D-13:** Search is drawn only. It appears in the tools row as a link that does nothing yet, or is left out of the built shell; the planner decides which, and neither builds a search.
- **D-14:** Home's words as the board draws them: title "Pick up where you left off", rows under "Recipes". The boards' grey explanatory sentences are canvas commentary, not copy.
- **D-15:** Import and Export keep their present behaviour (a file input and a JSON download) and move into the tools row.

### The rail at 390
- **D-16:** Below the phone step the side navigation becomes a bottom tab row, as drawn on "Home at 390 — bottom tab row" (version 171): five coloured tabs fixed at the bottom — Home, Notebook, Recipe book, Idea log, More; More holds Ingredients, Kitchen, Search, Import and Export. The lead block and the rows stack with their actions. The drawer variant was drawn and not chosen. The breakpoint follows the existing ladder in `app.css`.

### Hand and companions in code
- **D-17:** Caveat ships in the repo as one file, Regular 400 in woff2, with the SIL Open Font License beside it, declared with one `@font-face`; nothing is fetched from a network. Tokens: `--face-hand`, `--size-hand` (1.375rem), `--leading-hand` (1.25), `--size-hand-min` (1.25rem). Under `forced-colors: active` and in print the role falls back to the text face in italic. DESIGN.md's Hand entry leaves *pending* once the tokens exist and the fallback is verified in both modes.
- **D-18:** The hand is applied on Home's lead block only: the lead recipe's Next time, in the hand, in `--sheet-pen-blue`. No other App surface uses it this phase; the Sheet never does.
- **D-19:** The five `app-*-text` companions ship as tokens and colour the place names in the rail and the place name on each row, but stay marked tentative in DESIGN.md until Mark sees them in the real app.
- **D-20:** Rows carry no quotation. The maker's words appear once on Home, in the hand, on the lead block; the row's pen-blue "last words" are removed.

<code_context>
## Existing Code Insights

### Reusable Assets
- `app/src/ui/RecipeList.jsx` — today's Home at `/`: loads versions and batches through the repository, derives the newest batch per recipe, renders rows with tallies, and owns import/export (file input, JSON download). The data loading, `RecipeRows`, and the import/export handlers carry over; the row markup and the hue lookup do not.
- `app/src/styles/home.css` — the App-world stylesheet; its `--home-*` and `--jar-*` reads become `--app-*` reads.
- `app/src/domain/lineage.js` (`latestVersionPerRecipe`, `sortedVersions`, `versionsForRecipe`), `app/src/domain/batch.js` (`sortedBatches`) — the ordering and standing derivations for D-05 to D-07 come from these; a "last event" helper belongs beside them, framework-free.
- `app/src/router.jsx` — two routes today (`/`, `/recipe/:id`, plus the batch path); the placeholder pages (D-10) are new routes here.

### Established Patterns
- Every visual value reads a token in `tokens.css`; breakpoint literals live only in `app.css`'s own `@media` preludes; the contract suites read the stylesheets as text, so a rename is a text rename everywhere at once.
- Domain modules import no framework, DOM or store; the recency and standing rules go there with node-environment tests.
- Notes render as text; no `dangerouslySetInnerHTML`.
- Test input values, commit messages and agent prose are English.

### Integration Points
- `main.jsx` seeds and mounts the router; the shell (rail, tools row, tab bar) wraps every route, so it lands at the router or a layout route, not inside `RecipeList`.
- `RecipePageForRoute` already supplies a stable page shell for announcements; the new shell must not break the page-scoped feedback channel from 03.3.1.
