<objective>
Separate the recipe from the version in the store, end to end, on the olive oil seed alone. The recipe gets its own record ({ id, name, description }) behind the repository seam; the version keeps only its Sheet's own words (sheetTitle, sheetDescription); Carried forward leaves; the store resets to DB_VERSION 6 and the export file moves to schemaVersion 6 carrying recipes.

Purpose: every later plan in 03.5 (routes, the App band with Rename, the Sheet, the log, the seed) reads this shape. Home must keep naming recipes the moment the version stops carrying a name.
Output: the recipes store and its four seam methods, the olive oil recipe record and split version, activeWork reading names from records, the version field rename through every reader and the pen, Carried forward removed, and a schema-6 transfer that refuses older files in plain words.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired (kind `chosen`, on "the layout is chosen on a Claude Design canvas" — a wording match). The phase does carry a real identity change, which this plan owns: the recipe's name used to be derived from whichever version carried it; now it is chosen and stored once.
- Noun now primary: the recipe record in the `recipes` store, keyed by the recipeId every version already carries.
- Decision: **promote**. The recipe record becomes the only source of a recipe's name and description, and the version's copy of the name is deleted rather than kept alongside. activeWork, the Rename control (plan 04) and every later reader resolve the name through recipeId.
- Invariant test (accepted into Task 3): an import whose version names a recipeId with no recipe record is refused, and a comment-stripped source scan finds no read of the removed version name field anywhere under app/src.
</assumption_delta_decision>

<decisions_recorded>
1. **One plan, three tasks, wide by necessity.** Task 2 is a field rename through every reader. Split across tasks, the suite would sit red between commits because each UI test builds its fixture from oliveOilVersion. Nine of Task 2's seventeen files are test fixtures. Task 3 likewise sweeps one list out of data, UI and transfer together.
2. **Counters stay separate.** DB_VERSION 5 -> 6 (db.js), store-file schemaVersion 5 -> 6 (transfer.js), VERSION_SCHEMA_VERSION 4 -> 5 (olive-oil.js). Each moves off its own prior value. They are not merged (RESEARCH.md § 2).
3. **A missing recipe record names the entry by its recipeId**, never undefined. The import gate in Task 3 and the seed make the case unreachable in practice; the fallback keeps Home from rendering an empty link if a record is ever lost.
4. **The older-export sentence.** D-10 asks for a clear message. The path-named error already exists (`$.schemaVersion: expected 6, got 5`); a plain sentence goes first, `OLDER_EXPORT_MESSAGE = 'This file is from an older version of Sprinkles and can’t be imported.'`, and only when schemaVersion is a number below 6.
5. **Where the Sheet title shows before plan 04.** Task 2 moves the page's h1 from the recipe name to the Sheet title. Until plan 04 builds the App band, the recipe page names the recipe nowhere; Home names it from the record. This is intentional and lasts two waves.
6. **NoteList stays in Authored.jsx.** Method.jsx imports it for Before you start. Only the Authored wrapper and its Carried forward legend go.
</decisions_recorded>
