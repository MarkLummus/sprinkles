# Phase 03.5 Plan 02: Move every recipe address to the Notebook form Summary

**Every recipe address moves to /notebook/:recipeId/:versionId[/batch/:batchId]; the old /recipe/:id addresses redirect there forever through two new component-based redirects; every in-app link and navigate() call follows; the recipe route's own running head is retired with the page notice re-anchored to a new `.page-status-anchor`; and the Recipe Book's one-selected-version principle is written into the sketch README and the surface brief.**

## Accomplishments

- `app/src/ui/notebookPaths.js` — a new pure, framework-free module (no React or store import, grep-proven) exporting `notebookPath`, `legacyRecipePath` and `latestVersionPath`. Every segment runs through `encodeURIComponent` (T-03.5-06), so a stored id holding `/` or `..` can never change the path's shape.
- `app/src/ui/NotebookRedirects.jsx` — new: `LegacyRecipeRedirect` (resolves the old `/recipe/:id[/batch/:batchId]` form to the Notebook address, keeping the search string) and `NotebookLatestRedirect` (`/notebook/:recipeId` replace-redirects to the newest version, D-14). Both are component redirects, not route loaders — `createBrowserRouter` runs at import time, before `main.jsx`'s awaited `seedIfEmpty` resolves, so a loader on a first visit after the D-10 reset could read an empty store.
- `app/src/router.jsx` — the route table gained `/notebook/:recipeId`, `/notebook/:recipeId/:versionId` and its `/batch/:batchId` sibling; `/recipe/:id[/batch/:batchId]` now route through `LegacyRecipeRedirect` (D-16, kept indefinitely, never deleted); `RecipePageForRoute` keys `RecipePage` on `recipeId::versionId::batchId`, extending the existing stale-state guard the file's own header comment documents.
- `app/src/ui/RecipePage.jsx` — exports `RecipeNotFound` (shared by a missing version, a recipeId mismatch, and both redirect components); `useParams()` now yields `{ recipeId, versionId, batchId }`; every effect that read the old `id` reads `versionId`; a version whose own `recipeId` disagrees with the route's renders `RecipeNotFound` (decisions_recorded 3); both `navigate()` calls (batch save, version save) build their target with `notebookPath`.
- Every remaining `/recipe/` link site moved: `RecipeList.jsx` (4 sites — lead name, row name, Record a batch/Next version, the tasting link), `VersionRow.jsx` (From version, From batch), `BatchRow.jsx` (the batch register link), `RecipeHistory.jsx` (3 sites — BatchAttempt, the version identity link, the From-batch citation). A comment-filtered `grep -rn "/recipe/" app/src` now finds zero sites outside `router.jsx`'s two legacy redirect entries.
- The recipe route's running head is gone: `router.jsx` no longer renders `.page-head`/`.running-head`, and a new `.page-status-anchor` (zero-height, `position: relative`) is the notice's containing block, a sibling before the keyed page. `app.css`'s `body:has(...)` cream-canvas selector drops `.page-head` (keeping `.recipe-page` and `.not-found`, per decisions_recorded 5 — `.recipe-page` stays cream edge to edge until plan 04 builds the App band around it).
- `.planning/sketches/011-recipe-route-c/README.md` and `.impeccable/surfaces/route-recipe.md` § "03.5 revision" part 7 both now record the settled principle: the Recipe Book shows one selected version only — no version selection, no Next version, no History — with the Recipe name on its band. No board or generator file was touched (`git diff --name-only 1692885` against the sketch/generator directories lists only `README.md`).
