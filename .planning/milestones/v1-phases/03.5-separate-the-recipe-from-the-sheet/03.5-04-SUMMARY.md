**2. [Rule 2 - Missing Critical] Added a loading/missing guard for the new `recipe` state**
- **Found during:** Task 1, wiring `recipe` into the render
- **Issue:** The plan's action text describes loading `recipe` via an effect keyed on the loaded version, but says nothing about what renders before that fetch resolves — without a guard, `RecipeBand` would receive `recipe={undefined}` and crash reading `recipe.name` during the fetch window (and again if a version's `recipeId` ever named no stored recipe).
- **Fix:** Extended the existing `if (version === undefined) return null;` / not-found ladder with `if (recipe === undefined) return null;` and `if (recipe === null) return <RecipeNotFound />;`, mirroring the existing version-loading/not-found pattern exactly.
- **Files modified:** app/src/ui/RecipePage.jsx
- **Verification:** Full suite passes; no test exercises the loading window directly (renderToStaticMarkup runs no effects), but the guard mirrors an already-tested pattern one line above it.
- **Committed in:** 715de20 (Task 1 GREEN commit)
