## Accomplishments

- **Task 1 (tracer, TDD):** `IngredientTable.jsx`'s three render paths (`renderReadingEntry`, `renderShowChangesEntry`, `renderDevelopingEntry`) and the total row each split their first child (`GramsCell`, `DiffGramsCell`, or the split row's plain span) into a new preceding `<td className="ingredient-table__col-grams">`; the thead's "Ingredient" `<th>` gained `colSpan={2}`; `columnCount` became `3 + asMade`. `app.css`'s `.ingredient-table` moved to `table-layout: auto`; the new `.ingredient-table__col-grams` rule and `.ingredient-table__col-numeric` both read `width: 1%`. Wrapped the shared rule in `:where(...)` (the same technique already used for `:where(a:visited)`), dropping it to zero specificity — every column rule now wins as its own comment already claimed it would.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed a latent CSS specificity bug in the shared ingredient-table cell rule**
- **Found during:** Task 1's GREEN verification against the 984/1366 boards
- **Issue:** `.ingredient-table th, .ingredient-table td` (specificity 0,1,1) silently outranked every bare `.ingredient-table__col-*` class rule (0,1,0) on any property both declared — the numeric columns' computed `text-align` read `"left"` despite their own `text-align: right` rule, and the amount column's 18px gap before the name read 6px instead
- **Fix:** Wrapped the shared rule in `:where(.ingredient-table th, .ingredient-table td)`, dropping it to zero specificity — the same technique the file already uses for `:where(a:visited)`
- **Files modified:** `app/src/styles/app.css`
- **Verification:** `03.5-table-probe.mjs columns` group matches the 984/1366 boards to the pixel after the fix (before: 8 failures; after: 0)
- **Committed in:** `2a5f0eb`
