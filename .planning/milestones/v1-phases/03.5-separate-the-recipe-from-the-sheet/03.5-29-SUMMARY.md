# Phase 3.5 Plan 29: Fold heads read the count alone Summary

**The Batches and History fold heads now read "3 batches" and "N versions" and nothing after them, because the count is a plain function of the count and the History overflow state that only fed the removed hint is gone.**

## Accomplishments

- BatchRow.jsx: the batch list's FoldRow count is `${batches.length} batches` in both states. The accessible name reads "Batches, Hide, 3 batches".
- historyRail.js: `railHint(count, { open, upright, overflowing })` is replaced by `versionCountWords(count)`, "1 version" or "N versions".
- RecipeHistory.jsx: passes `versionCountWords(entries.length)` as the count and loses the `overflowing` state, `measureOverflow`, its call and the resize listener. The effect keeps the scroll-to-in-view and the `scrolledLeft` read, with the same dependency list, and no longer returns a cleanup.
- Tests: BatchRow (open count reads `>3 batches<` with no separator), FoldRow (fixture count "3 batches"), historyRail (the `railHint` block became a `versionCountWords` block), RecipeHistory (open case reads the count span exactly). No test or probe pins hint text any more.
- Probes: the batches probe `many` group reads the Batches count span exactly in the default state and after one click (undone), and on batches-many.html and upright-393.html. The band probe `history` group reads "3 versions" open and closed on the build, and the bare count on 1366-batch.html ("2 versions") and upright-393.html ("8 versions").
