## For Mark

- **Unverified on the device: the iPhone numbers layer.** A Chromium probe reads only the attribute set. Whether Out of machine and Tasting temperature open on the numbers layer with a minus and a period, with no tap on 123 first, and -6 takes two taps from a cold field, is a WebKit fact this environment could not measure. This build has not been run on the iPhone. Check from `npm --prefix app run build && npm --prefix app run preview -- --host`: Record another, tap Out of machine, then Add tasting and tap Tasting temperature. Time to draw temp., Churn duration, Tempering and Melt test should still open the numeric keypad. A lone minus then Save batch should show "Enter a temperature, such as −6, or leave blank." under the field and save nothing. Saved -6 and -12 should read back in the cells and in Correct.
- **The browser's number filter (accepted with variant A).** On a '.' locale a typed or pasted comma is dropped, so a pasted "-6,5" reads as -65. A pasted U+2212 is dropped, so a pasted "−6" reads as 6. 'e' and '+' can be typed, and "1e3" reads as a finite number that the parser then rejects with the contract sentence. The up and down arrow keys step the value. The parser's comma and U+2212 paths now serve only the four text fields. Contract line 187 says so.
- **Sketch 008's invalid sample.** A number input cannot be handed the sample word "cold" through its value attribute, so line 354's invalid state now draws an empty field with `aria-invalid` and the sentence beneath, and the filled state draws a hyphen-minus -6. The browser's own unreadable text is not drawn.
- **Undo-restore edge.** Removing a tasting that holds an unreadable temperature and then undoing the removal restores the carry value into a freshly mounted, empty-looking input. Save then flags the field with the contract sentence rather than saving blank, and typing and deleting a digit clears it. Rare, flagged rather than silent, not worth a mount-time sync.
- **No DESIGN.md or PRODUCT.md change is needed.** Neither mentions the keyboard; the 011 boards carry no inputmode or type on these fields.
