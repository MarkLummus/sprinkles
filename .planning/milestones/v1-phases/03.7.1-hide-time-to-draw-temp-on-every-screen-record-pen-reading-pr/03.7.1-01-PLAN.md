<decisions_recorded>
1. **D-03, the draft: the pen stops reading and writing the field entirely.** The record draft (blankRecordDraft, draftFromBatch) no longer holds the key, isDraftDirty no longer compares it, and buildChurnFieldsFromDraft no longer names it. A Correct save (and the band's Record a tasting save, the same amend branch) passes the batch's stored value to completeRecord unchanged; a new batch gets none, so the unchanged domain buildChurn writes null, the value an untouched field has always stored. Why not the smaller-looking alternative (leave the draft plumbing, drop only the control): it keeps a draft value no control can edit and two dirty-check comparisons that can never differ, and it keeps validating a value nobody can see. transfer.js accepts any finite number for the field, so an imported batch storing -5 would make every Correct save fail on an error attached to a field that is not on the screen, with no focus target: dead behaviour that traps the maker. With the key gone, parseAllMeasuredFields (which still walks the domain's BATTERY_FIELDS, unchanged) reads the field as blank and can never raise its error, and the stored value is passed through as the exact stored number, never round-tripped through a string. Cost: four draft lines deleted, one save-assembly line deleted, one line added to the amend branch. Stored data: unchanged in shape and value; no migration. Reversibility: reversible (restoring the control re-adds those lines; no stored record changes). Nothing here is costly or one-way. What Mark should know: a value a batch already stores stays in the store and in every export, invisible in the app, until Phase 4's reseed removes the field.
2. **The domain list stays; the UI filters.** BATTERY_FIELDS in domain/battery.js keeps the field (D-02). BatchRow's own CHURN_MEASURED_FIELDS include-list drops it, so the pen draws Out of machine and Churn duration beside Churn date.
3. **The plan sub-line goes with its cell.** The reading's only plan line ("plan 10–12 min", the come-up target) belongs to the removed cell (CONTRACT section 7). Its helper in rows.js has no other caller and is retired in Task 3 with its tests (CLAUDE.md section 3: remove what your change made unused). Its two CSS rules and their test pins go in plan 02.
4. **The 724 to 1365 reading grid stays five tracks.** notebook.css sets five equal columns there for the churn cells; four cells now leave the fifth track empty. No board draws four cells at those widths, and Phase 4's D6 regroups the reading (Exit consistency and Airiness under At draw), so this plan changes no column count; plan 02 measures it and words the question for Mark.
5. **No rename.** "At the machine" stays the pen note's caption and accessible name (D-04).
