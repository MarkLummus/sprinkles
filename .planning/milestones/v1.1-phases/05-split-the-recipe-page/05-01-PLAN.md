Usage: `node .planning/phases/05-split-the-recipe-page/05-walk.mjs record <out.json>` and `node .planning/phases/05-split-the-recipe-page/05-walk.mjs compare <a.json> <b.json>`. The build is read from `process.env.PROBE_DIST`, defaulting to `<repo root>/app/dist`. The repo root is computed from the walk's own URL, three directories up (`.planning/phases/05-split-the-recipe-page/` up to the repo root).

Imports: `webkit` from the playwright-core path in the Facts; `startServers` from `../../milestones/v1-phases/03.5-separate-the-recipe-from-the-sheet/03.5-probe-harness.mjs`, always called as `startServers({ appRoot: DIST })`; `createHash` from `node:crypto`; `readFile` and `writeFile` from `node:fs/promises`; `path` and `fileURLToPath`.

A context per scenario, built by the walk itself: `browser.newContext({ viewport: { width: 1366, height: 1100 } })` (Mark's iPad width, fine pointer). Before the first page loads: `await context.clock.setFixedTime(new Date('2026-10-14T12:00:00.000Z'))`, which fixes `Date` and keeps timers running, so the 250 ms draft debounce and the 5 s self-clearing toasts still behave. If the context-level clock does not reach the page in 1.63, call `page.clock.setFixedTime` with the same instant on the new page before its first `goto`, and confirm with `page.evaluate(() => new Date().toISOString())`. Then `context.addInitScript` replacing `crypto.randomUUID` with a counter that returns `00000000-0000-4000-8000-` plus the count padded to 12 digits. The count lives in `localStorage` under `sprinkles-walk-id-counter`, so a reload continues it and two records never share an id. Then a `context.route('**/*', ...)` that aborts every request whose hostname is not 127.0.0.1 (copy the harness's blockThirdPartyRequests lines). Each scenario's fresh context gives a fresh IndexedDB, which the app reseeds on first load, so every scenario starts from the seed.

`snapshot(page)` returns one plain object:
- `url`: pathname plus search.
- `pageStatus`: the `.page-status` text.
- `formStatus`: every `.form-status` text in DOM order.
- `tastingStatus` and `recordStatus`: the texts of those regions, or null when absent.
- `invalid`: the aria-label (or id) of every `[aria-invalid="true"]` element in DOM order.
- `focus`: `{ tag, ariaLabel, name, id, text }` of `document.activeElement`, with `text` trimmed to 60 characters.
- `pens`: the count of `form[aria-label="Next version"]` and of `.batch-margin--pen`.
- `fields`: `[ariaLabel, value, checked]` for every input, textarea and select inside an open pen, in DOM order.
- `buttons`: the trimmed text of every button inside an open pen and inside `.notebook-log`, in DOM order (this is how Restore tasting and Add tasting show up).
- `textHash`: the sha256 hex of the `.notebook` element's `innerText`, computed in Node.

`dumpStores(page)` opens `indexedDB.open('sprinkles')` with no version, reads `versions`, `batches`, `recipes` and `drafts` with `getAll` in one read transaction, and returns them keyed by store name, each list sorted by its key path value.

Expected facts (a miss is `FAIL version-pen-kept-draft: <what>`): the drafts store holds one record after step 3; after the reload the notice appears and the Version name field holds the typed value; the drafts store is empty after Cancel.

Output JSON is `{ walk: '05', engine: 'webkit', width: 1366, scenarios: [{ name, steps: [{ step, snapshot, stores }] }] }`, where `stores` is present only where the scenario dumped them. `record` checks every expected fact first. On any miss it prints each FAIL line, exits 1 and writes nothing. Otherwise it writes the JSON (2-space indent, trailing newline) and prints `RECORDED <path> <n> snapshots`.

`compare` loads both files and walks scenarios and steps in order. It prints `DIFF <scenario> / <step> / <json path>: before=<json> after=<json>` for every leaf that differs, including a scenario or step present in one file only, then exits 1. When nothing differs it prints `MATCH <n> snapshots` and exits 0. Close every context in `finally`, then close the browser and the servers.
