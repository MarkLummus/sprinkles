## Phase Goal

**As a** home ice cream maker, **I want to** open the churned olive oil recipe in Sprinkles and read it whole — its twelve ingredient rows, its method, its target bands, its authored notes, and its balance figures with the basis they rest on — **so that** I can work from the app instead of the printout.

*Provenance: the ROADMAP `**Goal:**` line for Phase 1 is not written in user-story form, so this story is a mechanical restatement of it rather than a new one. The capability is the Goal line verbatim; the actor is PROJECT.md's persona ("home ice cream makers", Mark first); the outcome is the Goal's own success criterion 4, "so the maker can work from the app instead of the printout". To make the ROADMAP Goal line itself a user story, run `/gsd mvp-phase 1` — this plan does not rewrite it.*

<objective>
Stand up the Walking Skeleton: the `app/` workspace, the router, the IndexedDB repository seam, the seeded olive oil version record, and the framework-free balance module — wired end to end so the recipe opens from the store and its formula reads on screen. Then prove the math against the printed sheet.

Purpose: this is the phase's tracer. Every later slice in Phase 1 (the method and authored notes, the six balance figures, the estimated-data flags) expands out from this one proven path, and Phases 2–4 attach to the same seam and router. Proving the architecture end to end here means an architectural dead end costs one commit rather than ten.

Output: a runnable local app (`npm --prefix app run dev`), a passing printed-sheet fixture (`npm --prefix app test`), and the seeded churned version living in browser IndexedDB as an ordinary record.

The visual world — type faces, palette, spacing — is deliberately NOT invented in this plan. The Impeccable direction contract is written at the start of plan 01-02 and the tokens land there. This plan produces the brief's structure (headnote, ingredient table, method region, margin) in semantic markup with each block wearing its plain-language name, and plain readable defaults for everything else.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired on this phase (`kind: chosen` — "the ingredient seed dataset is **chosen** in this phase's planning"). A configuration decision has become a modeling decision, so the identity model gets named before the plan is finalized.

- **Primary noun:** the *version-embedded ingredient row* — a row on a stored version record carrying its own copy of the ingredient's composition, basis, and source, plus the id of the coefficient set it came from.
- **Decision:** `promote`. The embedded snapshot is primary. A shared ingredient library (ING-01, later milestone) becomes a *source* that a version copies from at authoring time, never an authority a stored version reads through at render time. The alternative — versions holding library references — was rejected: it is the exact shape that let coefficient drift silently corrupt historical batches (`.planning/PROJECT.md`, "Known data hazards").
- **Rationale:** D-05 already requires the embedded copy and rates the move away from it `costly`. Promoting now means Phase 2's batch snapshot and Phase 3's comparison read one shape, and adopting the 103-row seed database later is a visible, citable re-authoring rather than a silent recomputation of every stored figure.
- **Invariant test (accepted):** task 3 asserts that mutating `library` after a version is built does not change that version's figures. That test goes red the instant a future phase reintroduces a live library reference.
</assumption_delta_decision>

Solids are fat plus MSNF plus sugar plus other plus emulsifier plus stabilizer.
