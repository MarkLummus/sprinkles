## Phase Goal

**As a** home ice cream maker, **I want to** open the churned olive oil recipe in Sprinkles and read it whole — its twelve ingredient rows, its method, its target bands, its authored notes, and its balance figures with the basis they rest on — **so that** I can work from the app instead of the printout.

*Provenance: a mechanical restatement of the ROADMAP `**Goal:**` line for Phase 1, which is not itself written in user-story form. Actor from PROJECT.md's persona; outcome from the phase's own success criterion 4. Run `/gsd mvp-phase 1` to restate the ROADMAP Goal line itself.*

<objective>
Close the phase: put the estimated-data flag in both the places D-04 requires, wire the brief's trace-to-contributors interaction so an assumption is one focus away from the number it moves, finish the provisional store's export and import contract, and record the structure that landed.

Purpose: a figure the maker cannot interrogate is a figure they have to take on faith, and this product's whole stance is that a balance figure is an assessment under assumptions. This slice makes the assumptions visible at the figure, traceable to the rows, and portable off the device by the maker's own choice.

Two things close this phase.

**Part one — `app/src/store/transfer.js`.** Export `exportStore(repository)`, `validateStoreFile(parsed)`, and `importStore(repository, parsed)`, completing the whole-store JSON transfer D-06 requires. All three go through the repository seam; none touches the store library.

`exportStore` reads `repository.getAll()` and returns `{ app: 'sprinkles', schemaVersion: 1, exportedAt: <ISO timestamp>, versions }`.

`validateStoreFile(parsed)` returns `{ ok, errors }` and is the only gate before a write. It checks the top level is a plain object with `app` equal to `sprinkles`, `schemaVersion` equal to 1, and `versions` an array; that each version has a non-empty string `id`, a string `recipeName`, a string `coefficientSetId`, and a non-empty `rows` array; and that each row has a non-empty string `id`, a string `ingredientName`, a `grams` that is a finite number of at least zero, and an `ingredient` object carrying a `composition` object whose every value is a finite number. It also rejects any object anywhere in the payload that carries an own key able to mutate an object's prototype chain. Collect every error, do not stop at the first, and name the offending path in each message so the maker can see what was wrong with their file.

`importStore(repository, parsed)` validates first and returns the failure without writing anything when validation fails. A partially applied import is worse than a refused one: it leaves a store the maker cannot reason about and versions that no longer say truthfully what they were computed from. On success it writes through `repository.putAll(versions)`.

Prototype-chain mutation via untrusted JSON is canon security, covered by `/gsd-secure-phase` and by lint rules; the reject-unsafe-keys check here is the specific mitigation for this import path, and no separate project prohibition is minted for it.

**The transfer controls** go on the recipe list as two plainly labelled actions, Export and Import. Export serialises the result and hands the maker a file to save. Import reads a file the maker chose, using the browser's own local file reading — no upload, no network, no external service. On rejection, show the validation errors as text next to the control; do not replace the store, do not clear anything, and do not show a colour as the only signal that it failed.
