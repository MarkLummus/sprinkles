<objective>
Two doors the pen layer never had: the way in when a batch already exists, and the way out that does not write.

Gap G-02-1: the `Record a batch` control lives only in the branch reached when the version has no batch — and the store always seeds one, so on every page a maker can actually reach, that branch is unreachable. There has been no way to record a second batch since the feature shipped. Gap G-02-4 (its cancel half): recording mode's only exit is the save handler. A maker who opens the pen layer by mistake, or who starts an amendment and changes their mind, can leave only by destroying the page.

Both are plan-level gaps, not build mistakes: the implementation matches what 02-01 and 02-03 asked for. This plan supplies the design instruction that was missing.

Purpose: after this plan the phase's own UAT test 8 is unblocked — a second batch can be recorded, listed, and reopened — and the pen layer is no longer a dead end.

Output: a margin whose three states each offer the right way forward, and the repo's first automated gate on a rendered component.

**No tracer task.** Tracer-first exists to prove an unproven architecture end-to-end on the agent's best tokens. This phase's architecture shipped and was exercised through nine UAT tests; a thin slice would tell us nothing we do not already know. The work here is corrective, against a proven skeleton.
</objective>

## Assumptions Mark can overrule before this plan runs

These were surfaced by the orchestrator and are planned on as stated. Each is a decision, not a discovery — say so now if any is wrong.

- **A-1 — Cancel discards immediately, with no confirmation.** Clicking cancel returns to the reading state at once. The surface brief forbids an invented dialog (route-recipe-batch.md §6, D-24), so there is no "are you sure". The browser's own leave warning still fires on tab close or reload, unchanged.
- **A-2 — The new-batch control is worded `Record another batch` and sits after the margin's batch list.** Distinct wording is the whole requirement (D-06: a correction is never a new event), so it must not read like `Amend`. Placing it below the batch list keeps the two batch-scoped controls (`Amend`, `Add a tasting`) with the batch and the version-scoped control with the version's batches.
- **A-3 — The other half of G-02-4 is out of scope here.** "Save batch is hard to find" has two named causes: no button token or control weight in the direction contract, and the formulation note pushing the margin to the foot of the longest column. Both are design decisions for Impeccable — they are already carried under `## Deferred Follow-Ups` (test 4) and in the gap's own `missing` list. This plan invents no button style, no token, and no layout change. **G-02-4 is therefore only partly closed by this plan**; the findability half stays open against Impeccable.
- **A-4 — Component tests render through `react-dom/server` in the existing node environment.** Verified before planning: a `.test.jsx` file under `app/src/ui/` importing `renderToStaticMarkup` transforms and runs green under `npm --prefix app test` with the current toolchain — no jsdom, no testing-library, no config change, no new dependency. This gates *what renders in a given state*. It cannot fire a click. Testing the click-through (press cancel, assert the draft is gone) would need a DOM environment and two new dev dependencies — **a structural choice left to Mark, not taken here** (working agreement: surface framework choices rather than assume them). The click paths are covered by the human-check instead.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the URL's `batchId` → what the margin claims about the record | An address the maker can type or keep in a bookmark; the page must not make a false statement about the version's records because it did not recognise one |

| an abandoned draft → the store | The point at which discarding unsaved ink must be provably a no-op against everything already recorded |
| device boundary | Nothing crosses it — no network API under `app/src` (TRUST-01, IMP-01) |
