<objective>
Two marks on the page that could not be read, and could not be scratched out.

Gap G-02-3: the `Skipped` label is nested inside the paragraph that carries the strike. Per CSS Text Decoration L3 a decoration set on a block propagates to every in-flow inline descendant and cannot be switched off by them, so the label is struck by construction — the requirement (a legible text label, not a drawn line alone) is defeated by where the label sits. Gap G-02-6: a mark placed on an axis cannot be removed. Two independent locks — the control emits only stops, and the handler only writes keys — so a single misclick permanently enables `Save tasting`, permanently removes the hint that explains it, and leaves reloading (which discards the whole draft) as the only escape. `AxisMark` is the only one-way control in the pen layer; the step-strike beside it is a freely-toggled checkbox.

Both were specification gaps: the brief asked for a label "beside" the prose and it was placed inside, and no artifact anywhere ever asked whether a mark is reversible.

Purpose: every mark the maker makes on this page can be read, and can be taken back before it is saved.

Output: a strike that draws through prose only, a per-axis clear control, and the delete rule proved in the domain suite.

**No tracer task**, for the reason given in 02-04: the architecture is proven and this work is corrective against it.
</objective>

## Assumptions Mark can overrule before this plan runs

Surfaced by the orchestrator and planned on as stated.

- **A-1 — The strike is scoped to an inner prose span rather than the label being moved below the paragraph.** Both fixes work; this is the smaller diff and the only one that keeps the label on the same line beside the prose, which is what the brief asked for. Moving the label out of the paragraph entirely would put it on its own line — a layout change nobody asked for.
- **A-2 — Clearing a mark is a small per-axis text control reading `Clear`, rendered only while that axis carries a mark.** The native radio group is kept exactly as it is: nine stops, arrow keys, one click sets. No tenth "unmarked" stop, and no `role="radiogroup"` rewrite with a custom keydown handler (the fallback 02-RESEARCH A1 held in reserve is not taken).
- **A-3 — The clear rule lives in the domain as `setMark`, not inline in the page handler.** The page's other delete-on-empty rules (`handleChangeStepChange`, `handleChangeAsMade`) are inline and untested, which is precisely why this gap shipped: no gate could reach them. Six lines in `app/src/domain/axes.js` make the one rule that must never regress provable in the node suite. If you would rather keep it inline and match the existing handlers, say so — the control and the CSS are unaffected either way.
- **A-4 — Component gates render through `react-dom/server` in the existing node environment** (verified before planning; no jsdom, no testing-library, no new dependency). These assert *what renders in a given state*. Firing the click on `Clear` and asserting the draft returns to unmarked needs a DOM environment and two new dev dependencies — **a structural choice left to Mark, not taken here**. In its place the delete rule itself is tested in the domain suite, where it is pure, and the click path is covered by the human-check.
