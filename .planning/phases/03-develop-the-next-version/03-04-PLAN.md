## Phase Goal

**As a** home ice cream maker, **I want to** open the pen on a version I have already churned, change it with the old values struck beside the new ones, and save the result as a next version that names its parent and my reason, **so that** I can develop the recipe without touching the record of what I actually made.

*Provenance: as recorded in `03-01-PLAN.md` — a mechanical restatement of the ROADMAP `**Goal:**` line, not a new story. Run `/gsd mvp-phase 3` to make the ROADMAP line itself a user story.*

<objective>
Lay the pen's grammar back on a saved version as a state of the page, so the maker can read exactly what changed from the parent and what it did to the balance without a diff viewer, a side-by-side, or a sheet laid over the page.

Purpose: FORM2-01. A saved version reads clean, because that is the page that prints and is made from; one control makes the comparison visible again, in the page's own structure, so the DOM order, the keyboard path and the screen reader all read a table with an old value and a new one rather than marks floating over one.

Output: the `changes` search parameter and its toggle; the live parent read; the struck-beside grammar in the table, the total row, the rule heads with their hollow ticks, the method and the notes.
</objective>

The comparison is a state of the page, addressable, with no motion and nothing floating over anything.

**The parameter — `app/src/ui/RecipePage.jsx`.** Read the search parameters with `useSearchParams` from `react-router`, once at the top of the component beside `useParams`. The state is on when the parameter named `changes` is present, read with `searchParams.has('changes')`; its value is not consulted, so the presence of the key is the whole signal. The toggle writes with `setSearchParams`, adding the key with an empty value or deleting it, building a new `URLSearchParams` from the previous rather than mutating it. Leave `setSearchParams`'s default history behaviour alone — pushing a new entry is exactly what makes the browser's own back button return to the clean reading, with no extra code. Because both `/recipe/:id` and `/recipe/:id/batch/:batchId` already resolve to this component, the parameter composes with either and no route is added. Phase 4's print route will ignore it.

**The live parent.** When the version carries a `parentVersionId`, read the parent record through `repository.getVersion` in a cancelled-flag effect beside the existing loads, keyed on that id, and hold it in state. It is read live, never from a copy stored on the child — that is the brief's binding constraint, and it is what makes show-changes tell the truth after a parent is itself saved over. When the read comes back with nothing, hold `null`: the toggle is then absent and the lineage line still names the parent from the child's own `parentVersionLabel` snapshot, so a child never silently reads as having no parent.

Compute the show-changes diff once, as `buildDiff(version, parentVersion)`, and thread it into the regions — the same function and the same descriptors the pen already uses against its own baseline (D-03), so the two states cannot render different comparisons of the same two records. When there is no parent, or the parameter is absent, there is no diff and nothing is marked.

**The toggle — `app/src/ui/Headnote.jsx`.** The lineage line gains one control, and only one: a `<button type="button">` reading `show changes from 50 g oil · 800 g`, built from the parent's version line, carrying `aria-pressed` set from the state. Its pressed state is carried by weight and outline; nothing fades and nothing moves. There is no per-element and no per-section control — one version-level control is the whole design. The toggle is absent when the version has no parent, and absent when the parent record could not be read.

**The table — `app/src/ui/IngredientTable.jsx`.** In the show-changes state the table renders the same struck-beside grammar the pen renders, from the same row descriptors, with one difference the brief is explicit about: **both values are ink**, because both are printed matter now — the pen's blue belongs to what is being typed, not to what was saved. Per row: the parent's grams struck immediately before the current grams; the parent's share struck immediately before the current share, independently, so a row whose grams held but whose share moved shows the share strike alone; and the parent's step allocation struck before the current one. The total row shows the parent's total struck before the current one. A removed row reappears whole and struck at its original index — never appended, never moved — and is absent from the clean reading.

A mark appears only where the value differs, and `buildDiff` has already decided that at the precision a reader sees: a share whose one-decimal printed form did not move is not marked, because a mark a reader cannot account for is worse than no mark. Extend the row's accessible name in the show-changes state the same way the pen extends it — `was 40 g, now 48 g` — so the strike is never the only carrier.

The table reflows once when the marks arrive, as it does when the as-made column arrives. Size the numeric columns so a struck value and a current value fit on one line at the working case's widths, reading the width from a token rather than a literal.

**Nothing ranks.** No wording, no weight, no order and no mark says a change was an improvement or a regression; there is no arrow, no colour and no badge on a change. The state says what moved and by how much, and stops there.

**Styles.** Reuse the one strike stroke and the struck-beside tokens 03-01 added; add nothing new here beyond what the column widths need. No literal colour, size, spacing or rule weight outside `tokens.css`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the `changes` search parameter → what the page renders | A display state anyone can type into the address bar; it must never reach a write |
| the parent record → the child's rendering | Read live at render time, so a parent saved over afterwards is reflected rather than frozen in a stale copy |
| a comparison → the records being compared | `buildDiff` reads two versions and must never edit either |
| what the strike carries → a reader who cannot see it | The accessible name is the second carrier the design requires |
| device boundary | Nothing crosses it — no network API and no external model call under `app/src` |
