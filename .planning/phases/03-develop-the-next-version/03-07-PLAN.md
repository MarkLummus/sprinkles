<objective>
Close G-03-9's remaining two root causes: stop the version strip, the batch list and the lineage links from carrying a maker off a page that holds unsaved ink, and make both dirty checks tell the truth in both directions.

Purpose: 03-06 made the pen unable to *survive* a route change. That is the corruption backstop. It is not ink protection — with the pen unable to follow, a strip click now discards the ink cleanly instead of corrupting a record, which is better but still silent. D-UAT-2 rules that while any pen is open those three routes off the page are disabled with a stated reason, and D-10 forbids answering it with a dialog of the app's own. Alongside it, RC4: the pen's dirty check omits method, headnote and authored — the three things the pen spends most of its time editing — so a maker who rewrote a step's prose and pressed reload lost it with no warning; and the churn's dirty check compares an amend draft against blank, so the warning fires the moment Amend opens and trains the maker to dismiss it.

Output: three regions that state why they will not move while ink is wet, and two dirty checks that fire on ink and only on ink.
</objective>

Write these as failing tests first, in `app/src/ui/RecipePage.test.jsx`, against the two exported check functions directly — no rendering needed. Build fixtures as small hand-written version objects in this file's existing style.

The pen's check:
- A pen draft seeded from a version with nothing touched is not dirty.
- Editing a step's lead-in makes it dirty. Editing a step's instruction makes it dirty. Editing a step's purpose makes it dirty. Editing a step's aside makes it dirty.
- Editing a step's target label, or its target value, makes it dirty.
- Toggling a row into or out of a step's uses list makes it dirty.
- Removing a step, or restoring one, makes it dirty.
- Editing the headnote prose makes it dirty.
- Editing an authored note's text makes it dirty; removing an authored note makes it dirty.
- Each of the above, typed back to the value it started from, reads clean again — the whole reason the check compares values rather than counting keystrokes.
- The three the check already caught still work: a changed gram, a changed step allocation, a removed row.
- A pen draft is never dirty when the mode is not developing, and never dirty when the version or the draft is absent.

The churn's check:
- A fresh recording draft with nothing typed is not dirty; typing any one field makes it dirty. Unchanged from today, and asserted so this rewrite cannot lose it.
- An amend draft, pre-filled from a batch and untouched, is NOT dirty. This is the inverse defect: today it reads dirty the instant Amend opens.
- The same amend draft with one churn field changed IS dirty; changed back, clean again.
- An amend draft that adds an as-made amount, or changes a step's strike or its line, is dirty.
- An amend draft that clears a field the batch had a value in is dirty — a deletion is ink too.
- A written zero still counts: an amend draft whose overrun the maker types as `0` where the batch held `5` is dirty, and one that types `0` where the batch held `0` is clean. Truthiness would get both of these wrong, which is why the existing check tests against `''`.

Two checks, wrong in opposite directions, both fixed against the thing they should have been comparing against all along.

**`isPenDraftDirty`, in `app/src/ui/RecipePage.jsx`.** It tests the version line, the reason, the citation and the rows today. Extend it to the three the pen actually spends its time in, and export it so the tests can reach it.

- *Headnote*: dirty when `penDraft.headnote` differs from `version.headnote`.
- *Method*: for each step of `version.method`, find the draft step by `n` and compare lead-in, instruction, purpose, aside, its removed flag, its uses list and its targets. Normalise an absent purpose or aside to the empty string on **both** sides before comparing, exactly as this plan's sibling 03-09 does inside `buildDiff`: the pen writes an empty string into a field the record had nothing in, and treating that as a change here would make the leave warning fire on a stray keystroke into an empty box. Normalise an absent removed flag to false. Compare a uses list as a set, since order is not a fact the maker authored. Compare targets by position, on both label and value.
- *Authored*: for each of the two lists, dirty when the list's length differs or when any note's text differs from the note at the same index in `version.authored`. Do not compare `inheritedFrom`: the page derives it from the text, so text equality already decides it.

Write the comparisons as small named helper functions at module level beside the checks, not as one long boolean — this function is about to be the thing that decides whether a maker's work is protected, and it should read as a list of what counts as ink.

**`isDraftDirty`, in the same file.** It compares every churn field against blank, which is right for a fresh recording and wrong for an amendment, where `handleStartAmending` pre-fills all of them from the batch. Give it the baseline it is missing:
