<objective>
Close G-03-1: stop the step selector overflowing leftward across three columns of values, and make the As made column obey the rule the file already wrote for it.

Purpose: the maker reported both halves of the same sentence — the table is unreadable while developing, and it carries a labelled column with nothing in it. The first is a single missing pair of CSS properties: the step cell copied the grams cell's flex arrangement and its `width: auto` override but dropped the `flex: 1 1 auto; min-width: 0` that made the grams cell safe, so under `table-layout: fixed` the select keeps the min-content width of its widest option — about 320px — inside a cell about 42px wide, and spills at the start edge because the cell justifies to the end. The second is a predicate computed and then applied to only two of the four places it governs.

Output: column widths that belong to columns, a select that fits its cell, and an As made column that is there when there is an as-made layer and absent when there is not.
</objective>

Two changes, in this order: make the widths belong to columns, then let the select shrink.

**Sizing by identity, in `app/src/ui/IngredientTable.jsx` and `app/src/styles/app.css`.** Today the width and the right-alignment of the three numeric columns are selected by their ordinal position in the row. That is only correct while every column is unconditional, and the table already has one conditional column — Remove, safe purely because it is last — and is about to gain a second in the middle. Give each cell a class naming the column it belongs to, in the file's existing block-and-element naming (the same family as `ingredient-table__grams-cell`), and select the widths on those classes instead:

- the ingredient-name column
- the numeric columns (Grams, As made, % of batch) — one class shared by all three, since they share a width and an alignment
- the step-allocation column
- the data-flag column
- the remove column

Put the class on both the `th` and every `td` of that column, in all three body branches and in the total row. Delete the positional width-and-alignment rule and the first-child rule, replacing them with class rules that set exactly what those two set today. Nothing about the rendered widths should change in this task: this is the same layout, addressed differently, so that task 2 cannot shear it.

Give the step column an explicit width through a new custom property in `tokens.css` — it is currently one of three unsized columns splitting whatever is left, which is what made it about 42px of content box. Derive the value rather than guessing it, and record the arithmetic in the token's comment: at a 1280px viewport the recipe page's two-column grid gives the table roughly 768px, from which the name column takes 40% and each numeric column takes its own width; the widest state of the table is a churned version open in the pen, which shows all three numeric columns *and* the step, data and remove columns at once. Choose a width that leaves the data column able to print the word it prints and the remove column its control in that widest state, and say so in the comment. Every value reads through a custom property; no literal reaches `app.css` or the component.

**The shrink guard, in `app/src/styles/app.css`.** The step cell's select rule cancels the base field's `width: 100%` and replaces it with nothing that constrains the control. Give it the same pair its sibling grams-cell rule carries, so the control's automatic minimum size stops being the width of its longest option and becomes something the cell can hold. Correct the rule's own comment while you are there: it claims to use "the same struck-baseline-beside-field arrangement the grams cell uses", which is what made the omission invisible — it copied the arrangement and not the guard. Say which properties are load-bearing and why, so the next builder who touches it knows that the flex arrangement alone is not the pattern.

Do not shorten or otherwise change the option labels in this task. They are rewritten in 03-10, which is the plan that owns what number an option carries; changing their text here would be changed twice and read as churn in the diff.

Commit.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a stored batch record → the as-made column's presence | The column is a claim that a record exists; an empty one claims a record that does not |
| a control's rendered box → the values beside it | Under a fixed table layout an unconstrained control cannot widen its column, only cover its neighbours |
| a column's identity → its width | Positional selection couples every column's width to every other column's existence |
| device boundary | Nothing crosses it — no network call and no external model call under `app/src` |
