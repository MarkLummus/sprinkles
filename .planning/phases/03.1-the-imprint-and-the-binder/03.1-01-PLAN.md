## Planner decisions and assumptions recorded for this phase

These are choices this planner made where the sources left a gap. They are visible, not silent.

1. **CSS class names do not change in this phase.** Markup that moves out of `Headnote.jsx`/`BatchMargin.jsx`/`VersionStrip.jsx` keeps its existing class names and its existing `app.css` rules; only genuinely new markup gets a new class. Reason: renaming `.headnote__*`, `.batch-margin__*` and `.version-strip__*` would be a large mechanical diff with no user-visible effect, would collide with the four state-outline selectors plan 03 must re-point by name, and would break class assertions in passing tests. D-01 governs the words on screen, not the words in a stylesheet. A rename is recorded as a follow-up for whichever phase next touches these files.
2. **The component file `Headnote.jsx` keeps its name and its export.** Only its contents shrink. Renaming the file would churn every import and test-file name for no user-visible gain.
3. **D-03 closes across plans 01 and 02.** This plan gives the recipe block the version line; the churned date's move into Versions arrives with the batch list in plan 02. Between the two commits the churned date still prints in the version line exactly as it does today, so no commit regresses.
4. **Assumption — the parent's line prints twice while the plan's pen is open.** The recipe block prints `version.versionLabel` in every state (D-03), and the ceremony prints the version-line field with `was <parent line>` beneath it (`route-recipe-version.md` § 3). Both are stated by binding sources, so both are built; the result is the parent's line on screen twice while that one pen is open. Flag this in the re-critique rather than resolving it in code.
