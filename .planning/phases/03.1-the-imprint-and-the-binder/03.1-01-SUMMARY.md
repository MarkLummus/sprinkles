## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] PenFoot gated on `openPen === 'plan'` instead of the plan text's literal `openPen !== null`**
- **Found during:** Task 1 (building PenFoot.jsx)
- **Issue:** The plan's action text says PenFoot "renders nothing when `openPen` is null. Otherwise it renders..." — read literally, this would render the plan's Cancel/Save(-as)/Save pair, bound to `onSaveAsNewVersion`/`onSaveOverVersion`/`onCancelDeveloping`, during a batch-recording, amend, or tasting pen too (`openPen` is `'record'`/`'amend'`/`'tasting'`, none of which is `null`). RecipePage only passes PenFoot the plan pen's three handlers in this plan — pressing the rendered "Save" during, say, a batch recording would call `handleSaveAsNewVersion`, which reads `penDraft.versionLabel` inside `buildPenFields`/`blockedSaveMessage` while `penDraft` is still `null` (only set by `handleStartDeveloping`), throwing.
- **Fix:** Gated the whole component on `openPen === 'plan'` rather than `openPen !== null`. This satisfies the plan's own acceptance criteria exactly (both only test the `null` and `'plan'` states) and matches the plan's own stated scope ("the record's and tasting's pens arrive in plan 02").
- **Files modified:** `app/src/ui/PenFoot.jsx`
- **Verification:** `PenFoot.test.jsx` asserts no render for `'record'`/`'amend'`/`'tasting'` in addition to `null`; full suite green.
- **Committed in:** `49c3556` (Task 1 commit)
