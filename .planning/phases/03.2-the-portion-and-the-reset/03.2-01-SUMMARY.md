# Phase 03.2 Plan 01: The Portion And The Reset Summary

**A row's total moves from a stored `grams` field to a derived `rowGrams(row)` sum over `portions`, the store resets to `DB_VERSION` 4 with a drop-then-recreate upgrade instead of a cursor lift, and `app/tests/db-reset.test.js` proves the whole path — pre-03.2 record in, reset, reseed, six figures unmoved — against a real IndexedDB.**

## Performance

- **Duration:** ~40 min
- **Tasks:** 3 (checkpoint:decision acknowledged, tracer executed and verified, auto task completed)
- **Files modified:** 16 (1 created, 1 deleted, 14 modified)

## Accomplishments

- `rowGrams(row)` added to `app/src/domain/rows.js`, the single derivation of a row's total as the sum of its `portions`; `composition.js`, `figures.js`, `advisories.js`, `batch.js` and `diff.js` all read it instead of a stored `grams` field.
- `app/src/data/olive-oil.js` rewritten: all twelve rows carry `portions` (whole milk `120+250.4`, sucrose `12+64`, the other ten one-portion); `SEED_USES`, `SEED_CREATED_AT` and `VERSION_SCHEMA_VERSION` (now 3) moved in from `versionLift.js`; the two split-step instructions (steps 2 and 3) no longer state the milk's or the sucrose's grams.
- `app/src/store/db.js` bumped to `DB_VERSION` 4; `upgrade` now drops both object stores (when `oldVersion > 0 && oldVersion < DB_VERSION`) *before* the two existing guarded `createObjectStore` calls recreate them — the opposite order from `03.2-PATTERNS.md`'s sketch, and the order the task called load-bearing. The cursor-lift branch and its `liftVersionRecord` import are gone; `upgrade` now awaits nothing at all.
- `app/tests/db-reset.test.js` created, replacing `app/tests/db-migration.test.js`: a pre-03.2-shaped version record opens at database version 3, then the reset at version 4 returns both stores present and empty, `seedIfEmpty` through the real repository seam writes the seed back, and the six figures and `computeBalance(activeRows(...)).mass` (`799.7 g`) read exactly as before.
- `buildDiff`'s row descriptor gained `stepsFrom`/`stepsTo`/`stepsChanged` (order-sensitive, over each row's portion step references) in place of `stepFrom`/`stepTo`/`stepChanged`; `gramsFrom`/`gramsTo` now read `rowGrams`.
- `lineage.js`'s `findBlockedRow` walks a draft row's `portions` in order, keeping both existing blocked-save sentences verbatim.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `db-reset.test.js` needed a dynamic import of `store/repository.js`**
- **Found during:** Task 2, writing the `seedIfEmpty` case
- **Issue:** `store/repository.js` exports `export const repository = createRepository()` at module top level, which calls `openStore()` immediately at import time. A static `import { createRepository } from '../src/store/repository.js'` at the top of the test file would run that before the file's own `beforeEach` had set `globalThis.indexedDB` to a fake `IDBFactory` — `indexedDB.open(...)` would run against `undefined`.
- **Fix:** Import `createRepository` via a dynamic `await import(...)` inside the one test that needs it, after `beforeEach` has already run for that test.
- **Files modified:** `app/tests/db-reset.test.js`
- **Verification:** `npm --prefix app test -- tests/db-reset.test.js` — 3/3 pass.
- **Committed in:** `3dc244d`

**2. [Rule 1 - Test-infrastructure] The plan's `gramsChanged|gramsFrom|gramsTo` acceptance count for `uses.js` undercounts by one line**
- **Found during:** Task 3 self-check
- **Issue:** The task's own acceptance criterion `grep -cE 'gramsChanged|gramsFrom|gramsTo' app/src/domain/uses.js` expects `-ge 3`, but `grep -c` counts matching *lines*, not occurrences — `uses.js`'s one line `{ ... from: rowDiff.gramsFrom, to: rowDiff.gramsTo }` carries two of the three keys on a single line, so the count is 2. `app/src/domain/uses.js` is untouched by this plan (confirmed correct per Task 3's own read_first note) and all three keys are present exactly once each (`grep -o 'gramsChanged\|gramsFrom\|gramsTo' | wc -l` reads 3).
- **Fix:** No code change — `uses.js` is already correct. Documenting the acceptance criterion's own counting mismatch rather than reformatting a correct file to force a line-count grep to pass.
- **Files modified:** none
- **Verification:** `grep -o 'gramsChanged\|gramsFrom\|gramsTo' app/src/domain/uses.js | sort | uniq -c` shows one of each.
- **Committed in:** n/a (no code change)

**3. [Rule 1 - Pre-existing, scoped for a later plan] `lineage.test.js`'s retiring `liftVersionRecord idempotence` block imports from `app/src/store/`**
- **Found during:** Task 3 self-check
- **Issue:** The Task 3 acceptance criterion "no file under `app/src/domain/` imports React, a DOM global, or anything from `app/src/store/`" is violated, literally, by `lineage.test.js`'s pre-existing `import { liftVersionRecord } from '../store/versionLift.js'` — present before this plan touched the file, and explicitly named in Task 3's own action text as a block to "leave alone in this task — 03.2-02 deletes it along with its subject."
