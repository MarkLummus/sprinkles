<objective>
Narrow the store file to the new shape alone and delete the ladder that used to widen it.

`transfer.js` stops being a compatibility surface. Export writes one schema number, `validateStoreFile` accepts that one and refuses the three that came before it with a clear error, `validateRow` gates on `portions`, and `importStore` loses its lift branch. `versionLift.js` — whose two call sites are now both gone — is deleted.

Purpose: D-08's promise narrows on purpose. A store exported *after* this change imports after it; a store exported *before* it does not, and this is where that is recorded. Reinstating the old promise later means restoring one lift branch in `importStore` alone, with no live-database ladder beside it.

Output: a `transfer.js` that knows one shape, a deleted `versionLift.js`, and a round-trip test that proves the surviving promise against the real seed.
</objective>

Shrink the accepted-shape set to one and keep every discipline that made the file trustworthy.

**`validateRow`** — replace the stored-amount gate with a portions gate, in the same collect-every-error, name-every-path style. A row's `portions` must be an array with at least one element (`$.versions[i].rows[j].portions: expected a non-empty array, got ...`). Each element must be a plain object whose `grams` is a finite number of at least zero and whose `step` is a finite number, each reported at its own indexed path so a maker can see which portion was wrong. Do not gate on any stored total — there is none. Leave the `id`, `ingredientName`, `ingredient.composition` and `removed` checks exactly as they are.

**`validateBatch`'s `declaredAxes` check (D-07a)** — keep the array check and add an element check in the same style: each element must be a plain object whose `name` is a non-empty string and whose `low` and `high` are strings, reported at `${path}.snapshot.declaredAxes[i].name` and so on. This refuses exactly the old bare-string form, which would otherwise pass validation and reach `axesForBatch` as an axis whose key and label are undefined. Keep the rest of `validateBatch` untouched.

**`validateStoreFile`** — the accepted schema set becomes the single value 4. One check, one message naming what was expected and what arrived, in the file's existing style. Delete the `schemaVersion === 1` branch that permits an absent or empty batches array, so the batches array is required unconditionally. Delete the long doctrine comment above the function that explains why 1 was special and that export always writes 3 — every sentence in it is now false, and a comment describing deleted behaviour is this change's own mess to clean up. Replace it with a comment stating the narrowed promise: a store exported after this change imports after it; 1, 2 and 3 are refused as old rather than silently read as current; and reinstating the old promise means one lift branch here alone, never a second live-database ladder (D-08, CONTEXT.md Deferred Ideas).

**`exportStore`** — the one literal to bump: it writes 4.
