# Phase 03.2 Plan 02: The Portion And The Reset Summary

**`transfer.js` narrows to one accepted schema (4), gates a row on its `portions` array instead of a stored total, validates each `declaredAxes` element's shape (D-07a), and the whole `versionLift.js` compatibility ladder is deleted — the surviving round-trip promise is proven end to end against the real seeded olive oil version and its 2 Aug batch.**

## Performance

- **Duration:** ~25 min
- **Started:** 2026-09-10 (session start; see git log for the previous plan's completion, 3def10b)
- **Completed:** 2026-09-10T03:36:39Z
- **Tasks:** 2
- **Files modified:** 4 (3 modified, 1 deleted)

## Accomplishments

- `validateRow` in `app/src/store/transfer.js` replaced its stored-`grams` gate with a `portions` gate: a non-empty array whose every element carries a finite non-negative `grams` and a finite `step`, each reported at its own indexed path.
- `validateBatch`'s `declaredAxes` check gained a per-element validator (`validateDeclaredAxis`), refusing exactly the old bare-string form that would otherwise reach `axesForBatch` as an axis with an undefined key and label (D-07a).
- `validateStoreFile` accepts the single value `schemaVersion: 4`, refusing 1, 2 and 3 with a named-path error; the `schemaVersion === 1` "batches absent or empty" branch and its doctrine comment are gone, replaced with a comment recording D-08's narrowed promise.
- `exportStore` writes `schemaVersion: 4`; `importStore` lost its lift branch entirely — `toImport` is now just `parsed`, validated directly, with the batches array always written.
- `app/src/store/versionLift.js` is deleted. Its last consumer, `app/src/domain/lineage.test.js`'s `liftVersionRecord idempotence` block, is deleted with it.
- `app/src/store/transfer.test.js` gained the phase's Done-when round trip: the real seeded olive oil version and its real 2 Aug batch, exported, serialised through `JSON.parse(JSON.stringify(...))`, and imported into a second empty repository — deep-equal to the originals.

## Decisions Made

- **D-07a's element check was taken.** Verified in planning against source that it costs "a few lines" (CONTEXT.md); it cost 13 (an 8-line `validateDeclaredAxis` function, following the file's existing named-validator convention, plus a 5-line call-site change in `validateBatch`), a little more than the "roughly six lines" estimate because it is a proper named function with its own doc comment rather than an inline block — matching `validateStep`/`validateAuthoredNote`/`validateTasting`'s existing shape.
- **The exact wording of the replacement comment above `validateStoreFile`** (the one that records D-08's narrowed promise, replacing the deleted doctrine comment about why schemaVersion 1 was special):

  > D-08: the accepted schema is the single value 4. A store exported after this change imports after it; a store exported before it — schemaVersion 1, 2 or 3 — is refused as old rather than silently read as current. Reinstating that older promise means restoring one lift branch in importStore alone, never a second live-database ladder (CONTEXT.md Deferred Ideas).

- **The three `row.grams`-typed cases were rewritten, not deleted**, since their subject (a malformed grams value) survives the shape change — only the field moved from `row.grams` to `row.portions[0].grams`. The negative-amount case doubles as the plan's requested "a row whose portion carries a negative amount is refused at its own indexed path" addition, avoiding a redundant second case.
- **Two fixtures' literal `schemaVersion` changed from 4 to 3** (`'reports two errors for a payload with two distinct faults'` and importStore's `'writes nothing on an invalid payload'`): both previously combined an invalid `app` with `schemaVersion: 4` to produce two faults; since 4 is now the accepted value, that combination would have produced only one fault. 3 (the immediately-prior, now-refused number) restores the intended two-fault coverage.
- **The final `__proto__`-on-a-method-step test in `describe('validateVersion, the new fields (D-06)')` was updated** to a well-formed schemaVersion-4/portions-shaped payload (it previously hardcoded schemaVersion 1 and a bare `grams` row field, which the row shape itself forces to change) so the assertion isolates the `__proto__` detection rather than also tripping the (now unrelated) schemaVersion and portions gates.
