### `app/src/store/db.js` — the reset (D-05)

**Analog:** itself — the file's own guarded-`createObjectStore` pattern is the thing to *keep*; the cursor-lift branch is the thing to *delete*.

**Pattern to copy** (lines 9-21, the part that survives):
```js
export function openStore() {
  return openDB(DB_NAME, DB_VERSION, {
    async upgrade(db, oldVersion, newVersion, transaction) {
      if (!db.objectStoreNames.contains('versions')) {
        db.createObjectStore('versions', { keyPath: 'id' });
      }
      if (!db.objectStoreNames.contains('batches')) {
        const batches = db.createObjectStore('batches', { keyPath: 'id' });
        batches.createIndex('by-version', 'versionId');
      }
      // D-05: the store resets rather than lifts — drop both stores
      // before recreating them so a returning profile reseeds clean
      // through seedIfEmpty rather than holding a stale-shaped record.
      if (oldVersion > 0 && oldVersion < DB_VERSION) {
        if (db.objectStoreNames.contains('versions')) db.deleteObjectStore('versions');
        if (db.objectStoreNames.contains('batches')) db.deleteObjectStore('batches');
      }
    },
  });
}
```
The two `createObjectStore` guards stay verbatim (they are the thing db.js's own comment calls load-bearing). The comment above the deleted cursor branch (lines 25-30 today) is the model for the new comment: state which awaits are IDB-native and why nothing here can auto-commit the transaction early — the constraint the file already documents survives (D-05, CONTEXT.md decisions). `import { liftVersionRecord } from './versionLift.js';` (line 2) is removed — this import becomes orphaned by this file's own change and must go.

**Bump:** `DB_VERSION` (line 5) increments from 3 to 4.

## Shared Patterns

### The derived-total discipline (D-01)
**Source:** `app/src/domain/batch.js`'s own precision-contract comment (lines 7-13) — "never rounded, never re-formatted... shows what was entered" for as-made, vs. `composition.js`'s `formatGramsValue` (lines 87-96) for computed figures.
**Apply to:** every domain module that currently reads `row.grams` — the derived total is a computed figure (sum of portions), so it inherits `figures.js`'s stated→derived→estimated→inherited basis ranking only insofar as its own composition math already does; the sum itself is exact arithmetic, not a basis-tracked figure.

### Own-property-over-truthiness (D-10, D-11, already codebase-wide)
**Source:** `app/src/domain/batch.js` `asMadeTotals` (lines 155-178) and `createBatch`'s `asMade` loop (lines 46-49); `store/transfer.js`'s comment on `validateBatch` ("explicit null test... never a finite check falling back to truthiness").
**Apply to:** whatever per-portion as-made key shape the plan picks in `batch-2026-08-02.js` and `domain/batch.js` — a written 0 must still read as a real value, never as absent.

### Collect-every-error, name-every-path (transfer.js, unchanged doctrine)
**Source:** `app/src/store/transfer.js`, every `validate*` function.
**Apply to:** the narrowed `validateStoreFile` — the *style* survives even as the accepted-schemaVersion set shrinks to one value.

### Comment-states-the-rule-once (codebase-wide convention)
**Source:** every file read above opens with a comment block stating what it is pure of (framework/DOM/store) and what invariant it protects; `stepNumbers.js`'s header is the clearest example.
**Apply to:** any new function this phase adds (the derived-total helper, the new `formatStepReferences`) — follow this house style rather than a bare function with no comment.
