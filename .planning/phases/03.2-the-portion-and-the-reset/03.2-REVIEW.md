## Info

### IN-01: A whitespace-only grams field is read three different ways, and has been since before this plan

**Files:** `app/src/domain/lineage.js:170`, `app/src/domain/lineage.js:150`, `app/src/ui/IngredientTable.jsx:690`
**Severity:** informational — not reachable without typing only whitespace into a grams field, and nothing bad persists, because the save is blocked either way.

A draft grams field holding `' '` is classified differently by each of its three readers:

| Reader | Test applied | Verdict for `' '` | Effect |
|---|---|---|---|
| `currentGramsValue` (`IngredientTable.jsx:683`) | `parseGramsDraft(g) ?? row.portions[i].grams` | `parseGramsDraft(' ')` is `null` → falls back | The derived figures on screen show the **stored** amount |
| `changedGrams` (`IngredientTable.jsx:690`) | `g.trim() === ''` | blank | The accessible name announces the **stored** amount — agreeing with the figures above |
| `findBlockedRow` (`lineage.js:170`) | `g === '' \|\| g === undefined`, then `parseGramsDraft(g) === null` | **not blank — invalid** | Save blocked with "…'s amount is not a number" rather than "…needs an amount" |

The first two agree; the third dissents. That split predates this plan — `parseGramsDraft`'s `??` fallback and `findBlockedRow`'s exact `=== ''` were both already there — and the new `changedGrams` line simply inherits it, siding with the visible figures, which is the right property for an accessible name to have.

Compounding it: `blockedSaveMessage` is called inside `buildPenFields` (`RecipePage.jsx:1048`), which runs on a save attempt, **not** on keystroke. So a maker can type a space, watch the figures sit at the old number, and learn nothing is wrong until they press Save.

**Why the original `=== ''` recommendation was withdrawn.** It rested on the claim that exact `=== ''` is this codebase's blank convention. It is not: `.trim() === ''` is the established test — `penDraft.reason` (`RecipePage.jsx:1072`), `versionLabel` (`lineage.js:202`, `219`), tasting words (`batch.js:230`). Exact `=== ''` appears in exactly one place, the grams branch of `findBlockedRow`. And applying the change would make `changedGrams` announce the literal space, joining to `now   + 250.4 g` — a dangling `+` in the accessible name, i.e. the CR-01 artifact class this very plan closed. **Do not apply it.**

**If this is ever worth closing**, the change is at the source, not at the announcement: make `findBlockedRow`'s first test `draftPortion.grams === undefined || draftPortion.grams.trim() === ''`, so all three readers agree and the maker is told "…needs an amount, or remove the row", which is the true statement. One line in `lineage.js`. Best folded into a later phase already opening the pen's save path; not worth a trip on its own.

### IN-02: No test pins the whitespace-only case

**File:** `app/src/ui/IngredientTable.test.jsx`
**Issue:** The new "pen announces the amount it would save for a portion field left blank" test (line 291) only exercises an exact empty string (`grams: ''`). It does not cover a whitespace-only value (`' '`), which is the input that exposes the three-way split in IN-01 above, nor a non-blank-but-invalid value (e.g. `'4o'`) in a multi-portion row's `changedGrams`/aria-label, which would pin the pre-existing (and still current) literal-echo behavior for that case.
**Fix (only alongside IN-01's source-level change, if that is ever taken):** add a case asserting that `'  '` (whitespace) in a portion field announces the stored amount, pinning today's shipped behaviour rather than changing it, and, if the literal-echo-for-invalid-text behavior is intentionally out of scope for this plan, a short regression test pinning that today's behavior for `'4o'` is unchanged.
