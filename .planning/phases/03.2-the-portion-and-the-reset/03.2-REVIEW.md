## Warnings

### WR-01: `changedGrams`'s new blank check uses `.trim() === ''`, which is a different definition of "blank" than the rest of this pen uses, so a whitespace-only grams input announces the wrong outcome

**File:** `app/src/ui/IngredientTable.jsx:690`
**Issue:**

```js
const changedGrams = gramsDirty
  ? draftRow.portions
      .map((portion, i) => (portion.grams.trim() === '' ? String(row.portions[i].grams) : portion.grams))
      .join(' + ')
  : null;
```

Every other blank check in this codebase — `findBlockedRow` in `app/src/domain/lineage.js:170` (`draftPortion.grams === undefined || draftPortion.grams === ''`), and `handleChangeAsMade`'s "back to empty string" rule in `RecipePage.jsx:658` — uses an exact `=== ''` comparison, and `parseGramsDraft`'s own `NUMERIC_GRAMS_PATTERN` is explicitly documented as having "no surrounding whitespace," i.e. whitespace-only is treated as an *invalid* value, not a *blank* one, and gets its own distinct user-facing message ("...'s amount is not a number", not "...needs an amount").

`changedGrams`'s new `.trim() === ''` test collapses that distinction: a portion typed as `" "` (space) is treated as blank and announces the row's *stored* amount as the value that will be kept —

```
was 40 g, now 40 g
```

— while the same input, on save, is rejected by `findBlockedRow` with "Row A's amount is not a number," not silently kept. The accessible announcement tells the screen-reader user their edit is a no-op ("now 40 g," same as before), when in fact the maker cannot save at all until they fix or clear the field. This is new code (no `.trim()` fallback existed before this diff), untested, and reachable by an ordinary keystroke (pressing space).

**Fix:** Match the codebase's existing blank predicate instead of introducing a new one:

```js
const changedGrams = gramsDirty
  ? draftRow.portions
      .map((portion, i) => (portion.grams === '' ? String(row.portions[i].grams) : portion.grams))
      .join(' + ')
  : null;
```

(Non-blank invalid strings such as `"4o"` continue to be announced literally, which is the pre-existing, unchanged behavior for that case and out of this diff's scope.)

## Info

### IN-01: No test pins the whitespace-only case this diff's new predicate introduces

**File:** `app/src/ui/IngredientTable.test.jsx`
**Issue:** The new "pen announces the amount it would save for a portion field left blank" test (line 291) only exercises an exact empty string (`grams: ''`). It does not cover a whitespace-only value (`' '`), which is the input that exposes WR-01 above, nor a non-blank-but-invalid value (e.g. `'4o'`) in a multi-portion row's `changedGrams`/aria-label, which would pin the pre-existing (and still current) literal-echo behavior for that case.
**Fix:** Add a case (or `it.each`) asserting that `'  '` (whitespace) in a portion field behaves like `''` once WR-01 is fixed — i.e. announces the stored amount — and, if the literal-echo-for-invalid-text behavior is intentionally out of scope for this plan, a short regression test pinning that today's behavior for `'4o'` is unchanged.
