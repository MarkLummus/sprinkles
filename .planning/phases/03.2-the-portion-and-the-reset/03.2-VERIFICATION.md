### Gap Closure Detail (Truth 11 / CR-01)

The gap recorded in the prior pass (`03.2-05-PLAN.md`'s target) is closed at the source level:

- `formatAsMadeReading` (`IngredientTable.jsx` ~410-424) now maps each portion through `asMadeForPortion`, filters out `null` (dropping only unwritten portions — the explicit `!== null` test is preserved so a written `0` survives), and returns `null` (not `''`) when nothing survives, rather than joining raw values including empty strings.
- The pen's `changedGrams` (`IngredientTable.jsx` ~688-692) now substitutes a blank portion's own stored amount (`row.portions[i].grams`) instead of leaving an empty join entry — matching the exact rule `currentGramsValue` already applies via `parseGramsDraft(...) ?? portion.grams`.

Both were re-verified by direct execution against the current source (not by re-reading the SUMMARY's claims), using a probe independent of the plan's own test file, and by exercising the plan's own new/rewritten test cases in `IngredientTable.test.jsx` (4 cases, full-string assertions, not substring).

### New Finding: WR-01 (pen's whitespace-only blank check) — confirmed still present, not phase-blocking

This run's own code review (`03.2-REVIEW.md`, commit `8a97bf1`) flagged that `changedGrams`'s new blank predicate uses `.trim() === ''` where the rest of the codebase (`findBlockedRow` in `app/src/domain/lineage.js`, `handleChangeAsMade` in `RecipePage.jsx`) uses exact `=== ''`. I confirmed this live: typing a single space into a portion field (`grams: ' '`) produces `aria-label="Whole milk, was 370.4 g, now 120 + 250.4 g"` — the pen announces the *stored* amount as if the edit were a no-op, while `findBlockedRow`'s save-time check would reject the same input with "...'s amount is not a number," not silently keep it. This is a genuine accessible-name/save-path mismatch, confirmed reproducible against the current source.

**Judgment on phase-goal impact:** does not block. The phase goal concerns portions becoming the authored amount, the derived total, `step`/`splitStep` retirement, and store reset — all satisfied. WR-01 is an accessible-name announcement inside the pen's mid-edit state for an edge-case keystroke (typing a bare space), not a data-correctness or persistence defect, and the executor implemented the plan exactly as written (`03.2-05-PLAN.md` explicitly specified "blank (empty or whitespace only)"). It is a plan-level design choice a reviewer disagreed with, not an execution defect or a regression the phase's Done-when text names. Recorded below as a warning for follow-up, not a gap.
