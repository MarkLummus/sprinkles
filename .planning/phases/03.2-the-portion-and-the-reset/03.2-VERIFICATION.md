### Gap Closure Detail (Truth 11 / CR-01)

The gap recorded in the prior pass (`03.2-05-PLAN.md`'s target) is closed at the source level:

- `formatAsMadeReading` (`IngredientTable.jsx` ~410-424) now maps each portion through `asMadeForPortion`, filters out `null` (dropping only unwritten portions — the explicit `!== null` test is preserved so a written `0` survives), and returns `null` (not `''`) when nothing survives, rather than joining raw values including empty strings.
- The pen's `changedGrams` (`IngredientTable.jsx` ~688-692) now substitutes a blank portion's own stored amount (`row.portions[i].grams`) instead of leaving an empty join entry — matching the exact rule `currentGramsValue` already applies via `parseGramsDraft(...) ?? portion.grams`.

Both were re-verified by direct execution against the current source (not by re-reading the SUMMARY's claims), using a probe independent of the plan's own test file, and by exercising the plan's own new/rewritten test cases in `IngredientTable.test.jsx` (4 cases, full-string assertions, not substring).

### New Finding: IN-01 (whitespace-only grams read three ways) — informational, not phase-blocking

This run's own code review originally filed this as a Warning, claiming `changedGrams`'s `.trim() === ''` diverged from a codebase-wide exact `=== ''` convention and should be changed to match. **That recommendation was withdrawn on 2026-09-10 (Mark's call) and the finding downgraded to informational** — see the downgrade note in `03.2-REVIEW.md` (§ Summary) and its rewritten IN-01. Two corrections to the original framing:

- **The premise was wrong.** `.trim() === ''` *is* this codebase's blank convention — `penDraft.reason` (`RecipePage.jsx:1072`), `versionLabel` (`lineage.js:202`, `219`), tasting words (`batch.js:230`). Exact `=== ''` appears in one place only, the grams branch of `findBlockedRow`.
- **The proposed fix would regress.** With `=== ''`, a field holding `' '` announces the literal space, joining to `now   + 250.4 g` — a dangling `+` in the accessible name, the CR-01 artifact class this plan just closed.

What is genuinely true, and predates this plan: a whitespace-only grams field is read three ways. `currentGramsValue` falls back to the stored amount (`parseGramsDraft(' ')` is `null`); the new `changedGrams` announces that same stored amount, so screen and screen reader agree; but `findBlockedRow` classes it invalid and blocks the save as "...'s amount is not a number" rather than "needs an amount" — and only at save time, since `blockedSaveMessage` runs inside `buildPenFields` (`RecipePage.jsx:1048`), not on keystroke. The shipped line inherits that split; it did not create it, and it sides with the visible figures, which is the right property for an accessible name.

**Judgment on phase-goal impact:** does not block. The phase goal concerns portions becoming the authored amount, the derived total, `step`/`splitStep` retirement, and store reset — all satisfied. IN-01 concerns an edge-case keystroke (typing a bare space) in the pen's mid-edit state, nothing persists wrong because the save is blocked either way, and the executor implemented the plan exactly as written (`03.2-05-PLAN.md` explicitly specified "blank (empty or whitespace only)"). Recorded as informational, not a warning and not a gap. **If it is ever closed, the change belongs at the source, not the announcement:** make `findBlockedRow`'s first test `draftPortion.grams === undefined || draftPortion.grams.trim() === ''` so all three readers agree — one line in `lineage.js`, best folded into a later phase already opening the pen's save path.
