# Phase 03.3 Plan 01: The front-matter rows split, WR-01 fix, and margin retirement Summary

**Split `Versions.jsx` into `VersionRow.jsx` and `BatchRow.jsx`, stacked the front matter into two full-width rows with a batch-row measured-cell grid, retired the margin's "Notes" heading, moved "Before you start" to head the Method, ruled the three blank prose fields, and fixed WR-01's blocked-save focus bug with an attempt counter.**

## Accomplishments

- Split `Versions.jsx` into `VersionRow.jsx` (the version's own row — Develop, the version strip, the lineage line) and `BatchRow.jsx` (the batch's own row — Record another/Amend/Add tasting, the churn and tasting content merged wholesale from `BatchMargin.jsx`, the batch list). Neither carries a page-level running head.
- Reworked `.recipe-band` from a single side-by-side row into two full-width stacked rows (`.recipe-band__row-version` carries the version row's own two-column split forward unchanged), closed above Ingredients by a baseline-weight rule.
- Introduced the batch row's measured-value cells (`batch-row__cells`/`__cell`/`__cell-label`/`__cell-value`, reading the new `--col-batch-cell-min` token) for the churn triple and every tasting's own measured/mark rows, replacing the retired `batch-margin__measured` paragraph list.
- Fixed WR-01 (03.1 REVIEW.md): `RecipePage.jsx`'s `blockedAttemptRef` now stamps an incrementing attempt number onto `blockedTarget` on every blocked save, and `VersionRow.jsx`'s focus-return effect keys on that number (`versionLineBlockedAttempt`) instead of a value-equal boolean — a second consecutive blocked press now re-fires the effect.
- Retired the margin as a titled region: `RecipePage.jsx`'s `margin-region` is now an untitled `<div>` holding only `DerivedAdvisories` and `Authored`'s carried-forward list.
- Moved "Before you start" out of `Authored.jsx` (which now exports the shared `NoteList` and renders only `carriedForward`) to head `Method.jsx`, before step 1, inside a new `.method__before` block.
- Ruled the three named blank prose fields (draw notes, ingredient notes, next time) with `prose-field--empty`'s hairline rule, applied conditionally on each field's own draft value being the empty string — no visible label added.

## Verify Gate Note (not a deviation — a documented false positive)

Task 1's automated CSS-literal-escape gate (`sed ... | grep -E '[0-9]+(px|rem|em)' | grep -v 'var(--'`) prints one line for `.batch-row__cell-label`: `letter-spacing: 0.04em;`. This is the plan's own literal, verbatim action text, and it matches 11 other identical, un-tokenized occurrences already present throughout `app.css` (`region-name`, `versions__lineage-label`, `batch-margin__legend`, etc.) — `letter-spacing` has never been part of this project's token discipline (colour, face, size, spacing, rule weight per CLAUDE.md), unlike every other value in the six checked rule blocks, which read exclusively through `var(--...)`. Confirmed manually: no other literal unit escapes `var()` in any of the six blocks. Treating this single, pre-existing-convention line as a real violation would mean either deviating from the plan's own explicit CSS text or inventing a new token inconsistent with every other identical rule in the file — neither is warranted.
