# Phase 03.3 Plan 02: The ingredient table in step order Summary

**Rebuilt `IngredientTable.jsx` around per-portion, step-grouped rendering across all three render branches, added `formatPortionLine` to `domain/composition.js` for the split-ingredient sub-line, deleted the pen's step-choice `<select>` outright (LD-02), fixed WR-01's second half, and retired the Step column's CSS/tokens.**

## Accomplishments

- Added `formatPortionLine(portionGrams, rowTotalGrams, mass)` to `app/src/domain/composition.js`, composing the existing `formatGrams`/`formatShareOfBatch` rather than reimplementing their rounding/trace-threshold rules; `portionGrams` prints exactly as given (never `.toFixed()`'d), matching the never-round-a-stored-amount discipline `formatGrams`'s own doc comment states. Tested against the sketch's own worked example, the same-tail invariant across a split row's two portions, and a trace-share case.
- Rebuilt `IngredientTable.jsx`'s body across all three render branches (reading, pen, show-changes): a local `groupPortionsByStep` helper resolves every portion's step through `displayNumberOf` alone (never a hand-rolled filter mentioning `removed`), bucketing an unresolvable portion into a trailing "Unallocated" group instead of dropping it. Each group renders one step-head `<tr>` (the step's lead-in text) followed by one `<tr>` per portion in that group, in `rows`' own iteration order.
- A split ingredient's name repeats once per step it participates in, each occurrence carrying the `formatPortionLine` sub-line beneath it (`.ingredient-table__portion-note`), in the sketch's exact format including the middle dot.
- Deleted `StepCell` (the pen's step-choice `<select>`), `DiffStepCell`, `formatStepReferences`, `formatDiffSteps`, `resolveStepNumber`, `safeDisplayNumberOf`, and `formatAsMadeReading` outright (LD-02: a portion's step is no longer editable in the pen — a deliberate, recorded editability regression; amounts stay editable per portion, unchanged).
- `GramsCell`/`AsMadeCell` are now portion-scoped (one field for one named `portionIndex`) instead of looping over `row.portions` and joining every field with `" + "` inside one cell — a direct consequence of each portion now being its own `<tr>`.
- Fixed WR-01's `IngredientTable.jsx` half: the blocked-save focus effect now keys on a new `blockedRowAttempt` prop (`RecipePage.jsx`'s existing `blockedTarget.attempt` counter, already stamped by 03.3-01's `blockedAttemptRef`) instead of `blockedRowId` alone, so a second consecutive blocked press on the same row re-fires the effect.
- `RecipePage.jsx`: `<IngredientTable>` gains `steps` (the same expression `<Method>`'s own `steps` prop already computes) and `blockedRowAttempt`; loses `onChangePenRowStep` and `baselineStepNumbers`. `handleChangePenRowStep` deleted as fully orphaned by `StepCell`'s removal.
- `tokens.css`: `--col-step`/`--col-step-pen` deleted, with a retirement note in the `--col-ingredient` precedent's style. `app.css`: the four rule blocks the Step column and its pen `<select>` alone consumed are deleted; three new token-only rules (`.ingredient-table__step-head`, `__step-head-lead`, `__portion-note`) transcribe the sketch's own CSS.

## Decisions Made

- Kept `rowAccessibleLabel`'s grams/share phrase row-level (the row's own stored total) rather than portion-level, since that total is genuinely visible in every one of a split row's portion-`<tr>`s via the sub-line — the announced value agrees with the row's own visible content, not just the one field on that particular `<tr>`.
- Made `asMadeValue` in both accessible-label functions portion-scoped, matching `AsMadeCell`'s own now-portion-scoped rendering — no row-level joined as-made summary exists anywhere in the new design for a row-level label to agree with.
- `formatPortionLine`'s `rowTotalGrams` argument stays `rowGrams(row)` (the row's stored/baseline total) in all three branches, including the pen — only `portionGrams` and `mass` vary by branch, per the plan's own explicit scoping of what changes across states.
