## Accomplishments

- Added `targetValueFor(version, label)` to `domain/rows.js`: a pure lookup walking `activeSteps(version)`, returning the first matching target's value or `null`, built on the module's own removal discipline (never reads a removed step's targets).
- Rebuilt BatchRow's reading-state head: one `batch-row__head` line (Batch region-name, `churned {date}` in pen blue, and a `{N} later batch(es)` disclosure toggle) replacing the old per-state legend; the D-09 always-a-list batch list is now gated behind that disclosure when `batches.length > 0`, and stays unconditional when it is 0.
- Closed G-03.3-3: the standalone empty-record paragraph now renders nothing when `batches.length === 0`; the D-09 list's own `<li>no batch yet</li>` entry is the only place the phrase appears (`grep -c` confirms exactly 1 occurrence).
- Restructured the three churn measured cells (Time to temperature, Draw temperature, Air) from folded ALL-CAPS label+unit strings to plain-word labels with units in a small-print span beside the figure; Time to temperature gained a `plan {targetValueFor(...)}` sub-line, Air a static `overrun` sub-line (the figures.js word/term idiom applied to a churn field for the first time). "Draw temperature" kept its locked label text and no sub-line.
- Added a `churnMeasured(value, options)` display helper wrapping `readMeasured` to substitute "not measured" for "unknown" in these cells only — `readMeasured`'s own default export and every other call site are untouched.
- Converted the "recorded ... against ..." and "amended ..." prose sentences into `batch-row__cell` figure cells in the same grid as the three measured cells, rather than `<p className="ink-text">` lines.
- Built the "Batches of this version" disclosure panel behind the head's own count: per-batch churn date (bold, `· in view` on the current one), drawn temperature, words, and tasted-count meta line — per the sketch contract's Row 2 item 6, which the plan as written did not fully specify.
- Restructured `TastingReading` into one head line ("Tasting · at {temp} · {date}") and filtered per-axis cells to only those present as a key in `tasting.marks` — an unmarked axis renders nowhere, never as "unmarked". The melt-test cell always renders with a static "g at 20 min" unit.
- Relocated Correct/Add tasting from binder buttons at the top of the row to underlined `.text-control` elements at its foot, after the batch-margin content; the emptied `openPen === null` wrapper markup was deleted outright.
- **Checkpoint feedback, round 1 (519d67d):** Mark's live review found the record pen's four fields (churned date, Time to temperature, Draw temperature, Air) stretched to the full row width once the batch row widened in 03.3-06/07. Added `--field-w-date`/`--field-w-figure` tokens, scoped width rules to the pen's own date/number inputs, and laid the three churn number fields side by side in the same grid the reading state uses.
- **Checkpoint feedback, round 2 (7bda1c4):** Mark caught the head line printing "churned {date}" for the batch already in view while a new record's own empty fields sat above it, sandwiched with that new record's Save/Cancel. The head's date/later-batches control now names the batch in view only when `openPen !== 'record'` (amend keeps both, since amend corrects that same batch); the churned date moved into the pen's own field grid as its first cell; Cancel/Save moved to the pen's foot, in the same `batch-row__acts` row the reading state already uses for Correct/Add tasting.
