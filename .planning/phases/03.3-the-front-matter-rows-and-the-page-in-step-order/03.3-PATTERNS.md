### `app/src/domain/composition.js` — split-ingredient sub-line formatter

**Analog:** the two adjacent formatters already in this file, `formatShareOfBatch` and `formatGrams` (`composition.js:80-106`):
```javascript
export function formatShareOfBatch(grams, mass) {
  if (!(mass > 0)) return '—';
  const share = (100 * grams) / mass;
  if (share < 0.05) return 'trace';
  return `${share.toFixed(1)}%`;
}

export function formatGramsValue(grams) {
  return grams.toFixed(1);
}

export function formatGrams(grams) {
  return `${formatGramsValue(grams)} g`;
}
```
**Pattern to follow for the new formatter** (e.g. `formatPortionLine(portionGrams, rowTotalGrams, mass)`): a pure function in this same file, composing the two above rather than duplicating their rounding/threshold logic — e.g. ``` `${portionGrams} g of ${formatGrams(rowTotalGrams)} · ${formatShareOfBatch(rowTotalGrams, mass)} in all` ```. Add its test to `composition.test.js` alongside the existing formatter tests, not inline JSX assembly (this is A2 in RESEARCH.md's Assumptions Log — a convention inference, not a binding source, but consistent with every other display-string builder in this codebase living in `domain/composition.js`).

**Consumer site pattern (where it plugs in):** `IngredientTable.jsx:2` already imports `{ computeBalance, formatShareOfBatch, formatGrams, formatGramsValue }` from this module — add the new formatter to the same import line, call it once per portion inside the step-grouped per-portion `<tr>`.

### `app/src/ui/Method.jsx` — read-only pen with `edit this step` disclosure

**Analog:** the file's own `useOnDemandField` hook and its two existing call sites (`purpose`, `aside`), `Method.jsx:49-72` and `195-249`:
```javascript
function useOnDemandField(initialOpen, onCollapse) {
  const [isOpen, setIsOpen] = useState(initialOpen);
  const fieldRef = useRef(null);
  const openedByUser = useRef(false);

  function openField() {
    openedByUser.current = true;
    setIsOpen(true);
  }

  useEffect(() => {
    if (isOpen && openedByUser.current) fieldRef.current?.focus();
  }, [isOpen]);

  function handleBlur(event) {
    if (event.target.value.trim() === '') {
      setIsOpen(false);
      openedByUser.current = false;
      onCollapse();
    }
  }

  return { isOpen, openField, fieldRef, handleBlur };
}
```
```jsx
{purpose.isOpen ? (

    onClick={purpose.openField}

    add purpose
  </button>
)}
```
**Pattern to apply at the whole-step level:** per RESEARCH.md's own recommendation, call `useOnDemandField` (or a sibling `useState`-based toggle following the identical open/collapse shape) once per step to gate the whole `StepPenBody` field set, with the closed state rendering the show-changes branch's read-only JSX (`Method.jsx:551-618`, excerpted above under IngredientTable's analog) and one `edit this step` button styled with the new `.text-control` class (not `.method-step__on-demand`'s current binder-adjacent styling — RESEARCH.md's scope explicitly wants text controls, not bordered buttons, for these specific controls).
