# Sketch 003 variant B — structural contract for the front matter

Derived 2026-09-10 from `.planning/sketches/003-front-matter-rows/index.html` (variant B, the one Mark chose 2026-09-09) and its README's "Handoff" decisions. This is the acceptance target for the 03.3 gap plans (06, 07). Where a plan's prose and this file disagree, the sketch file wins, then this file.

Reading rule for executors and checkers: every region below names the sketch's element, its place in the page grid, its states, and the exact text it shows. Acceptance is DOM order and placement plus text, not label presence alone.

## Page grid (variant B)

- `.page` is a two-column grid. In B the front matter (`header.front`) spans both columns (`grid-template-areas: 'front front' 'ingredients side' 'method side'`).
- `header.front` closes with a baseline-weight rule (`--rule-baseline`) above Ingredients.
- Inside `.front`, two rows in order: `.row.row-version`, then `.row.row-batch`. Each row ends with a graduation-weight rule (`--rule-graduation`); the last row carries none (the front's baseline rule closes it).

## Row 1 — the version row (`.row-version`)

Grid: two columns, `minmax(0, 1.6fr) minmax(300px, 1fr)`, gap `--gap-l`, items aligned to start. Children in DOM order:

1. `.headnote` (left): `h1` recipe name; `p.version` version line; `p.prose` headnote prose. Max width `--measure-prose`.
2. `.vmeta` (right):
   - `h2.region-name` **Version**
   - `dl` (grid `max-content 1fr`, gap `--gap-hair --gap-s`), `dt` small-print uppercase. Rows by state:
     - Root version: `Written` → date; `Why` → reason text (text face); `Later` → text control `N later versions` (only when N > 0).
     - Child version: `From version` → `version <parent line as link> · written <date>` (the app keeps "From version", locked 2026-09-10; the sketch says "From"); `Why` → reason or `no reason given`; `From batch` → cited batch as link (only when cited). No `Written` row on a child; `Later` row when N > 0.
   - `.acts` (flex, gap `--gap-s`, margin-top `--gap-s`): `button.btn` **Next version**, `button.btn` **Record another** (version has a batch) or **Record batch** (none), then, on a child, `button.text-control` **Show changes**.
3. `section.ceremony` (the Next version pen), `grid-column: 1 / -1`, hidden until open. When open it is a two-column grid with the same columns as the row:
   - Left: `h2.region-name` `Next version · from <current version line>`; `label` with `span` **Version** over `input.ink-field` (placeholder `e.g. 48 g oil · 800 g`); `p.was` `was <current version line>`; `label` with `span` **Why** over `textarea.prose-field` rows=2 (placeholder `e.g. more oil, after the batch of 2 Aug`).
   - Right: `label` with `span` **From batch** over `select.ink-field` (options: each batch as `the batch of <date>`, plus `no batch`); `.saves` flex row: `button.btn` **Cancel**, `button.btn` **Save as new version**; `p.blocked` for the blocked-save message (`The version needs a name before this saves.`).
   - While the pen is open the sketch hides `.vmeta` entirely and the row collapses to one column (`[data-pen="develop"] .vmeta { display:none }`). The app instead keeps the metadata visible and shows a "Links return after you save or cancel." hint; that is an app decision, noted under Open items.
4. `section.list#list-versions`, `grid-column: 1 / -1`, hidden until the `Later` control opens it: `h2.region-name` **Later versions**; `ul.vtree` (grid `repeat(auto-fill, minmax(260px, 1fr))`), one `li` per descendant (the whole subtree, flat): `p.vline` version line as a link (text face, version-line size, no underline); `p.meta` `from <parent line> · after the batch of <cited date> · <written date>`; `p.batch` with `span.pen` `churned <date>` when it has a batch, then `button.text-control` **Open**.

Opening one list closes the other; Escape closes an untouched list or pen; Cancel returns focus to Next version.

## Row 2 — the batch row (`.row-batch`)

Children in DOM order:

1. `.head` (flex, baseline, gap `--gap-s`): `h2.region-name` **Batch**; `span.date` `churned <date>` (text face, version-line size, pen blue); `button.text-control` `N later batch(es)` when N > 0.
2. `.cells` (grid `repeat(auto-fit, minmax(96px, max-content))`), one `.cell` per measured fact: `span.k` label (small print, uppercase); `span.v` figure (figure-value size, bold, pen blue, tabular) with the unit in `span.u` (deviation-words size, regular); optional `span.plan` sub-line. Drawn cells: **Time to temperature** `20 min` / `plan 10–12`; **Out of the machine** `−6 °C` / `draw temperature` (the app keeps the label **Draw temperature**, locked 2026-09-10, and drops the sub-line); **Air** `not measured` / `overrun`; **Oil bottle open** `24 Jul 2026` (no such stored field exists; see Open items).
3. `p.words` the maker's words (text face, headnote-prose size, pen blue, max 65ch).
4. `.tasting`: `p.running-head` **Tasting** followed inline by `· at −12 °C · date unknown` (not uppercase, pen blue); `.cells` with only the marked axes: label is the axis word alone (**Oil character**, **Bitterness**, **Sweetness**), value with unit `of 5` on the first only; **Melt test** `3 g at 20 min`. Unmarked axes are absent, not "unmarked".
5. `.acts`: `button.text-control` **Correct**, `button.text-control` **Add tasting**.
6. `section.list#list-batches`, hidden until the head's control opens it: `h2.region-name` **Batches of this version**; `ul.blist` (flex, gap `--gap-l`, wrap), one `li` per batch: `p.date` the churn date (bold when it is the one in view, with `span.small` `· in view`; a link otherwise); `p.meta` `drawn −6 °C · soft, not greasy · tasted once` (draw temperature, the words, tasting count).

## After Save (the child version, from the sketch's script)

The version line becomes the typed line; the dl becomes From / Why / From batch as above; the acts become Next version, Record batch, Show changes; the batch row is removed. The README says the batch row reads "not churned yet" instead; see Open items.

## Scenarios the sketch does not draw (for Impeccable to complete)

1. **A version with no batch.** The script removes the batch row; the README says the row reads "not churned yet"; the app shows a `Batch` head with "no batch yet". Which of the three, and does Record batch live in the version row alone?
2. **Save over.** The README lists "Correct an unchurned plan without forking → Ceremony → Save over", but the pen only draws Cancel and Save as new version. The app has Cancel / Save as / Save. Labels and placement of the second save are undrawn.
3. **The record's pen** (Record another / Record batch): "ink in place; ceremony under the row and repeated at the foot" is described, never drawn.
4. **Correct** and **Add tasting** pens: described as opening on the page; not drawn.
5. **Show changes** state: "lays the strikes back on the page"; not drawn.
6. **A batch with no tasting**, a tasting with no marked axes, a batch with no words: the row's shape without those blocks is undrawn.
7. **Oil bottle open**: drawn as a measured cell, but no stored batch field exists. Either a new batch field (a schema change) or the cell goes.
8. **A root version with no descendants**: the dl without a Later row is implied, not drawn.
9. **A child version that also has descendants**: From version plus Later in one dl; implied by the rules, not drawn.
10. **The later-versions list beyond four entries** and **a deep subtree** (grandchildren): README marks this open; the list is flat.
11. **Pen open with the metadata hidden** (sketch) versus visible with a hint (app): the sketch hides `.vmeta` while the pen is open; the app keeps it and prints "Links return after you save or cancel." in each row.
12. **Blocked-save presentation**: only the sentence is given; its place and face are the sketch's `p.blocked` defaults.
13. **The fork's landing focus** and other keyboard paths: not a sketch concern; governed by D-27 and the phase's own decisions.
14. **"Draft" / "churned twice" wording** for a version's churn state: README only.
15. **Print** on the version row: Phase 4.

## Resolutions for the undrawn scenarios (Impeccable, 2026-09-10)

Most of §"Scenarios the sketch does not draw" turn out already decided elsewhere; only one item needed a fresh call. Resolved against `route-recipe-version.md` and `route-recipe-batch.md` (read 2026-09-10), most recent revisions.

1. **A version with no batch.** `.row-batch`'s `.head` reads `h2.region-name` **Batch** and `span.date` **no batch yet**, in ink, not pen blue — nothing was recorded, so nothing is the maker's. No cells, tasting, or acts block renders beneath it. "no batch yet" is the term already named in `route-recipe-batch.md` §4 ("the margin's 'no batch yet' state"); the README's "not churned yet" is superseded. Record batch already lives in the version row's own `.acts` (this file's Row 1, item 3: `Record batch` when the version has no batch) — the batch row itself carries no control.
2. **Save over.** Already decided, not undrawn by oversight: `route-recipe-version.md` §3 "The ceremony in the headnote" — a version with no batch offers two saves, "Save over this version" and "Save as a new version"; a churned version offers only "Save as a new version". The sketch's pen only needed one path because it draws a churned version forking.
3. **The record's pen** (Record another / Record batch). Already decided: `route-recipe-batch.md` §3 "The ceremony" and §6's 2026-09-08 revision — the pen's ceremony (date field, Save/Cancel) sits in the imprint, in place, with the same Save/Cancel pair repeated once at the foot of the page.
4. **Correct and Add tasting pens.** Same source as (3): "Amend" (labelled Correct) reopens the pen with the record's values in the fields; "Add a tasting" opens a dated tasting section in the margin. Both follow the imprint-ceremony-plus-foot-repeat pattern; the margin holds content only, no buttons.
5. **Show changes.** Already decided: `route-recipe-version.md` §3 "Lineage, the strip, and what changed" and §6 "Show-changes state" — a version-level toggle in the lineage line lays the pen's strike grammar back on the page in place; nothing moves, `aria-pressed` carries the state.
6. **Absent blocks.** No tasting: the batch reads "not yet evaluated" (already named, `route-recipe-batch.md` §3 "Silence becomes a value"), not a `.tasting` block. No marked axes: only marked axes render, per this file's own Row 2 item 4 ("Unmarked axes are absent, not 'unmarked'"). No words: `p.words` is absent, following the same "blank means nothing was written" convention as a blank measured cell.
7. **Oil bottle open.** Drop the cell for good, not pending a schema change. `route-recipe-batch.md` §4 "Out, and named" already scopes the oil bottle's open date as free text inside the batch's ingredient-notes line, never a discrete measured field. Plan 07's drop is correct and final.
8. **A root version with no descendants.** No `Later` row — each `dl` row already appears only when its condition holds; nothing further to decide.
9. **A child with its own descendants.** `From version` and `Later` both appear in the same `dl`; the rules that produce each are independent and both can be true at once.
10. **Later-versions overflow and deep subtrees.** Already decided by the sketch itself: the list is "the whole subtree, flat" (this file's Row 1 item 4), so grandchildren already render. Given the realistic ranges (`route-recipe-version.md` §5: 1–6 versions per recipe, 0–3 children per version), no recipe reaches a count where the `auto-fill` grid needs pagination in milestone 1; it simply wraps. No cap, no truncation.
11. **Pen open, metadata hidden vs. visible.** Already decided, not left open: the app keeps `.vmeta` visible with "Links return after you save or cancel."; the sketch's `display:none` was the sketch tool's shortcut, not a direction.
12. **Blocked-save presentation.** Already decided: `route-recipe-version.md` §6 "Fields" — the sentence renders at the ceremony (now the imprint) and the offending row or field is marked with the same weight-and-outline the trace uses. The sketch's `p.blocked` default placement matches.
13. **Fork's landing focus and other keyboard paths.** Out of scope here, as this file already notes; governed by D-27 and the phase's own decisions.
14. **"Draft" / "churned twice" wording.** Not adopted. Labels are governed by `product-requirements/05-domain-and-language.md`, which names neither; a version with any number of batches continues to read "churned <date>" with no count (Phase 1 D-21).
15. **Print.** Phase 4, out of scope here.
