# Phase 03.3.1 Plan 06: The battery's CSS layer and browser conformance Summary

**Battery tokens and responsive-ladder CSS land in tokens.css/app.css with the one-level at-rule contract intact; live-browser conformance testing against the structural contract found and fixed two real gaps (Home/End keyboard support, stop box-sizing) and surfaced one carry (the pen's 640px cap is not yet applied).**

## Performance

- **Duration:** ~2h15m (Tasks 1-2, gsd-executor in an isolated worktree) + ~1h (Task 3, orchestrator with Chrome browser tooling — gsd-executor has no browser tools)
- **Tasks:** 3 (Task 1 and 2 executed by a worktree agent; Task 3 executed directly by the orchestrator)

## Accomplishments

- Battery tokens (`--pen-w`, `--track-stop`, `--track-stop-narrow`, `--stop-w`, `--stop-h`, `--stop-gap`, touch/gap aliases, `--axes-cols-clearance`) declared in tokens.css with the contract's exact verified values.
- The `.axis-mark` desktop section rebuilt from scratch in app.css — it had gone stale relative to AxisMark.jsx's 03.3.1-03 rebuild (six-axis battery shape) and was never restyled until now.
- The responsive ladder: the desktop 3-column grid holds to 768px with a 12px clearance; below 760px the groups stack on a horizontal rule with `auto-fit` columns and 40×44 stops on a 216px track; a new sibling 600px `@media` block handles frame padding, field font sizes, and lets both save ceremonies wrap identically.
- The picked-state affordance (bold+underline+outline, never colour alone) landed with the carried P3: the filled-control underline is gone by construction.
- **Live-browser conformance pass** (real window resize, not emulation) found two real gaps beyond what the unit suites could catch, and both were fixed:
  1. Chrome's native radiogroup does not move focus on Home/End (only arrow keys) — added a minimal, arrow-key-free Home/End handler to `AxisMark.jsx`.
  2. `.axis-mark__stop` rendered 40×46 instead of the contract's 40×44 below 760px because the global `button, select { box-sizing: border-box }` rule doesn't reach a `<label>` — added the property directly.
- The final battery field list for Phase 4's PRINT planning is recorded below.

### Auto-fixed Issues (Tasks 1-2, by the worktree executor)

**1. [Rule 1/3] Dead `.axis-mark__legend` selector and stale binder pin, in files not in Tasks 1-2's declared list**
- **Found during:** Task 1's own verify command (`npm test -- src/styles`), which runs the whole style suite

- **Fix:** renamed the dead selector references to the live `.axis-mark__name`; updated the block-count assertion to two, at the two named breakpoints
- **Files modified:** `app/src/styles/binder.test.js`, `app/src/styles/cross-cutting.test.js`
- **Verification:** full style suite green (81/81)
- **Committed in:** `4403535`, `76bc598`

### Auto-fixed Issues (Task 3, found live and fixed by the orchestrator)

**2. [Rule 1 — correctness] Home/End did not move focus in AxisMark's stop groups**
- **Found during:** Task 3's real-browser keyboard-contract check
- **Issue:** the file's own docblock claimed "the browser already gives the group... Home and End", but Chrome's native radiogroup only supports arrow keys, not Home/End
- **Fix:** added a minimal keydown handler on the stops group that intercepts only `Home`/`End`, focuses and selects (via `onChange`, never `.click()`, so a repeat press never toggles clear) the first/last stop
- **Files modified:** `app/src/ui/AxisMark.jsx`
- **Verification:** live browser (End → stop 5 selected; Home → stop 1 selected; repeated Home stayed selected, did not clear); full suite still 885/885
- **Committed in:** `1dbef3c`

**3. [Rule 1 — correctness] `.axis-mark__stop` rendered 40×46, not the contract's 40×44, below 760px**
- **Found during:** Task 3's real-browser dimension measurement
- **Issue:** content-box sizing meant the 1px+1px border added onto the declared height instead of being drawn inside it
- **Fix:** added `box-sizing: border-box` to `.axis-mark__stop`, matching the codebase's existing `button, select` convention
- **Files modified:** `app/src/styles/app.css`
- **Verification:** live browser, re-measured 40×44 exactly at 700px; desktop 34×32 unaffected at 1280px; full suite still 885/885
- **Committed in:** `1dbef3c`
