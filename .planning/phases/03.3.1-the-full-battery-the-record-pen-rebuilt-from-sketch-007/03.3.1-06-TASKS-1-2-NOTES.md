### Known gap, flagged for Task 3 / Mark's review

**`--pen-w` (640px) is declared but not yet applied to any selector.** The
structural contract's "the pen is 640px wide" truth needs a container to
carry `max-width: var(--pen-w)`, but the only candidate container
(`.batch-margin`, `BatchRow.jsx`) is shared identically between the
recording pen and the batch's read view (no mode-scoped class distinguishes
them). Capping `.batch-margin` unconditionally would also shrink the
already-shipped, UAT-approved full-width read view (page-shell-front-
matter.md's "front matter spans the whole page" rule) — a real risk of
visually regressing prior, already-verified plans, with no way for me to
confirm the actual on-screen effect without a browser. Applying it correctly
appears to need a small JSX change (a recording-mode class on the container)
that sits outside Tasks 1–2's CSS-only file scope. I left the token declared
(documented in its own tokens.css comment) but unconsumed, rather than
guess. **The orchestrator's Task 3 browser pass should check the record
pen's real width at 1280px against this 640px expectation and decide
whether the follow-up JSX change is needed** (either in Task 3 itself, if
the Home/End contingency is already touching AxisMark.jsx/BatchRow.jsx, or
flagged onward).

**A handful of contract-adjacent DOM elements remain intentionally

## What Task 2 built (commit `76bc598`)

**The responsive ladder — 760px step-down and the 600px block**, citing the
structural contract's "Responsive ladder" section:

- `.axes-grid` / `.axes-rule`: the desktop 3-column layout (`AxesGrid`,
  `BatchRow.jsx`) — a real DOM swap driven by `useBelow760()`'s `matchMedia`
  read, not a CSS-media-scoped layout, so this rule carries no media guard
  of its own; the hairline sits at the contract's `calc(200% / 3)`,
  independent of the column gap. `--axes-cols-clearance` (12px) is the
  grid's own `column-gap`, so the verified 12px stop-to-rule clearance is
  that one token's arithmetic.
- `.axes-declared-caption`: shared by both the desktop (inside Body's own
  axis-mark box) and stacked (its own line above the declared group)
  renderings of "Declared for this recipe".
- `.axes-grid--stacked` / `.axes-grid__group` / `.axes-grid__group--declared`:
  the below-760px stacked arrangement — core and declared groups on a
  horizontal rule, each an `auto-fit, minmax(min(100%, 280px), 1fr)` grid
  (the contract's "collapsing further once two 280px columns no longer fit"
  is exactly what this formula does at any width, 393px included, with no
  second breakpoint needed for it specifically).
- Extended the existing `@media (max-width: 759.98px)` block:
  `.segmented__option` added to the 44px min-height list; the axis-mark
  stop's 40×44 box moved from the (now-invisible) input to the label
  (`.axis-mark__stop`) to match Task 1's rebuild; `.axis-mark__stops` /
  `.axis-mark__anchors` widen to `--track-stop-narrow` (216px).
- Added a **second, sibling top-level `@media (max-width: 600px)` block**
  (required — `css-source.js`'s one-level nesting contract forbids nesting

  `.batch-margin__field, .ink-field` font-size drops to `--type-control`;
  `.save-ceremony, .pen-foot__controls` both gain `flex-wrap: wrap` (one

### Judgment calls worth flagging for the browser pass

- **"Field-row label widths" (contract's 600px-block item) has no analogue
  in this codebase's layout.** The original sketch puts a field's label
  beside its input in a row; this codebase's `.batch-margin__field` already
  stacks label above input (`flex-direction: column`), so there's no
  side-by-side label width to shrink. I implemented the adjacent "field font
  sizes" tweak instead (drops to `--type-control`) as the closest available
  lever toward the same "reads comfortably at 600px" goal, and skipped the
  label-width item as inapplicable rather than inventing a rule for a
  layout shape that doesn't exist here.
- **"Frame padding" mapped to `.recipe-page`'s own padding**, since this
  codebase has no separate `.pen` frame — the whole page shell is what
  frames the record at every width. This is a page-wide change below
  600px, not scoped to the batch pen alone; I judged it safe/likely
  necessary (page padding at `--gap-xl`, 48px each side, plus the axes'
  narrow 216px track leaves uncomfortably little room well before 393px)
  but it hasn't been visually confirmed.
- **`--gap-chip-row` (aliases `--gap-s`, 12px) and `--declared-flaw-gap`
  (aliases `--gap-l`, 32px)** are my own reasoned choices — the plan's
  artifacts list named these tokens but not their values (unlike the
  geometry tokens, which the contract states verbatim). Worth a look
  alongside the browser pass.
