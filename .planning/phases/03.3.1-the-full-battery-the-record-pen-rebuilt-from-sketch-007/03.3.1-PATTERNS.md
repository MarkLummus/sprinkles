### `app/src/domain/axes.js` (domain constants, transform)

**Analog:** itself — `setMark` and the snapshot-only read survive byte-for-byte; `CORE_AXES`/`MARK_STOPS` are replaced by the contract's table.

**Imports pattern** (lines 1-6): framework-free header comment declaring the constraint, no imports at all:
```js
// Pure. No framework, no DOM, no store import. ...
```

**Surviving core pattern — prototype-safe marks write** (lines 53-74):
```js
export function setMark(marks, axisKey, stop) {
  const next = { ...marks };
  if (stop === null) {
    delete next[axisKey];
  } else {
    next[axisKey] = stop;
  }
  return next;
}
```
The header docblock (62-65) names why: object spread + delete write only own properties, never through an assignment path that could walk a prototype chain (T-02-32). Copy this discipline for every new map (defects set, marks).

**Surviving reader pattern — snapshot-only read** (lines 33-41): `axesForBatch(batch)` reads `batch.snapshot.declaredAxes` only, never a live version ("Reaching for a live version record here would be exactly the drift this phase exists to prevent"). The rewritten version must keep this contract whatever the new declared shape is.

**Replaced content:** `CORE_AXES` (15-20, behavioural anchors) and `MARK_STOPS` (23, nine half-stops) are superseded by the contract's AXES table (six rows of `[name, low, mid, high]`, five whole stops, stop words "low / leaning {low} / right / leaning {high} / high"; core = first four, declared = Body + Oil; Bitter is the declared-flaw toggle, not an axis). Build the AXES constant from the contract "Axes spec" verbatim — not invented here.

### `app/src/domain/battery.js` — new parser/constants (role-match analog: `app/src/domain/lineage.js`)

**Analog:** `lineage.js` — the pure draft-parser shape and the one-traversal block rule.

**Parser shape** (lineage.js lines 147-164):
```js
// A non-negative number with up to two decimals, kept exactly as typed
// (critique P1 #3, D-21): no leading minus, no stray letter, no
// surrounding whitespace, no exponent — anchored at both ends so a value
// like "4o" or "1.234" fails outright rather than partially matching.
const NUMERIC_GRAMS_PATTERN = /^\d+(\.\d{1,2})?$/;

export function parseGramsDraft(value) {
  return NUMERIC_GRAMS_PATTERN.test(value) ? Number(value) : null;
}
```
The battery's `parseMeasuredDraft(raw, { signed })` copies this *shape* (pure, anchored, returns null/ok-false on malformed) but with its own rules — decimal point and comma both accepted, Unicode minus normalised, negatives rejected except on °C fields via a `signed` field-metadata flag. RESEARCH.md Code Example 2 is the working sketch. **Do not reuse `parseGramsDraft`** (rejects `.5`/`45.`; brief § 7 records why not to merge) and **do not reuse `toNumberOrNull`** (RecipePage.jsx:235-239 silently converts a non-finite raw string to `null`, which would make a typo read "unknown" — Pitfall 4).

**One-traversal, message-and-target-never-disagree** (lineage.js lines 178-192, 214-236): `blockedSaveMessage` and `blockedSaveRowId` both read the single `findBlockedRow` walk so the sentence on screen and the field it names can never disagree (T-03.1-21). The churn-date block (D-05) follows the same rule: one derivation produces both the sentence and the focus target, beside both ceremonies.

**Field-config metadata precedent:** the battery's °C fields are known by metadata (`signed: true` on "Out of machine" and "Tasting temperature"), not by sniffing rendered label text. No in-repo field-config table exists yet — the closest stylistic match is `axes.js`'s fixed constant arrays; keep one home (planner's discretion per RESEARCH.md "battery.js?").

### `app/src/store/db.js` (store config, event-driven upgrade)

**Analog:** itself — D-09 says "bumps the constant and touches nothing structural."

**The reset upgrade, whole pattern** (lines 8-38):
```js
export function openStore() {
  return openDB(DB_NAME, DB_VERSION, {
    upgrade(db, oldVersion, newVersion, transaction) {
      // D-05: the store resets rather than lifts — drop both stores before
      // the two guarded creates below recreate them...
      if (oldVersion > 0 && oldVersion < DB_VERSION) {
        if (db.objectStoreNames.contains('versions')) db.deleteObjectStore('versions');
        if (db.objectStoreNames.contains('batches')) db.deleteObjectStore('batches');
      }
      // Both guards are load-bearing: this callback runs cumulatively...
      if (!db.objectStoreNames.contains('versions')) {
        db.createObjectStore('versions', { keyPath: 'id' });
      }
      if (!db.objectStoreNames.contains('batches')) {
        const batches = db.createObjectStore('batches', { keyPath: 'id' });
        batches.createIndex('by-version', 'versionId');
      }
      // This callback holds no async keyword at all...
    },
  });
}
```
Change: `DB_VERSION = 4` (line 4) → 5. Keep: drop-first-then-guarded-create order (documented as load-bearing), the no-async-keyword rule, the sole-`idb`-import constraint (lines 6-7).
