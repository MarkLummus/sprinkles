## Note on the roadmap goal's "decoupled churn/tasting saves" phrase

The ROADMAP.md goal text (written before phase discussion) says "decoupled churn/tasting saves." This is superseded by an explicit, recorded, Mark-approved mid-discussion decision (03.3.1-CONTEXT.md D-01–D-06): the sketch's decoupled two-scope save model was replaced with **one save action, repeated as two identical ceremonies**. This supersession is documented as the phase's "biggest fact" in the CONTEXT.md domain section and is honored consistently and correctly throughout the shipped code (`PenFoot.jsx`'s `SaveCeremony`, mounted twice, identical markup and label). This is not treated as a gap — it is a legitimate, human-approved design change captured in the phase's own decision record, and the phase's must_haves (authored after the decision) correctly build to D-01 rather than the stale roadmap phrase. This finding is unchanged from the initial verification.

## What changed since the prior verification

The prior `03.3.1-VERIFICATION.md` (generated 2026-09-13T19:10:00Z per its own frontmatter timestamp, though its body reported `Status: gaps_found`) found one concrete gap: plan 06's must-have "the pen is 640px wide" failed because `--pen-w` was declared in `tokens.css` but consumed by zero selectors — the pen rendered at its shared container's full width (~1013px at a 1280px viewport). The orchestrator fixed this immediately in commit `2fb0aba`, adding a recording-mode class `.batch-margin--pen` (applied by `BatchRow.jsx` only while `mode === 'recording'`) that `app.css` caps at `max-width: var(--pen-w)`. The prior VERIFICATION.md was hand-edited afterward to record the fix, but its `verified` timestamp predates the fix commit, so `gsd_run query verification.status` correctly reports the record `stale`. This report is a full, independent re-verification — every truth, artifact, key link and anti-pattern was re-checked against the current working tree, not assumed from the hand-edited record.

**Confirmed independently in this session:**
- `grep -c 'var(--pen-w)' app/src/styles/app.css` → 1 (was 0 before the fix)
- `app/src/ui/BatchRow.jsx:427` conditionally applies `batch-margin batch-margin--pen` only when `mode === 'recording'`; `BatchRow` renders exactly one `.batch-margin` container per mounted batch (the one-pen rule — `RecipePage.jsx` mounts a single `<BatchRow>`), so the cap can never leak onto the read view
