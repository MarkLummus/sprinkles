## Summary

Every one of the 18 UAT items traces to a concrete divergence between the app's source and the sketch's `<style>` block, and none of them is something the sketch draws the same way — the one candidate the CONTEXT named (the "Time to draw temp., min" caption wrapping) turns out to be an app-side problem: the app puts the unit word *inside* the caption (`BatchRow.jsx:69` renders `"Time to draw temp., min"`) while the sketch's caption is "TIME TO DRAW TEMP." with "min" beside the 48px box (sketch lines 213, 43–44), and the app's caption sits in a 96px-minimum grid cell (`app.css:1367-1372`) rather than a content-width label in a wrapping flex row (sketch lines 37–39). The sketch's `min-height: 2.4em` reserves two lines of *height*; it does not cause a wrap. So the D-03 triage table sends all 18 to "fix here", with one note for the record (the tasting-state text is roman ink in the sketch, not the "muted italic" the contract and CONTEXT describe).

**The D-22 sketch round is committed (`977846a`, the README's "Ninth round") and went further than the three edits CONTEXT listed.** Every sketch line number in this file is re-cited against that commit. Beyond D-04/D-08/D-12 and the Clear placement, Mark's 2026-09-14 calls redraw: the two ceremonies (both "Add tasting | Cancel | Save batch", right-aligned at every width, one end-of-record ceremony above Next time plus the foot — so the earlier "pre-declared departure" is gone and D-14 is now what the sketch draws); "Restore tasting" replacing "Undo clear tasting", taking Add tasting's place while a restore is pending, with the removal toast in a new `record-status` live region at the left of the end-of-record row; plain region names "Batch" and "Tasting"; group cue rows "Every recipe" / "This recipe only" above the axes and the defects moved *inside* the axes grid as two labelled groups (the "Declared for this recipe" cue, the Bitter aria-label and the "· declared" helper are all gone — D-08 is superseded); `.seg { row-gap: 6px }`; and "e.g." placeholders on all four prose fields. The "Re-citation against commit 977846a" subsection carries the planner's implications and test pins.

Three method facts shape the plans. First, the pen's tasting wrappers have *no CSS at all* — `.tasting-head`, `.tasting-field-row`, `.note-block`, `.melt-block`, `.defects-row__caption`, `.defects-row__helper`, `.tasting-head__helper`, the `<legend>`s and `.batch-margin__field span` are unstyled (grep-verified), which is why the Remove control sits below the caption, the field rows stack, the melt row stacks and the pen's captions are sentence case. Second, the picked-state rules to replace are exactly three (`app.css:1643-1649`, `1717-1721`, `1723-1727`, plus chips at `1745-1751`), and four style-test pins enumerate them by selector (`binder.test.js:191-207` underline list, `:43-52` outline count, `:248-264` and `cross-cutting.test.js:119-121` two-`@media`-block count) — the plans must update those pins in the same task as the CSS or the suite goes red. Third, the page-shell plan needs a third and fourth top-level `@media` block (1099.98px stack per sketch 003 line 48/510; the version row's collapse rides the existing 759.98px block per D-15) plus a `forced-colors` block for D-05, and the sketch 003 table columns sum to 368px, which cannot fit the 353px content width at 393 — the zero-overflow criterion needs a decision the sketch does not make.

**Primary recommendation:** four plans — (1) page shell against sketch 003 (ladder, version row, min-width 0, 393 overflow), (2) the battery's captions, field rows, widths, placeholders and the axes-and-defects grid with its cue rows (D-10–D-13; sketch lines 58–70, 261–282), (3) the picked/hover/focus/forced-colors rules, the tasting head, the two ceremonies' order/alignment and the Restore rule (D-04–D-09, D-14; lines 55, 242–246, 301–314), then (4) the orchestrator-run conformance pass with `gsd-browser` at the ten D-16 widths, writing CONFORMANCE.md against sketch commit `977846a`. ### Anti-Patterns to Avoid

- **Putting the unit word in the caption** (`BatchRow.jsx:69`): the sketch never does; it is the root cause of item 2.
- **Nesting a helper inside an uppercase caption** (`BatchRow.jsx:596`): the transform cascades into it.
- **Keeping the Bitter chip's aria-label, helper or wider gap** (`BatchRow.jsx:618-626`): the sketch's group cue "This recipe only" is the accessible name path now (line 276: `aria-labelledby="defects-caption defects-declared-cue"`); a leftover `aria-label="Declared for this recipe: Bitter"` would read a phrase the sketch no longer uses anywhere.
- **Routing the removal toast to the foot** (`RecipePage.jsx:953`): the sketch's `record-status` sits in the end-of-record ceremony (line 303) so feedback lives where the action was; `form-status` (309) is only the save/validation channel.
- **A fourth at-rule type or a nested at-rule**: `css-source.js` parses one level of `@media` only; `@container` and nesting break every style suite (`cross-cutting.test.js:119-147`).
- **Literal px in `app.css`**: `binder.test.js`'s no-bare-px gate; tokens first.
- **`outline: none` anywhere** (`binder.test.js:87-90`).
- **Changing `.batch-row__date`'s lowercase "churned 2 Aug 2026"** — that is sketch 003:237's own lowercase `.date` span, not a caption; D-12's "Churn date" is the *pen* caption at `BatchRow.jsx:427` only.
- **Reading widths from CSS and calling them measured**: the pass measures; this research only reasons (Pitfall 6).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Radiogroup keyboard semantics for stops/segments | A roving-`tabindex` button group | Native `<input type="radio">` inside the label (present) + the Home/End handler (`AxisMark.jsx:49-55`) | 03.3.1 Pitfall 5; arrow keys, Space, one tab stop and checked-first landing are native |

## Common Pitfalls

### Pitfall 1: Changing a picked-state rule without its test pin
**What goes wrong:** `binder.test.js:191-207` enumerates the exact underline selectors (`.axis-mark__stop:has(...)`, `.segmented__option ... ~ span`, `.chip-toggle[aria-pressed='true']`); `:43-52` counts rules reading `--focus-outline-width` (exactly two); `:248-264` and `cross-cutting.test.js:119-121` count `@media` blocks (exactly two, at two named conditions); `cross-cutting.test.js:56-95` enumerates the 759.98 block's selectors. Any of Plans 1–3 goes red on the first `npm --prefix app test`.
**How to avoid:** every CSS task lists its pin updates in the same task; the underline list shrinks to `a`, `a:visited`, `.text-control` (+ hover) only; the outline-count pin grows to three with the focus-on-box rule named as the exception; the `@media` list becomes `(max-width: 1099.98px)`, `(max-width: 759.98px)`, `(max-width: 600px)`, `(forced-colors: active)`.
**Warning signs:** a test named "exactly two" or "the only …".

### Pitfall 2: `:has(input:checked)` fill without `z-index` on the segmented option
**What goes wrong:** the picked option's pen-blue border is hidden under its right neighbour's ink hairline (the `-1px` overlap, `app.css:1696`).
**How to avoid:** keep `position: relative; z-index: 1` on the picked option (sketch 49; the app already has it at `:1726`).

### Pitfall 3: The global `button:hover` rule on chips
**What goes wrong:** D-06 says chips get no hover; `app.css:44-48` thickens every `button`'s border on hover with compensating padding.
**How to avoid:** `.chip-toggle, .chip-toggle:hover { border-width: var(--rule-ink-field); padding: var(--chip-pad-y) var(--chip-pad-x) }` — and check `binder.test.js:111-130` still passes (it reads the bare `button, select` rules only).

### Pitfall 4: `field-sizing: content` + `width: 100%` textareas inside a flex row
**What goes wrong:** a prose field in a `.field-row` shrinks to content. The sketch keeps textareas *outside* `.field-row` (234–235, 258, 298).
**How to avoid:** only the date/numeric fields and the melt category move into field rows; textareas keep `.batch-margin__field`.

### Pitfall 5: Container query vs viewport query for the version row
**What goes wrong:** copying 003:71 `@container` verbatim adds an at-rule type `css-source.js` cannot read and the pin suites reject; and the app's band has no `container-type`.
**How to avoid:** D-15's 760px viewport rule inside the existing 759.98 block.

### Pitfall 6: Reasoning about wraps from CSS
**What goes wrong:** two spacing bugs in 03.3.1 were only visible in the DOM (CONTEXT § Established Patterns; sketch README "Caption-to-content spacing unified"). Item 2's wrap analysis above is *reasoned*, not measured.
**How to avoid:** the pass records `getClientRects().length` for every `.lbl` at every width; a value > 1 is a gap row.

### Pitfall 7: The 393 table
**What goes wrong:** with a batch in view the ingredient table shows three numeric columns + Data = 368px of sized columns (`tokens.css:152-167`) in a 353px content width (393 − 2×20); `table-layout: fixed; width: 100%` cannot shrink a sized column, so the table overflows the region and `document.scrollWidth > innerWidth` — D-15's acceptance fails for a reason sketch 003 never drew (it was tested at 834/1024, `page-shell-front-matter.md` line 24).

### Pitfall 8: Two "Add tasting" buttons, one "Restore tasting", and the focus refs
