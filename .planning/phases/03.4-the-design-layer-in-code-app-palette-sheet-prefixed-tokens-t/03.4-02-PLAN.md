<decisions_recorded>
1. **`font-display: swap`** (RESEARCH.md open question 3, left to the planner). The maker's own words must never be invisible while a face loads; the text face shows first and the hand swaps in. `optional` would silently drop the hand on a cold load, and `block` hides the words.
2. **The face is vendored, not installed from npm.** D-17 says "ships in the repo as one file... with the SIL Open Font License beside it"; `@fontsource/caveat` would add a dependency the decision does not ask for and would need the package-legitimacy gate. No npm package is added by this phase, so that gate has no subject.
3. **The role class is `.app-hand`, and its base rule lives in app.css.** The two fallbacks have to live in app.css — it is the only stylesheet carrying the `forced-colors` and `print` blocks, and no new block may be opened — so the base rule sits beside them rather than being split across two files.
4. **The role enforces its own floor**: the font size is the larger of the hand size and the hand minimum, so `--size-hand-min` is a live guard rather than a token nothing reads (DESIGN.md: "Never below 1.25rem, because a script face loses its letterforms before a text face does").
5. **This plan writes no DESIGN.md edit.** D-17 says the Hand entry leaves *pending* once the tokens exist and the fallback is verified in both modes; DESIGN.md is Impeccable's file (`/impeccable document`), and the two-mode visual confirmation is an end-of-phase UAT item recorded in plan 04.
</decisions_recorded>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party font distribution -> repository | A binary font file enters the repository from outside and is served to every visitor from the app's own origin |
| app origin -> browser font loader | The face is fetched from the bundle's own origin only; no third-party origin is contacted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.4-04 | Tampering | the vendored woff2 binary | medium | mitigate | the file is taken from the font's own public distribution, its licence text is committed verbatim beside it, and fonts.css's header records the source URL, the retrieval date and the file's sha256, so a later swap is visible in review |
| T-03.4-05 | Information Disclosure | font loading | high | mitigate | no CDN or `@import` reference exists anywhere; the face is served from the app's own origin, so no third party learns a visitor's IP or user agent (TRUST-01, IMP-01: no external calls without a stated policy) |
| T-03.4-06 | Denial of Service (usability) | text invisible while the face loads | low | mitigate | `font-display: swap` guarantees the words render in the text face immediately; the forced-colours and print fallbacks cover the two modes where the face cannot render at all |
| T-03.4-SC | Tampering | package installs | low | accept | no npm, pip or cargo install occurs in this phase — RESEARCH.md's Package Legitimacy Audit records "not applicable, no external packages installed"; if a future change swaps the vendored file for an npm package, that package must go through the legitimacy gate first |
</threat_model>
