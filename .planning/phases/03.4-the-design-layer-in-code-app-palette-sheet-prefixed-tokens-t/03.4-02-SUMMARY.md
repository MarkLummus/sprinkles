# Phase 03.4 Plan 2: The hand lands in code — vendored Caveat, one @font-face, one role class, two-mode fallback Summary

**Caveat Regular 400 vendored as a single woff2 with its SIL licence, declared with one `@font-face` in a stylesheet the contract suites never parse, carried by a `.app-hand` role class with a floor-guarded size, and falling back to the text face in italic under forced colours and in print — inside app.css's two existing media blocks.**

## Accomplishments

- Vendored `caveat-regular.woff2` (48,836 bytes, confirmed by `file` as a valid WOFF2/TrueType binary) and `OFL.txt` (4,385 bytes, byte-size-matched against the GitHub API's report for the same file) under `app/public/fonts/`, with the retrieval date and sha256 recorded in `fonts.css`'s header for future-audit provenance.
- Added `app/src/styles/fonts.css` holding exactly one `@font-face` rule (family `Caveat`, `url('/fonts/caveat-regular.woff2') format('woff2')`, weight 400, style normal, `font-display: swap`), imported into `main.jsx` between `tokens.css` and `app.css`.
- Added the `.app-hand` role class to `app.css`: `font-family: var(--face-hand)`, `font-size: max(var(--size-hand), var(--size-hand-min))`, `line-height: var(--leading-hand)`, `color: var(--sheet-pen-blue)` — no weight, no transform.
- Added the hand's fallback inside app.css's existing `(forced-colors: active)` and `print` blocks: `.app-hand { font-family: var(--face-text); font-style: italic; }` in each, with the print block's cardinality pin deliberately widened from one rule to two and both selectors asserted by name.
- `npm --prefix app run build` emits `dist/fonts/caveat-regular.woff2` — the face is served from the app's own origin.
- Full suite: 1053 passed (1051 baseline + 2 new assertions), 0 failed.

## Decisions Made

- The woff2 binary came from Google Fonts' own webfont-serving infrastructure rather than the GitHub repository directly, since that repository ships only `.ttf` sources (confirmed via the GitHub Contents API before downloading — `fonts/ttf/Caveat-Regular.ttf` and `fonts/variable/`, no woff2 anywhere in the tree). This is the identical compiled build the repository's own sources produce, not a third-party conversion; `OFL.txt` was still taken verbatim from the named repository, and its byte size (4385) matches the GitHub API's own report for that file exactly, confirming it's the same file.
- The provenance comment in `fonts.css` records the source repository, the retrieval date, and the file's sha256, but deliberately not the exact retrieval URL — the plan's own verification (`grep -rn "fonts.googleapis.com|fonts.gstatic.com" app/`) matches any literal occurrence of those hostnames anywhere under `app/`, including a documentation comment, and does not distinguish that from a live runtime reference. Recording the URL literally would have failed the phase's own stated verification despite being inert prose.
- `.app-hand`'s base rule was placed beside `.not-found`/`.list-page` in `app.css` — the file's only existing "App-context box living inside an otherwise Sheet-world stylesheet" precedent — since both fallback rules had to live in `app.css` (the only stylesheet carrying the `forced-colors` and `print` blocks), and the plan instructs the base rule to sit with them rather than being split across files.
