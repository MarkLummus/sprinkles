# Phase 03.4 Plan 3: The shell — layout route, rail, brand mark, tools row, and the bottom tab row Summary

**A react-router layout route (Shell.jsx) now wraps every route in a wordmark-and-tools-row header plus a 224px destination rail that becomes a five-tab bottom bar with a More disclosure below 759.98px, with Import/Export relocated onto it and six new placeholder routes for the App's unbuilt destinations.**

## Accomplishments

- `Shell.jsx` (new): a layout route rendering a header (wordmark, a five-sprinkle brand mark in navigation order, a Search/Import/Export tools row) and a body split into a 224px `.shell__rail` (Home, a divider, Notebook/Recipe book/Idea log, a divider, Ingredients/Kitchen) and `.shell__main` holding `<Outlet context={storeRevision} />`. Every rail/tab item is a `NavLink` carrying its own `shell__place--{slug}` modifier class, so `aria-current="page"` and the active place's subtle-surface background come from the router's own match, never hand-written state.
- `router.jsx` nests the three existing routes (`/`, `/recipe/:id`, `/recipe/:id/batch/:batchId`) plus six new placeholder routes (`/notebook`, `/recipe-book`, `/idea-log`, `/ingredients`, `/kitchen`, `/search`) under the new `Shell` layout route, using react-router 8.3.1's `Component`/`children` route-object shape.
- `Placeholder.jsx` (new): the place's name as an `h1.place__title`, one sentence (`.place__note`) saying it is not built yet, nothing else — reusing the existing `.list-page` page-gutter wrapper.
- Import and Export moved verbatim (same object-URL/anchor-click export, same JSON-parse-with-two-error-paths import) from `RecipeList.jsx` into `Shell.jsx`'s tools row and the bottom tab row's More disclosure, sharing one hidden file input. A successful import increments a `storeRevision` counter passed down as the `Outlet`'s context value; `RecipeList.jsx` now reads it via `useOutletContext()` and adds it to its data-loading effect's dependency array, so Home reloads without a page reload.
- Below the existing `(max-width: 759.98px)` step, `.shell__rail` hides and `.shell__tabs` (five tabs: Home, Notebook, Recipe book, Idea log, and a `<details>` More disclosure holding Ingredients, Kitchen, Search, Import, Export) shows fixed to the bottom edge; `.shell__main` gains a bottom padding equal to the new `--app-size-tab-h` token so the fixed row never covers the end of a page.
- Three new tokens under the App block of `tokens.css`: `--app-size-nav-w` (224px, D-09), `--app-size-icon` (20px), `--app-tilt-sprinkle` (-8deg), and `--app-size-tab-h` (56px).
- `shell.css` (new) and `shell.test.js` (new): the shell's own stylesheet and contract suite, scoped to `.shell`/`.place`, with a containing-block guard (`.shell`, `.shell__body`, `.shell__main` declare none of `transform`, `filter`, `perspective`, `will-change`, `contain`) proving the shell cannot silently intercept the recipe route's absolutely positioned page notice.
- Home's header, brand gradient, nav, actions, filled/quiet actions, file input and import-error markup and rules are gone from `RecipeList.jsx`/`home.css` — the shell owns all of it now.
