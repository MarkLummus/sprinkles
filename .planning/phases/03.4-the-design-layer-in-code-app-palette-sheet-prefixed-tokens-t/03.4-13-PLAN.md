<decisions_recorded>
1. **The smaller move only.** The debug session's first recommendation — a linked or inlined critical stylesheet and minimal shell markup in index.html — is a structural change to how this app boots, and Mark scoped it out of this closure. It is recorded as a follow-up. What this plan takes is the part that needs no structural decision: get IndexedDB off the first-paint path and give both waits something to show.
2. **Two-phase render, not a concurrent seed.** `main.jsx` creates the root and renders a boot line BEFORE awaiting the seed, then renders the app once the store is ready. The alternative — mounting the real shell immediately and letting the seed finish underneath it — was rejected: the seed's write transaction is only created after its own read resolves, so Home's own read can win the race and render the empty shelf on a first run, and any fix for that (a shared ready promise consumed by every route, or a Suspense boundary) is a structural change this closure is not making. With the two-phase render the guarantee `main.jsx` has today is unchanged: no route mounts against an unseeded store.
3. **The boot line is a role class in app.css, not a component.** `.app-boot` follows `.app-hand`'s precedent from plan 02 — an App role class in the shared stylesheet — and reads the grotesk, the meta size, the secondary text colour and the page gutter from existing tokens. It renders outside `.shell`, so the ground it sits on is `body`'s, which plan 09 makes the App's white.
4. **The failure path becomes a rendered state.** `main.jsx` today writes `textContent` into the root element and throws. Once a React root owns that element, writing to it directly is fighting React, so the same message renders through the same root and the throw stays.
5. **Home's loading state renders inside the existing wrapper.** cross-cutting.test.js counts exactly one `className="list-page"` in RecipeList.jsx (it is the guard against a shipped rule with no renderer), so the early `return null` becomes a branch INSIDE the existing return, not a second wrapper. The title stays put across both states, so the page does not jump when the data lands.
6. **The standing rule goes in `.claude/CLAUDE.md`'s conventions.** That is where this project's other "always do it this way" lines live and where an agent reads them. The block is inside GSD's generated markers with `source:CONVENTIONS.md`, and no such file exists today; if codebase mapping ever runs, this line has to be carried into it. Noted so it is not lost.
</decisions_recorded>
