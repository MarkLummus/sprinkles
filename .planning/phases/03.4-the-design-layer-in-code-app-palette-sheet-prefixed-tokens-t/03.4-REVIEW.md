### IN-01: Two near-duplicate source-reading blocks in RecipePage.test.jsx

**File:** `app/src/ui/RecipePage.test.jsx:743-751` and `:780-788`
**Issue:** The pre-existing `describe('the running head is owned by the routed shell...')` block and the new `describe('the running head and the not-found link carry an explicit tabindex...')` block both independently `readFileSync` and comment-strip the same two files (`router.jsx`, `RecipePage.jsx`) into effectively identical local constants (`routerSource`/`routerSourceForTabIndex`, etc.). The new block's own comment explains this is deliberate ("Declares its own reads — the block above's constants are scoped inside its own callback"), which is a reasonable call given each `describe` scopes its own `const`s and Vitest doesn't share `describe`-level bindings across blocks without a shared helper. This is not a defect — both blocks pass and the duplication is small and localized — but a shared module-level helper (e.g. a `readStripped(path)` function used by both) would remove the repetition if this pattern grows a third callsite.
**Fix:** Optional: factor the `fileURLToPath` + `readFileSync` + comment-strip sequence into one small helper shared by both `describe` blocks, next time either is touched. Not worth a standalone change for two occurrences.
