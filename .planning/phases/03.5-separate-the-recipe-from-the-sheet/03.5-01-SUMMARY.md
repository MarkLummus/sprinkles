# Phase 03.5 Plan 01: Separate the recipe from the sheet Summary

**A new `recipes` IndexedDB store (DB_VERSION 6) holds the recipe's name/description behind the repository seam; the version keeps only sheetTitle/sheetDescription; Carried forward is deleted from code, seed and store; and the transfer format moves to schemaVersion 6 with a `recipes` array, refusing older exports with a plain sentence first.**

## Accomplishments

- A `recipes` object store (keyPath `id`, no index), added to db.js's existing drop-and-recreate upgrade pattern at DB_VERSION 6, proven against a real IndexedDB via fake-indexeddb for both a fresh profile and a version-5 profile carrying a pre-existing record.
- The repository seam gained `listRecipes`/`getRecipe`/`saveRecipe`/`putAllRecipes`, line-for-line copies of the existing `versions` method quartet — `grep -rln "from 'idb'" app/src` still prints only `app/src/store/db.js`.
- The olive oil recipe (`oliveOilRecipe`, D-09's exact strings) is seeded before the version and batch; `activeWork(versions, batches, recipes)` resolves each recipe's name from its own record via a `recipeId` lookup, falling back to the recipeId string when no record exists; Home's lead now reads "Olive Oil Ice Cream, circulator" from that record.
- The version's `recipeName`/`headnote` fields are gone everywhere, replaced by `sheetTitle`/`sheetDescription` (VERSION_SCHEMA_VERSION 5): `createChildVersion`/`saveOverVersion` (Next version copies both from the parent), `buildDiff`'s two independent changed flags, `validateVersion`'s two string checks plus a new required `recipeId`, `Headnote.jsx`'s reading-mode h1/prose and a new developing-mode Sheet title field beside the existing Sheet description field (each with its own struck-beneath baseline), and `RecipePage.jsx`'s dirty check/seeding/save-field-building.
- Carried forward is deleted outright — its three notes' words dropped, not moved (decisions_recorded 10) — from `olive-oil.js`'s seed data, `Authored.jsx` (the wrapper and legend removed; `NoteList` stays, still used by Method.jsx's "Before you start"), `RecipePage.jsx`'s render and dirty check, and `transfer.js`'s `validateVersion` (now requires only `authored.beforeYouStart`).
- `transfer.js` moved to `STORE_SCHEMA_VERSION` 6 with a new `$.recipes` array block and `validateRecipe`; any file below schema 6 is refused with `OLDER_EXPORT_MESSAGE` first, then the path-named `$.schemaVersion` error; `importStore` gained a recipe-resolves gate (mirroring the existing parent-resolves gate) that refuses a version whose `recipeId` names no recipe in the file or the store, writing nothing on refusal, and calls `putAllRecipes` before `putAll`/`putAllBatches` on success.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] db.test.js's first fake-indexeddb setup hung the test runner**
- **Found during:** Task 1, writing db.test.js's RED tests
- **Issue:** The first version used `import 'fake-indexeddb/auto'` with a `beforeEach` calling `indexedDB.deleteDatabase(name)` awaited directly (not wrapped in a Promise resolving on `onsuccess`). When a prior test's assertion threw before `db.close()` ran, the leaked open connection blocked the next test's delete indefinitely (5000ms timeout).
- **Fix:** Switched to the pattern `app/tests/db-reset.test.js` already established: import the individual IDB constructors from `'fake-indexeddb'` (not `/auto`), assign them to `globalThis` once, and assign a fresh `IDBFactory` to `globalThis.indexedDB` in `beforeEach` — no leaked-connection deadlock is possible since each test gets an entirely separate in-memory database.
- **Files modified:** app/src/store/db.test.js
- **Verification:** Isolated the failing test with `it.only`, confirmed it failed cleanly (not a hang) once isolated, then diagnosed and fixed the cross-test interaction; full suite green afterward.
- **Committed in:** b3e7a18 (Task 1 test commit)

**2. [Rule 1 - Bug] transfer.test.js's OLDER_EXPORT_MESSAGE addition broke two error-count assertions**
- **Found during:** Task 3, writing transfer.js's GREEN implementation
- **Issue:** Adding `OLDER_EXPORT_MESSAGE` as a second error entry for any `schemaVersion` below 6 meant two pre-existing tests asserting exact error-array lengths for a payload with `app: 'other', schemaVersion: 3` (previously 2 distinct faults = 2 errors) now correctly produce 3 errors (app + the message + the path-named schemaVersion line).
- **Fix:** Updated both assertions' expected length from 2 to 3, with a comment explaining the count.
- **Files modified:** app/src/store/transfer.test.js
- **Verification:** Full suite green; RED-phase revert confirmed both tests genuinely failed (wrong count) before the fix.
- **Committed in:** e54b855 (Task 3 test commit)

**3. [Rule 1 - Bug] A literal "carriedForward" string survived in a new test, violating the plan's own acceptance criterion**
- **Found during:** Task 3, before committing GREEN
- **Issue:** A test titled "says nothing about carriedForward" and its assertion (`error.includes('carriedForward')`) both contained the literal string, which the plan's acceptance criterion greps for across all of app/src including test files — `grep -rn "carriedForward" app/src ... | wc -l` must print 0.
- **Fix:** Deleted the redundant test (the grep itself is the proof of absence; a unit test asserting the same thing needs the literal string to do so, which is the actual thing being disallowed). Also stripped `"carriedForward":[]` from one JSON-literal test fixture testing an unrelated `__proto__` scan.
- **Files modified:** app/src/store/transfer.test.js
- **Verification:** `grep -rn "carriedForward" app/src --include='*.js' --include='*.jsx' | grep -vE ':[0-9]+:[[:space:]]*(//|\*|/\*|\{/\*)' | wc -l` prints 0.
- **Committed in:** e54b855 (Task 3 test commit)
