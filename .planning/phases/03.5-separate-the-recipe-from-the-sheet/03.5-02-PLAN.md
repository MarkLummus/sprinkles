<decisions_recorded>
1. **Component redirects, not loaders** (RESEARCH.md Assumption A1's fallback, taken deliberately). createBrowserRouter runs when router.jsx is imported, which is before main.jsx awaits seedIfEmpty. A loader on a first visit after the D-10 reset could read an empty store and report not-found for a real recipe. A component renders only after the seed resolves. Both redirects call navigate(path, { replace: true }), which satisfies D-14's replace-redirect.
2. **Pure path functions, thin components.** The node test harness cannot run effects or import router.jsx (RecipePage.test.jsx records why). So every decision a redirect makes lives in notebookPaths.js and is unit-tested; the components only fetch, call, and navigate.
3. **A recipeId that does not match the version's own is not found.** /notebook/wrong/olive-oil-ice-cream-v1 renders RecipeNotFound rather than a recipe under a wrong address.
4. **The link list is grepped, not trusted.** D-17 names nine sites; research found RecipeList.jsx holds four, not one, and two navigate calls sit in RecipePage.jsx. The acceptance gate is a comment-filtered grep for any remaining /recipe/ target, not a checklist.
5. **The cream-canvas selector changes in two steps.** This plan drops only the removed head from `body:has(...)`. The `.recipe-page` trigger stays until plan 04 puts the App band around the Sheet; dropping it now would paint the overscroll white under a page that is still cream edge to edge.
6. **The notice's new anchor.** A zero-height `.page-status-anchor` (position: relative) sits where the head was, above the keyed page and outside it, so the notice still survives the navigation a save causes. The notice keeps its look and its left inset, --gap-page, and overlays the top of the page as before. Plan 07's conformance pass may move its inset to the band's edge.
</decisions_recorded>
