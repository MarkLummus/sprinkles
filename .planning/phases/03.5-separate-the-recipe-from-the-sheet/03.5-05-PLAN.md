<decisions_recorded>
1. **Pure entries, thin component.** Every rule the rail follows lives in historyRail.js and is node-tested: order, mark state, words, the draft node and the hint. The rail's order and ordinals come from lineage.js's sortedVersions/versionIdentity and batch.js's sortedBatches. The component renders the entries and owns only scroll and fade, which no node test can reach and plan 08's browser check covers.
2. **State words for versions other than the one in view.** The boards draw the in-view state ('churned 2 Aug · Latest', 'not yet churned · Latest'), and 1600-long-history.html leaves the illustrative versions' state lines blank. This plan gives every version the same rule: 'churned <day month of its latest churn>' or 'not yet churned', plus '· Latest' on the latest. Flagged for plan 08's record.
3. **The in-view node is not a link.** The boards draw every node as `<a href="#">`. The app's standing convention is that the item you are on is not a link and carries aria-current, and every link is suppressed while a pen is open (D-UAT-2). Both are kept; the node looks the same either way.
4. **The draft node's date** is the day the pen opened, held in memory as penOpenedAt and never stored (D-13).
5. **Singular.** One version reads '1 version'.
</decisions_recorded>
