<decisions_recorded>
1. **The cut is 1366, and it is Mark's.** Decision 18 sets it: the open Balance column's minimum is 190, so the open state fits from the log's cut, 1366 = 224 + 3 × 32 + 696 + 350. Plan 12's decisions_recorded item 5 records "Desktop state from: 1366", written after its SUMMARY recorded option-measure. This plan builds plan 12's option-1366 Task 3, plus decision 18's folds at every width.
2. **A fold's default follows the width it is in.** `useFold(openByDefault)` starts at the width's default and goes back to it whenever that default changes, so an iPad rotation across 1366 resets the folds. The band rhythm, which CSS switches at the same cut, then never disagrees with the folds. A maker's own open or close lasts until the route changes (RecipePage is route-keyed) or the window crosses the cut. The boards draw only the two defaults, so plan 14 lists this for Mark.
3. **One fold head, FoldRow, drawn as gen.py's fold_row.** The markup is `button.fold-row[type=button][aria-expanded][aria-controls]`, holding `span.fold-row__head` (the label, then `span.fold-row__control` with "Show" or "Hide", plus " " and `what` when given), then `span.fold-row__count` as the last child when a count or date is given.
   - The class is `fold-row` only, not `text-control` or `history-disclosure`. That keeps the log's and version column's blue `.text-control` scopes and the touch union's `.text-control` rule off it. Its own rule carries fold_row's inline resets and a 44px minimum height at every pointer.
   - Its CSS sits in notebook.css under `.notebook`, since every fold head renders inside `.notebook`. It reads only existing tokens:
     - `--touch-min` (44);
     - `--app-notebook-recipe-rail-gap` (14);
     - `--app-notebook-link-underline-offset` (3);
     - `--face-grotesk`, `--sheet-type-control` and `--sheet-ink` for the Show/Hide word (the board's own face for it, "the app's text control");
     - `--app-size-label` and `--app-text-secondary` for the count.
4. **The Version caption moves into the fold row.** 1366-batch.html draws the version column's first child as the button: the caption, then "Hide details". The identity heading follows it, then the details list, then the acts.
5. **Show changes names the action by its state, and aria-pressed goes.** A toggle whose label changes must not also announce a pressed state (WAI-ARIA APG button pattern). Otherwise it would read as "Hide changes, pressed" and say the state twice. No board draws the control, because every board's Version 1 has no parent, so there is nothing to redraw first; plan 14 lists it as undrawn.
6. **Print is not in this gap.** Decision 18 says print still reads whole. Print belongs to Phase 4 (app.css's print block: "Phase 4 owns the print route … this must not pre-empt it"), and Mark's confirmed scope for this gap names no print work. This clause is carried to Phase 4.
</decisions_recorded>
