# Phase 03.5 Plan 16: Balance and Watch for fold apart; the Tasting head becomes one full-row control Summary

**Decision 18's split (Balance and Watch for each get their own full-row fold, "Watch for" replaces "Things to check") and decision 19's full-row Tasting head (Show/Hide beside the label, the tasted date at the row's end) — no fold on the recipe route is width-gated any more.**

## Accomplishments

- **Task 1 (tracer):** `RecipePage.jsx`'s Balance region now owns its own `useFold(!belowDesktop)` state (replacing the plain `useState`) and renders one branch at every width — `h2.region-name` holding `FoldRow(label 'Balance', controls 'fold-balance')`, then `div#fold-balance` (`hidden={!balanceOpen}`) wrapping `FormulationNote` and `BasisNote`. The old combined toggle (one `HistoryDisclosure` whose `aria-controls` named both `fold-balance` and `fold-check`, rendered only below desktop) and the duplicate at-desktop/below-desktop branches are gone. `margin-region` no longer carries a fold id or `hidden` of its own — `DerivedAdvisories` now owns that fold internally, reading a new `foldsOpen` prop (default `true`) through its own `useFold`. Its section now wraps `h2.region-name` holding `FoldRow(label 'Watch for', controls 'fold-check')`, then `div#fold-check` (`hidden={!open}`) around the unchanged advisory paragraphs — the old "Things to check"/"derived" legend paragraph is retired outright, along with its own CSS rule and the old Balance toggle's CSS rule and token (`--sheet-balance-fold-gap-b`). A live app-vs-board measurement confirmed the 32px gap above "Watch for" needs no replacement spacing — it already comes from `.side-region`'s own flex gap.
- **Task 2:** `BatchRow.jsx`'s `TastingReading` gets its state from `useFold(foldsOpen)` (the `foldable` prop, renamed `foldsOpen`, default `true`, threaded from `BatchRow`'s own renamed prop). Its head is now `h3.region-name` holding `FoldRow(label 'Tasting', controls 'fold-tasting', count: 'tasted <date>')` — the separate date paragraph is gone, its text now living in the fold row's own count slot at the row's right end (taking the count's smaller, secondary-coloured face). The body always sits in `div#fold-tasting` with `hidden={!open}`, so the fold exists at every width and only its default (open from 1366, closed below) changes. `RecipePage.jsx` passes `foldsOpen={!belowDesktop}` to `BatchRow`, the same prop `VersionRow` and `DerivedAdvisories` already read. The tasting head's own date rule and its now-unread `--app-notebook-log-tasted-size` token were retired.
- **03.5-band-probe.mjs**: the `folds` group generalized from checking `fold-version` alone to every id in `EXPECTED_FOLDS` (now `fold-version`, `fold-balance`, `fold-check`, `fold-tasting`). `readFoldGeometry` gained fields for a fold whose label is bare text (reading the button's own inherited `font-size`/`color`/`text-transform`, since `FoldRow`'s CSS carries the ancestor heading's face straight onto the button) and for a fold whose `FoldRow` carries a `count` (read structurally as the button's second `<span>` child, since the board's own count span carries no class attribute). The board-state and board-comparison loops now iterate every `EXPECTED_FOLDS` id against both `1366-batch.html` (open) and `1024-batch.html` (closed).
