<decisions_recorded>
1. **Drawn width = the board's own `$preview.width`.** gen.py's board() writes `data-props='{"$preview":{"width":W,"height":H}}'` on every board, including the multi-panel count boards (1174 to 1884 wide) and details-fold.html (1040). The harness reads it from the file on disk before opening, resolving `file` against `.planning/sketches/011-recipe-route-c/` exactly as the URL does, so `../011-options-counts/x.html` works. It fails with a message naming the file if the value is absent.
2. **Pointer = coarse exactly when the file name carries 393.** Those boards are drawn for the iPhone, and 393-batch.html carries the touch floor. Every other board draws fine-pointer sizes (README "How the boards are made": "the touch floor only on the 393 board"). A coarse board context mirrors openApp: hasTouch, isMobile, deviceScaleFactor 3, and the same matchMedia assertion.
3. **Callers change nothing.** The defaults carry the rule, and an explicit `{ width, coarse }` still overrides for a caller that needs it. Viewport height stays 1100, as in openApp.
4. **The count boards open at their page width, not at 393.** Their panels carry their own fixed widths inline, so the panel is drawn at 393 whatever the page width. Only the pointer follows the 393 name.
</decisions_recorded>
