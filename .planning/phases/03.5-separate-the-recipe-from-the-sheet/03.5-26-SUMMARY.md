# Phase 03.5 Plan 26: sortedBatches stands a batch at the day it was made Summary

**sortedBatches now stands each batch at its churn date or, with none, the UTC day it was recorded, so Mexican Chocolate's later-recorded undated v3 outranks its older churned v1 and Home reads Awaiting tasting.**

## Performance

- **Duration:** about 12 min (start time was not captured at spawn; estimated from the commit stamps)
- **Completed:** 2026-10-01T05:02Z
- **Tasks:** 2 (a tracer and an auto task, both tdd)
- **Files modified:** 5 (4 modified, 1 created)

## Accomplishments

- **The rule as built (decisions_recorded 1).** Every batch has a standing day: its churn date when it has one, otherwise the first ten characters of its recordedAt when that is a string (the UTC calendar day it was recorded), otherwise none. The later standing day comes first and a batch with no standing day comes last. Two batches on the same standing day order by recordedAt descending, a missing or non-string recordedAt last, and a full tie returns 0 so equal batches keep their input order. The signature is unchanged and the function still returns a new array.
- Mexican Chocolate's undated, untasted v3 batch (recorded 2026-01-13) outranks its churned, tasted v1 (2025-12-13), through a real fake-indexeddb round trip and on the built app.
- A built-app probe, `03.5-standing-probe.mjs`, reads Home's standing word for every seeded recipe and checks six named recipes plus the three reachable standings.
- The doc comment on `sortedBatches` and the one stale comment in `RecipePage.jsx` now state the rule instead of "undated last".
