<decisions_recorded>
1. **The count is a pure function of the count.** `railHint(count, { open, upright, overflowing })` becomes `versionCountWords(count)`: "1 version" for one, "N versions" otherwise, with no state argument. The History fold only renders from two entries, so the singular is never shown, and it stays only because the function is general. The Batches count is the plain template of its own length, since the list only renders from two batches.
2. **What the overflow code did, and what stays.** RecipeHistory's `overflowing` state, its `measureOverflow` function and the window resize listener fed only the removed clause. The effect's other two jobs stay: set the rail's own scrollLeft so the version in view is visible (never scrollIntoView), and set `scrolledLeft` for the fade. The effect still re-runs when the version in view, the entry count, `open` or `belowDesktop` change.
3. **Tests that pinned a hint.** BatchRow.test.jsx (the open fold's count test, which also keeps its closed counterpart), FoldRow.test.jsx (a fixture count, so the accessible-name test reads "Batches, Hide, 3 batches"), historyRail.test.js (the hint's five cases become the count's), RecipeHistory.test.jsx (the open horizontal case). The debug file lists the lines.
4. **Probes that pinned a hint.** The band probe's `history` group (two `countText` endsWith checks) and, for the Batches count, the batches probe's `many` group (a substring check on the whole button text, which cannot see a clause). Both gain a board reading, so the app and the redrawn boards are compared directly.
</decisions_recorded>
