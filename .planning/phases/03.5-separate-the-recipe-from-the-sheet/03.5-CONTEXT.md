<domain>
## Phase Boundary

The Notebook recipe route shows the recipe record apart from the version's Recipe Sheet — visually, in the store, and in its routes — as D17, DESIGN.md's Context Boundary Rule and `.impeccable/surfaces/route-recipe.md` § "03.5 revision" define them, built to layout C as drawn in `.planning/sketches/011-recipe-route-c/` (the acceptance target). The store gains a recipe record; `recipeName`/`headnote` leave the version and `sheetTitle`/`sheetDescription` arrive; Rename edits the recipe record; routes move to `/notebook/:recipeId/:versionId[/batch/:batchId]`; `carriedForward` is removed; and the seed grows to several real recipes transcribed from Mark's binder.

Out: the Recipe Book form and route (reserved only), print (Phase 4), Adapt, Recipe Book selection, reordered and new steps in a batch (Phase 5), phone logging (deferred to the phone-jobs brief), persisted drafts (edit recovery is Phase 4, UX1-03).

**Already settled before this discussion — do not re-open** (source: `route-recipe.md` § "03.5 revision" parts 2–7 and sketch 011 README § Decisions 1–14): layout C and the ladder (1600 / 1366 / 1024 / 393); Sheet table style 6 and the "estimated" chip; the hand (Caveat, pen blue, 20px min) for every batch edit on the Sheet; History as a dated rail, versions only; the pen opens from Next version with the ceremony in the band, steps edit one at a time via "edit this step" with Cancel then Done on the open step; "change the ingredients" on the step's uses control; folds below desktop (Details, Balance + Things to check, Tasting) closed on every visit with no stored state; "Rename" label; destination caption dropped; Carried forward dropped from code, seed, store and transfer; Instructions is a screen-only rename (code keeps `method`); Next version copies Sheet title and Sheet description.

## Implementation Decisions

### Seed content
- **D-01:** Mexican Chocolate is seeded as **v1, v3, v4** under its real version names. v3's parent is v1. No v2 is made up: it is missing from the binder and from disk, and History shows the gap as it is.
  - **Amended 2026-09-25 (Mark, quick 260925-kix):** v2 exists after all — `~/Documents/Mexican Chocolate v2-2.ier` (Ice Ed export, saved 2026-01-11) — and is seeded as v2 with parent v1; v3's parent is v2; the chain is v1 → v2 → v3 → v4 and History shows four versions. Nothing is made up: v2 carries no batch and no tasting, and its carried-forward Notes become no note, reason or tasting.
- **D-02:** Sources. v1 comes from `Ice Cream Log Pages/IMG_2453.HEIC` and `~/Desktop/Ice Cream/Mexican Chocolate v1.ier`. v3 comes from `Ice Cream Log Pages/IMG_2454.HEIC`. v4 comes from `~/Downloads/recipe-Mexican Chocolate v4.json` (Ice Ed export). The binder audit (`Ice Cream Log Pages/sprinkles-churn-log-binder-audit.md` §§ 1–2) already transcribes and flags these pages: v1 is a "Double Recipe" and its 75C was overwritten to 176F; v3's "Observations" are v1's retyped and must not become a v3 result.
- **D-03:** Ingredients the library lacks (cocoa powder, cinnamon, vanilla extract, fructose, Stabilizer Mix 4421) take their coefficients **from the Ice Ed JSON as-is**, with basis recorded as Ice Ed and missing fields left missing.
- **D-04:** "Whole Milk 3.3%" becomes **its own library entry**, separate from "Whole milk, 3.5% fat".
- **D-05:** The other recipes are **2–3 from the binder photos** (`Ice Cream Log Pages/IMG_2455`–`IMG_2481`), including at least one single-version recipe. Across all recipes the seed covers the states churned, not yet churned and not yet tasted.
  - **Amended 2026-09-25 (Mark, quick 260925-lpd):** four more recipes join the transcribed seed — Standard Base (v1, v2, from Ice Ed exports) and Underbelly Light Base (v1 from `~/Desktop/Ice Cream/Ice Cream Comparisons.xlsx`, v2 from its Ice Ed export), both bases; Strawberry (V1, V2, V2.1) and Mocha (v0-v3) from Ice Ed exports, binder photos IMG_2455-2457 and IMG_2464-2466 and the comparisons workbook — Mocha v2's rows from its printed page. Batches and tastings only where a photo or the workbook supports them. Seven dates are ordering placeholders until Mark supplies them; Pineapple's and Coconut's placeholder dates become their .ier save times.
- **D-06:** Which versions get batch records, and what those batches hold, is **for the transcriber to decide from the sources**. Record only what a source supports, leave missing values missing, and never invent a result. Mark reviews it (D-07).
- **D-07:** Transcription review is a **blocking checkpoint** before the seed is wired in. The executor writes the data files plus a side-by-side review document (source image or file → transcribed fields, every judgement call flagged), and execution stops until Mark approves.
- **D-08:** Source fields the app model doesn't hold (Type, serving temp, hardness, overrun, kcal, PAC/POD targets, error flags, and so on) go into a **sidecar transcription file outside the app**, not into the store. The schema does not grow for the seed's sake.
- **D-09:** Olive oil is seeded **as the boards draw it**: Recipe name "Olive Oil Ice Cream, circulator"; Recipe description = today's headnote text ("Scaled 0.8× from the 1 kg formula…"); Sheet title "Olive Oil Ice Cream"; Sheet description "Silky and quietly savoury…", exactly as on `1600-batch.html`.

### Store and rename
- **D-10:** The store **resets rather than migrates**. The DB version is bumped, the upgrade drops and recreates the stores and reseeds, and import accepts only the new export shape, refusing older exports with a clear message. Mark confirmed there is no real data to keep. — **Reversibility:** one-way — any records in a browser profile are wiped on upgrade, and exports made before 03.5 can no longer be imported.
- **D-11:** A new recipe record `{ id, name, description }` is reached only through the repository seam. Nothing else is stored for the Recipe Book (no `selectedVersionId`).
- **D-12:** **Rename** opens Recipe name and Recipe description as fields **inline in the band**, with Cancel first and then Save. Save writes the recipe record at once: no version, no Why, no fork, and no saved Sheet is touched. It works whether or not the pen is open.
- **D-13:** Drafts stay **in memory only**, as today. The History rail shows the draft node only while the pen is open. The 1600-batch board's closed-pen draft node is not built in 03.5; persisting drafts belongs to edit recovery (Phase 4, UX1-03).

### Routes and entry
- **D-14:** `/notebook/:recipeId` with no version **replace-redirects to the latest version**.
- **D-15:** `/notebook` itself **keeps its placeholder**. The Notebook nav item still marks active on every `/notebook/…` route.
- **D-16:** The `/recipe/:id` and `/recipe/:id/batch/:batchId` redirects (old ids are version ids) are **kept indefinitely**.
- **D-17:** Every in-app link and navigation to a recipe moves to the `/notebook/…` form. Today's sites: `VersionRow.jsx:225,248`, `RecipePage.jsx:1409,1725`, `BatchRow.jsx:347`, `RecipeHistory.jsx:81,125,137`, `RecipeList.jsx:110`. Each keeps `tabIndex={0}`, following the project convention.

### Recipe Book band
- **D-18:** The principle is settled now and the drawing deferred. The Recipe Book shows **one selected version only: no version selection, no Next version, no History**, and its band carries the Recipe name. The sketch 011 README and `route-recipe.md` § "03.5 revision" are amended to say so; the reference board itself is redrawn in the phase that builds the form. The route stays reserved, not built.

### Design record
- **D-19:** The approved bend to DESIGN.md's Hand Rule is recorded in this phase: batch edits on the Sheet, including weighed as-made grams, are written in the hand, where the old rule set them in type. DESIGN.md is changed through Impeccable (`/impeccable document`), not by a GSD executor editing it freehand.

## Specific Ideas

- Mexican Chocolate v1 was a "Double Recipe", so the batch mass is twice the printed table. Its sous vide target was overwritten from 75C to 176F (= 80 °C). Record this as the source shows it and flag it at review.
- v3's populated "Observations" are stale v1 text. Do not turn them into a v3 tasting.
- v4's Ice Ed Notes field mixes process ("Sous Vide for 60 minutes @ 75C") with observations and next-time deltas. Split it only where the model has a home for each part; the rest goes to the sidecar (D-08).
