### `app/src/ui/useBelowDesktop.js` — the App-context matchMedia hooks

**Analog:** its own two existing query/hook pairs — this is the pattern to extend or edit, not replace.

**Current state** (full file, 49 lines, read this session):
```js
export const BELOW_DESKTOP_QUERY = '(max-width: 1499.98px)';
export function useBelowDesktop() {
  const hasMatchMedia = typeof window !== 'undefined' && typeof window.matchMedia === 'function';
  const [below, setBelow] = useState(() => (hasMatchMedia ? window.matchMedia(BELOW_DESKTOP_QUERY).matches : false));
  useEffect(() => {
    if (!hasMatchMedia) return undefined;
    const mediaQuery = window.matchMedia(BELOW_DESKTOP_QUERY);
    const onChange = (event) => setBelow(event.matches);
    mediaQuery.addEventListener('change', onChange);
    return () => mediaQuery.removeEventListener('change', onChange);
  }, [hasMatchMedia]);
  return below;
}

export const LOG_BESIDE_SHEET_QUERY = '(min-width: 1100px)';
export function useLogBesideSheet() { /* identical shape, different query */ }
```

**Node-guard pattern (critical, must be preserved verbatim in any new/edited hook):** both hooks guard with `typeof window !== 'undefined' && typeof window.matchMedia === 'function'` before touching `window` at all, because `RecipeHistory.test.jsx`/other static-markup tests render under Vitest's `node` environment with no `window`. Any edit to these queries — or a new third hook, if the band-stack or rail/tab-row cut needs one in JS rather than pure CSS — **must copy this guard exactly**, per this file's own header comment (lines 3-11) and `BatchRow.jsx`'s matching comment at lines 115-123.

**What changes:** `LOG_BESIDE_SHEET_QUERY` moves from `'(min-width: 1100px)'` to `'(min-width: 1366px)'` (log-beside now starts at 1366, not 1100/1099.98). `BELOW_DESKTOP_QUERY` at `'(max-width: 1499.98px)'` — decide against decision 16's actual top rung: if "desktop" (folds open, Sheet reads whole) now means "the ≥1366 layout only," this becomes `'(max-width: 1365.98px)'`; if folds should still open across both the ≥1366 and 984–1365 layouts (both have the two-column Sheet), the value may stay closer to its current `1499.98` intent but should still be re-derived from a real cut in the new ladder, not left as the retired 1500px placeholder. ### `app/src/ui/RecipeHistory.jsx` + `app/src/styles/notebook.css` — nodes above the line

**Analog:** `.planning/canvas-generators/gen.py`'s already-fixed version of the identical structure (track + nodes container, sibling divs inside one `position: relative` parent).

**The bug, confirmed by reading both the app's CSS and the generator's own fix:**

App today (`notebook.css` lines 371-404, `RecipeHistory.jsx` lines 63-70 for the matching markup):
```css
.notebook-history__rail { position: relative; overflow-x: auto; }
.notebook-history__track { position: absolute; left: 0; right: 0; top: var(--app-notebook-history-track-top); height: var(--app-rule-row); background: var(--app-divider); }
.notebook-history__nodes { display: flex; gap: var(--app-notebook-history-node-gap); min-width: max-content; margin: 0; padding: 0 var(--gap-xs); list-style: none; }
```
`.notebook-history__track` is `position: absolute` (a positioned element); `.notebook-history__nodes` is plain `display: flex` (non-positioned, in normal flow). Under CSS's painting-order rules, a stacking context's positioned descendants (the track) paint **after** — i.e. on top of — its non-positioned in-flow descendants (the nodes/marks), regardless of DOM order. That is the exact defect the gap scope names: the grey line currently paints over the circles.

## Shared Patterns

### The node-guarded matchMedia hook
**Source:** `app/src/ui/useBelowDesktop.js` lines 14-25 (full hook), mirrored privately in `app/src/ui/BatchRow.jsx` lines 124-135.
**Apply to:** any new or edited width-derived JS hook this gap needs (e.g. if the band-stack cut or the rail/tab-row cut needs a JS-side read, not just CSS).
```js
const hasMatchMedia = typeof window !== 'undefined' && typeof window.matchMedia === 'function';
const [flag, setFlag] = useState(() => (hasMatchMedia ? window.matchMedia(QUERY).matches : false));
useEffect(() => {
  if (!hasMatchMedia) return undefined;
  const mediaQuery = window.matchMedia(QUERY);
  const onChange = (event) => setFlag(event.matches);
  mediaQuery.addEventListener('change', onChange);
  return () => mediaQuery.removeEventListener('change', onChange);
}, [hasMatchMedia]);
```
This guard exists because `RecipeHistory.test.jsx`, `BatchRow.test.jsx` and others render via `renderToStaticMarkup` under Vitest's `node` environment, where `window` does not exist at all — an unguarded hook crashes every existing static test the instant it lands (both source files' own comments say this explicitly).
