### Judgement calls

1. **Recipe description left blank.** No source sentence describes Mexican Chocolate as a recipe (only process/observation text exists, none of it recipe-level prose); `mexicanChocolateRecipe.description` is `''`.
2. **Equipment copied from the olive oil kitchen profile.** Mexican Chocolate's sources name no scale or machine. `domain/advisories.js` dereferences `version.equipment` unconditionally (it would throw on `undefined`), so the shared kitchen equipment block (scale, machine, batches-ahead) was copied from `oliveOilVersion.equipment` rather than inventing recipe-specific values — the kitchen is one kitchen, used for every recipe. Flagged for Mark: confirm this is acceptable, or that a Mexican-Chocolate-specific equipment block should be authored instead.
3. **createdAt taken from the export's own `SavedAt` timestamp.** No other date is authored for v4.
4. **The Notes field's "Observations" and "To fix" text is excluded from v4 entirely.** It is word-for-word identical to Mexican Chocolate v1's own outcome text (see the v1 review section below) and v3's own stale "Observations" block — Ice Ed appears to carry the Notes field forward unedited across Save As. Since v4 has never been churned, none of this text can be v4's own result; it is recorded only in the sidecar, flagged as stale, and does not become an authored note, a tasting, or a battery mark on this version.
5. **Dextrose mapped to the existing library entry, not a new one, despite a value discrepancy.** The library's own comment on `dextrose` already documents that its PAC "moved from 1.9 to 1.66 between generations of the predecessor app" — the Ice Ed export used here carries the newer generation's value (PAC 1.66 × 100 = 166, POD 0.61 × 100 = 61), while the library's `dextrose` entry still holds the older 190/70 pair (`coefficientSetId: '2026.1-slice-transcription'`). Per this plan's rule that no existing entry's coefficients change, the row maps to the existing entry unedited rather than overwriting it or adding a second dextrose entry. **Flagged for Mark:** confirm whether the library's dextrose PAC/POD should be updated to the newer 166/61 pair in a future plan (this would move every recipe using dextrose, not just this one).
6. **Salt mapped to the existing library entry despite a small PAC discrepancy.** The library's `salt` entry carries `pac: 580`; the Ice Ed export's Salt PAC is `5.86` (×100 = 586). Both are recorded as `basis: 'estimated'` already; the 6-point difference is within the entry's own stated uncertainty. Mapped to the existing entry unedited.
7. **Step allocation.** The source names one process (sous vide, then chill/churn); all 12 rows are allocated to step 1 (the sous vide/combine step) as the "base step" — no per-ingredient step breakdown exists in the source.
