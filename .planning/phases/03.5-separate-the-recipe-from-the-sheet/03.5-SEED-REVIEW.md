### Judgement calls

8. **The version's plan keeps the typed 45 min / 75 °C; the batch records the ink overwrite as a step change, not a rewritten plan.** The printout shows both numbers struck and replaced by hand — the `.ier` export (saved before the overwrite) still carries the original typed values, which is what a maker planned before churning. The overwrite is what was actually done, which belongs on the batch record, not the recipe's own plan.
9. **"Double Recipe" recorded as every row's as-made value at plan × 2, with a note stating the rule**, rather than inventing a doubled formula on the version itself (the version's own rows keep the single-recipe plan the printout's table shows) or leaving the doubling unrecorded. Flagged for Mark: confirm this reading of "Double Recipe" is correct — the alternative would be a version-level note only, with no as-made values at all.
10. **Three battery marks set from the ink text, each an interpretation:** "Sweetness Good" → sweetness 3 (right); "Hard straight from Freezer" → hardness 5 (hard); "But scoopable" → scoopability 3 (right — read as neither crumbly nor gummy, following the binder audit's own reading of this line). None of these map without some interpretation; flagged for Mark to correct if any reads wrong.
11. **No draw temperature or churn duration recorded.** "40+ minutes to Churn" is inexact (open-ended) and is kept as prose in `atTheMachine`, not coerced into a number for `churnDurationMinutes`.

### Judgement calls

12. **This is the single most dangerous page in the binder** (binder audit's own words): it looks like it has a result — a populated "Observations:" field — but that text belongs to a batch made roughly a month earlier, on a formula with 2× the cocoa, no allulose, and 86 g of dextrose instead of 45. It is excluded from v3 entirely: not a tasting, not a note, not a battery mark. It is recorded only in the sidecar, clearly flagged as stale.
13. **A v3 batch is recorded even though the page supports almost no measured data**, because the binder audit confirms every one of the 29 binder pages was actually churned — the batch's existence reflects that fact. `churnDate` stays `null` rather than guessing from the print timestamp (which records when the page was printed, not necessarily when the recipe was churned). This is the "churned, not yet tasted" state D-05 asks the seed to cover.
14. **`reason` on the v3 version is the v1 to-fix list**, even though v3's own executed numbers differ slightly from that list's stated targets (dextrose lands at 45 g, not the stated 55 g; allulose at 36.8 g, not "+30 g"). It is the closest available source for "why this version exists." Flagged for Mark: confirm this reading, or that `reason` should be left `null` since the page itself never states it responds to v1 (the binder audit notes this explicitly — the connection is inferred from the numbers, not stated on the page).

### History

The rail shows three versions for Mexican Chocolate — v1, v3, v4 — with no v2 (it is missing from both the binder and Mark's disk; D-01 keeps the gap visible rather than inventing one). The app's own history counts printings, not source version numbers, so it reads "Version 1 · v1", "Version 2 · v3", "Version 3 · v4" (decisions_recorded 8) — the "2" is the app's own count of what exists, not a claim that v2 never happened.

### Judgement calls

1. **Recipe description left blank.** No source sentence describes Mexican Chocolate as a recipe (only process/observation text exists, none of it recipe-level prose); `mexicanChocolateRecipe.description` is `''`.
2. **Equipment copied from the olive oil kitchen profile.** Mexican Chocolate's sources name no scale or machine. `domain/advisories.js` dereferences `version.equipment` unconditionally (it would throw on `undefined`), so the shared kitchen equipment block (scale, machine, batches-ahead) was copied from `oliveOilVersion.equipment` rather than inventing recipe-specific values — the kitchen is one kitchen, used for every recipe. Flagged for Mark: confirm this is acceptable, or that a Mexican-Chocolate-specific equipment block should be authored instead.
3. **createdAt taken from the export's own `SavedAt` timestamp.** No other date is authored for v4.
4. **The Notes field's "Observations" and "To fix" text is excluded from v4 entirely.** It is word-for-word identical to Mexican Chocolate v1's own outcome text (see the v1 review section below) and v3's own stale "Observations" block — Ice Ed appears to carry the Notes field forward unedited across Save As. Since v4 has never been churned, none of this text can be v4's own result; it is recorded only in the sidecar, flagged as stale, and does not become an authored note, a tasting, or a battery mark on this version.
5. **Dextrose mapped to the existing library entry, not a new one, despite a value discrepancy.** The library's own comment on `dextrose` already documents that its PAC "moved from 1.9 to 1.66 between generations of the predecessor app" — the Ice Ed export used here carries the newer generation's value (PAC 1.66 × 100 = 166, POD 0.61 × 100 = 61), while the library's `dextrose` entry still holds the older 190/70 pair (`coefficientSetId: '2026.1-slice-transcription'`). Per this plan's rule that no existing entry's coefficients change, the row maps to the existing entry unedited rather than overwriting it or adding a second dextrose entry. **Flagged for Mark:** confirm whether the library's dextrose PAC/POD should be updated to the newer 166/61 pair in a future plan (this would move every recipe using dextrose, not just this one).
6. **Salt mapped to the existing library entry despite a small PAC discrepancy.** The library's `salt` entry carries `pac: 580`; the Ice Ed export's Salt PAC is `5.86` (×100 = 586). Both are recorded as `basis: 'estimated'` already; the 6-point difference is within the entry's own stated uncertainty. Mapped to the existing entry unedited.
7. **Step allocation.** The source names one process (sous vide, then chill/churn); all 12 rows are allocated to step 1 (the sous vide/combine step) as the "base step" — no per-ingredient step breakdown exists in the source.
