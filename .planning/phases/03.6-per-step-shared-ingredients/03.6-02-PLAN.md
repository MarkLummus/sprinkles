<decisions_recorded>
1. **The row flag is written `false` by the pen, never `true`.** transfer.js still requires a boolean row flag and every seed carries `removed: false`, so the saved row keeps the key (plan 01 decision 3). A stored `true` is folded into the lines when the pen opens, through `isLineRemoved(row, portion)`, so it can never resurrect a row the maker restored.
2. **The saved line flag is always a boolean** (`Boolean(draftPortion.removed)`), in the style of the row and step flags that are explicit `false` everywhere. A reader still treats an absent flag as in (T-03.6-01).
3. **A removed line keeps its stored amount.** The saved grams stay `parseGramsDraft(draft) ?? portion.grams`, so a blank or garbled field on a removed line never reaches the store as a non-number (T-03.6-04).
4. **The orphaned-row flag's button** keeps the table prop `onTogglePenRowRemoved(rowId)`. It now acts on every line of the row, through one exported pure function `toggleDraftRowLines(draftRow)`: if every line is out it puts every line back in, otherwise it takes every line out. The flag only prints on a row with a line in, so in practice it removes.
5. **The flag prints on the first line still in**, because plan 01's rule "index 0" could land the flag on a struck line. A row with a line in always has one (a row with none is never orphaned).
</decisions_recorded>
