## Warnings

### WR-01: Row-level diff figures sum every stored line, including lines that are out

**File:** `app/src/domain/diff.js:121-141` (consumer `app/src/domain/uses.js:112-113`)
**Issue:** `buildRowDiff` computes `gramsFrom`, `gramsTo`, `gramsChanged`, `shareFrom` and `shareTo` from `rowGrams(row)` and `rowGrams(baseRow)`, which sum all stored portions regardless of removal. The masses they are divided by (`activeMass`) exclude out lines, and the new `lines` array is per-line and does honour removal. So for a split row the two layers disagree:
- Taking one line of a split row out leaves `gramsChanged` false (the stored total did not move), so `stepsWithStaleAmounts` never flags the steps that use that row, although the row's effective amount in the batch dropped.
- Editing the grams of a line that is out sets `gramsChanged` true and raises a stale-amount flag for a change that has no effect on the batch.
- Row-level `shareTo` is an out line's grams over a mass that does not contain them.

Before this phase the row-level figure and the active mass were consistent, because a row was either wholly in or wholly out. This mixed state is new in this phase.
**Fix:** Make the row-level figures read the lines still in, on each side, with the same predicate `lines` uses:
```js
function activeRowGrams(row, method) {
  return row.portions.reduce(
    (total, portion) => (isLineRemoved(row, portion, method) ? total : total + portion.grams),
    0,
  );
}
// in buildRowDiff
const rowTotal = activeRowGrams(row, method);
const baseRowTotal = activeRowGrams(baseRow, baseMethod);
```
Apply the same to the `!baseRow` branch (`gramsTo`, `shareTo`). Add a `diff.test.js` case: a split row with one line taken out gives `gramsChanged === true`.

### WR-02: Pen accessible name announces a false "was X%, now Y%" for a split row with a line already out at open

**File:** `app/src/ui/IngredientTable.jsx:640-649` (label built at line 671, `rowAccessibleLabel` at 104-122)
**Issue:** `baselineShare = formatShareOfBatch(rowGrams(row), baselineMass)` uses the stored row, so it includes lines that were already out when the pen opened. `baselineMass` and `currentShare` both use lines-in only. Open the pen on a version where a split row has one line out (its own flag, or its step removed in the stored method) and touch nothing. The line still in gets `changedShare` non-null, and its accessible name reads, for example, "Cream, 300 g, was 25.0%, now 16.7%". Nothing changed. The `gramsPhrase` `${rowGrams(row)} g` also counts the out line, whereas the reading state correctly passes `liveRow` (`IngredientTable.jsx:536-537`). Screen-reader users get false change announcements; the strike is not the only carrier of a change (D-10), so this is the carrier.
**Fix:** Read the opening row through the existing active map:
```js
const openingRow = baselineActiveById.get(row.id);
const baselineShare = formatShareOfBatch(openingRow ? rowGrams(openingRow) : 0, baselineMass);
```
and pass `openingRow ?? row` to `rowAccessibleLabel` so its "was N g" phrase excludes lines that were already out.

### WR-03: Portion sub-line of a line that is out in the opening version reads "N g of M g" with N > M

**File:** `app/src/ui/IngredientTable.jsx:718` and `app/src/ui/IngredientTable.jsx:598`
**Issue:** For a struck line the sub-line is `formatPortionLine(portion, rowGrams(openingActiveById.get(row.id) ?? row), openingMass)`. `openingActiveById` holds the opening version's lines still in. When the line was already out in the opening version (pen opened on a version with the line out, or Show changes where parent and child both have it out), the opening active row excludes that line. The sub-line then prints the line's grams "of" a row total that does not contain it (for example "150 g of 100 g · 25.0% in all"). When the whole row was out at open, the lookup misses and falls back to the stored row, whose total is then divided by a mass that excludes it. Both are reachable on any second-generation version that keeps a removal.
**Fix:** For a line that is out in the opening version there is no opening share. Print a sub-line only when the line was in at open, and otherwise show the bare amount:
```js
const openingRow = openingActiveById.get(row.id);
const wasIn = openingRow && openingRow.portions.some((p) => (p.index ?? 0) === portionIndex);
// wasIn ? formatPortionLine(portion.grams, rowGrams(openingRow), openingMass) : `${portion.grams} g`
```
In Show changes, `rowDiff.lines[i].removedChanged` (already built, currently unused by the UI) says whether the line's out state is new.

### WR-04: Blocked-save marker and focus still address the row and its first portion, not the blocked line

**File:** `app/src/domain/lineage.js:218-236, 281-285`, `app/src/ui/IngredientTable.jsx:658, 680`
**Issue:** `findBlockedRow` now walks lines and skips ones that are out, but it still returns only `{ row, message }`. The table registers the focus ref only on `portionIndex === 0` and marks `isBlocked` on every line of the row. With per-line removal this misfires: if line 0 is out (struck) and line 1 has a blank amount, a blocked save focuses line 0's struck field and outlines both lines, including the struck one. The message "needs an amount, or remove the row" also offers a row-level removal where the control is now per line (decision 51).
**Fix:** Return the blocked portion index from `findBlockedRow` (`{ row, index, message }`), have `blockedSaveRowId` callers receive `{ rowId, index }` in `blockedTarget`, key the ref map by `${rowId}:${index}`, mark only that `<tr>`, and word the message "needs an amount, or remove it".

## Info

### IN-01: `activeRows` dereferences `row.portions` unguarded while `isRowRemoved` guards it

**File:** `app/src/domain/rows.js:45` vs `app/src/domain/rows.js:69-72`
**Issue:** `isRowRemoved` tolerates a missing portions array (`row.portions ?? []`), but `activeRows` calls `row.portions.forEach` and `.length` directly. Before this phase `activeRows` never touched portions, so a row without them now throws where it used to be filtered. Import validation requires a non-empty array, so this is reachable only through fixtures or hand-built versions, but the two helpers disagree about what a legal row is.
**Fix:** Pick one. Either drop the `?? []` in `isRowRemoved` (portions are validated non-empty) or add `const portions = row.portions ?? [];` in `activeRows`.

### IN-02: Line descriptor fields `removedChanged`, `index` and `step` have no reader, and `DiffShareCell` can print an empty strike

**File:** `app/src/domain/diff.js:64-95`, `app/src/ui/IngredientTable.jsx:234-237`
**Issue:** `removedChanged` on a line is built but no UI reads it, and `DiffGramsCell`/`DiffShareCell` strike any out line even when it was out in the parent too (no change). `DiffShareCell` renders `<span class="struck-value">{line.shareFrom}</span>` with `shareFrom === null` for a line with no baseline portion, an empty strike span. Not wrong for the current data, but the descriptor carries a signal the table is not using (see WR-03, which needs it).
**Fix:** Use `line.removedChanged` where the table decides whether a strike marks a change (WR-03), and guard the strike with `line.shareFrom != null`.
