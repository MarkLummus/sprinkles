## How it was measured

- The build was written on 2026-10-10 by `npm --prefix app run build` from the tree at plan 01's last app commit (`ef88dd9`); Task 2 of this plan changes two unused CSS rules and nothing that renders, and the board mode was run again on that final tree (see Regression). Nothing contacted Mark's `vite preview --host` on :4173, the :8077 sketch server, his browser profile or any third-party host.
- Two engines, both with a coarse pointer: Playwright WebKit (the iPad's engine) and system Chrome. Widths 1366 (where the log column beside the Sheet is 350 wide) and 393 for the board comparison; 1366 fine, 1024 coarse and the same two for the before and after numbers. Every case is a fresh context at the case's own width; a pen case clicks `.batch-row__record` (Record another) or `.batch-row__correct` (Correct) and waits for `.batch-margin--pen`. No DOM edit anywhere.
- The expectation is read live from the board's own panel, never from prose: each board is opened coarse through the harness's `openBoard` at the board's own `$preview` width (the file names carry no 393, and CONTRACT section 7 was measured with a coarse pointer), and a panel is located by its class (`.fp-win.fp-r4-393` and so on; declared-pen-reading's pen panels by index among the `.fp-win` panels that hold a `.field-row`, at their own width). The app and the panel are read by the same function.
- The boards also draw D6 to D14 (At draw and From freezer, the pen order, Exit consistency and Airiness in their own group, Airiness without "(estimated)"), which Phase 4 builds. So only the churn row and the churn cells are compared, never a whole panel's height.
- Pen facts: the caption texts in order; each label's box (x, y, width, height) relative to the first `.field-row`; the row's width and height; that Churn duration's top lies below Churn date's (its own line, as D17 says it sits at 350 and 393). Reading facts: the first two cells' label and value texts; each cell's box relative to the first `.batch-row__cells` grid; the first grid row's height. Numbers within 1 px, text exact. The app's reading holds four cells (Exit consistency and Airiness are in the app's grid; the boards draw them elsewhere), so only the first two are compared.
- Dispositions: `match`; `fixed here with a test` (only for a difference this phase caused); `open for Mark` (a difference the baseline already shows predates the phase, and anything only Mark can judge). A difference between the engines is a finding, not an average.
