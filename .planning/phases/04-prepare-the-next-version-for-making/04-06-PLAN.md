## Phase Goal

Maker can print the new version as a bench sheet, carry it to the kitchen, and match the printed sheet back to its version — with the whole develop loop operable by keyboard and recoverable.

(ROADMAP Goal, verbatim; not in "As a / I want to / so that" form and not invented here.)

<objective>

Facts the executor relies on (measured or read 2026-10-06 to 2026-10-11):
- WebKit prints 1 CSS px as 0.8 pt: at `@page { size: letter; margin: 0.5in 0.75in }` the content box is 630 × 900 CSS px in Safari and 672 × 960 in Chrome. WebKit ignores @page margin boxes and named pages and prints a position:fixed element once, so every foot is in-flow markup inside its page. `100vh` in WebKit print is the window, never the page: page boxes take `height: 100%` with html, body and every wrapper down to the page given `height: 100%` (RESEARCH Pattern 2, verified in both engines).
- The route renders inside Shell (the boards draw the shell around it), so the print rules hide the shell's chrome and neutralise its `min-height: 100vh` only when the route is present (`:has(.print-route)`), leaving every other route's print untouched.
- css-source.js's readAllRules throws on @page and @supports, and cross-cutting.test.js pins app.css's media blocks and nine print rules, so the new rules live in a new app/src/styles/print.css, imported in main.jsx after notebook.css and listed in tokens.test.js's CSS_FILE_NAMES; tokens.test.js reads it with regexes only (readCustomProperties, var refs), never readAllRules. Its expectedUnread list holds `--rule-tick`, which print.css will read: remove it there. print.test.js reads print.css with its own at-rule-aware reader.
- The boards' log markup and CSS (classes lf, lf-body, lf-datebox, lf-title, lf-row, lf-field, lf-field--under, lf-rule, lf-base, lf-base--figure, lf-unit, lf-group, lf-ghead, lf-gname, lf-gcue, lf-verdict, lf-opt, lf-box, lf-mrow, lf-mrow--plain, lf-mark, lf-srow, lf-sc, lf-track, lf-tick and its --1..--5 and --end modifiers, lf-anchor, lf-lo, lf-hi, lf-mid, lf-num, lf-n1, lf-n5, lf-sub, lf-dhead, lf-notes, lf-lines, lf-line, lf-foot; plus pen-caption, pen-helper, axis-mark__name, region-name) are the target; CONTRACT § 10 lists the literals to tokenise.
- Words come from the built pens: BATTERY_FIELDS labels and units, SEGMENT_OPTIONS, DEFECTS, PRINTED_MARK_ONE_OPTIONS (04-03), AXES and CORE_AXIS_COUNT; the printed caption is Airiness without "(estimated)" (sketch 010 D3). A version's declared problems are `version.declaredFlaws` (04-03).
- `.planning/canvas-generators/wkprint.swift` waits for `.ingredient-table` before printing; this plan adds an optional WKP_READY environment variable (a JavaScript boolean expression) so the probe can wait for the route's own ready mark, with the old check as the default. Compile it with `swiftc -O` into the OS temp directory, as 03.7-print-probe.mjs compiles pdf-pages.swift.
- The probe follows .planning/phases/03.7-before-you-start-as-its-own-sheet-section/03.7-print-probe.mjs: the 03.5 harness (startServers with appRoot, launch() is headless Chrome, openApp, openBoard, check, finish), every request to another host aborted, PROBE_DIST default app/dist, page.pdf for Chrome, pdf-pages.swift for per-page text.
