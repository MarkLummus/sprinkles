In app/src/store/transfer.js, validateVersion requires sheetCode to be a string equal to normaliseCode(sheetCode) (canonical XXXX-XXXX), path-named otherwise; the code is kept exactly as written and never recomputed (D-04a). importStore, after the existing parent and recipe pre-checks and before the write, reads the stored versions (already read for the parent check) and runs sheetCodeProblems(storeVersions, parsed.versions); each problem becomes a path-named message: for a clash, `$.versions[i].sheetCode: "CODE" is already the Sheet code of version "ID"` (naming the file path of each side when both are in the file); for a change, `$.versions[i].sheetCode: "NEW" would replace the Sheet code "OLD" of the stored version "ID", and a Sheet code never changes`.
