<objective>
The store-side contracts Save and Save-over stand on: what a created recipe carries (createRecipe's optional fields), the two one-transaction writes (create, and write over a first version), the version pen's existing overwrite guarded the same way, the one rule for who may edit a first version, the edit draft's kind, and the address the edit lives at (MAKE-10, STRUCT-04; D-01, D-02, D-03, D-06, D-19).

Purpose: atomicity is a success criterion (a failed save leaves neither recipe nor version) and the stale-edit check must run inside the save's own read (D-06), so both transactions and their forced-failure tests land before any UI calls them; the eligibility rule is pure so the page, the route and the transaction share it. Once a first version can be saved over from the edit route, the version pen's own Save over is a second writer of the same record, so it gets the same expected-record check at the repository boundary (review round 2, L82@45089779).
Output: newRecipe.js, repository.js, firstVersion.js (new), draft.js, notebookPaths.js, useVersionPen.js's Save over, and their tests; creation-roundtrip.test.js and RecipePage.perStep.test.jsx extended.
</objective>
