<locked_decisions>
Decided by Mark in the critique follow-up on 2026-09-07. Locked — do not revisit, do not extend.

- **D-1 Cancel.** `TastingForm` gets a `Cancel` button after `Save tasting`, in the same order and
  markup as the churn form's `Save batch` / `Cancel` pair (BatchMargin.jsx:224-229). RecipePage adds
  `handleCancelTasting`, which sets `tastingDraft` to null, passed as `onCancelTasting`. Cancel
  discards silently, exactly as the churn Cancel does — the brief (§ 6, "Leaving with unsaved ink:
  the browser's own leave warning; no invented dialog") forbids a dialog of the app's own. The
  existing `beforeunload` guard is untouched.
- **D-2 Legend.** The form's first child is `<p className="batch-margin__legend">Tasting</p>` — the
  same element the reading state uses for a tasting's date words (BatchMargin.jsx:19), so a tasting
  being written is headed the way a read one is. No new class, no new token.
- **D-3 Focus on open.** The tasting date input gets `autoFocus`, the same mechanism the churn date
  field uses (RecipePage.jsx:357). No refs for this.
- **D-4 Focus on close.** When `tastingDraft` goes from non-null to null (cancel or save), focus
  moves to the `Add a tasting` button that re-renders in the form's place. Implemented inside
  `BatchMargin` with a `useRef` on that button and a `useEffect` keyed on `tastingDraft`, plus a
  second ref tracking whether the form was open so it never fires on first mount.
- **D-5 Nothing else.** No "recorded" feedback line for a saved tasting, no overflow-wrap change, no
  button styling, no copy changes elsewhere. Those stay parked in the critique snapshot.
</locked_decisions>

<grounded_facts>
Verified against the working tree before planning — build on these, do not re-derive them.

1. `app/src/ui/BatchMargin.jsx` imports nothing from `react` today (line 1 is `react-router`). The
   hooks import must be added.
2. `BatchMargin` has three return branches (`mode === 'recording'` at line 157, `openBatch` at 234,
   and the fallback at 316). React's rules of hooks therefore require `useRef`/`useEffect` to be
   called at the very top of the component body, **before** the `if (mode === 'recording')` return.
3. `renderToStaticMarkup` does not run effects, so the focus-return effect is invisible to the test
   suite. `useRef` is safe during a server render.
4. `renderToStaticMarkup` serializes `autoFocus` as the attribute `autofocus=""` (verified).
5. Today the tasting date input serializes as `<input type="date" class="ink-field" value=""/>`;
   attribute order follows JSX prop order, so tests must not depend on it.
6. The tasting form renders cleanly under `renderToStaticMarkup` with `augustSecondBatch` and a
   fresh draft — 138 `axis-mark` fragments, no router context needed (a single batch renders no
   `<ul>` and no `Link`).
7. The existing test "renders no date input ... while recording" (BatchMargin.test.jsx:104-108)
   negative-matches `type="date"` under `mode: 'recording'`. The recording branch returns before the
   tasting form is ever reached, so adding an autofocused date field to `TastingForm` leaves it
   green. Do not weaken or rewrite that test.
8. The existing test "does not render the cancel wording" (BatchMargin.test.jsx:96-101) renders with
   `openBatch: null`, so no tasting form exists in it. It stays green. Do not weaken it.
9. `isTastingDraftDirty(null)` returns `false` (RecipePage.jsx:36-38), so setting `tastingDraft` to
   null removes the `beforeunload` listener through the existing effect — cancel needs no guard
   changes at all.
10. `.batch-margin__legend` (app.css:425) and `.tasting` (app.css:482) already carry every rule the
    new legend needs. **No CSS change is expected; do not edit `app/src/styles/app.css`.**
11. Baseline: `npm --prefix app test` is green (BatchMargin.test.jsx has 9 tests), and
    `impeccable detect --json` on both target files returns `[]`.
</grounded_facts>
