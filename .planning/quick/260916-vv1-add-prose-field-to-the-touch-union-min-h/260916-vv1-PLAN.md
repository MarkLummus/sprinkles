# `.prose-field` joins the touch-union `min-height` list

Impeccable critique issue 4 (P1), measured live at viewport 759 and 600: the four record
prose fields — At the machine, Ingredient notes, How did it turn out?, Next time — render
560 x 19 at every coarse pointer. `PRODUCT.md` makes the phone the transcription device and
UX1-01 binds a 44px touch target, so a 19px field a maker is meant to type into with a
thumb is a real violation.

The cause, re-verified against the live files this session: the touch union at
`app.css:2292` declares `min-height: var(--touch-min)` for
`button, select, .ink-field, .segmented__option, .batch-margin .chip-toggle`, and
`.prose-field` is absent from that list while its base rule (`app.css:1351`) sets neither
`min-height` nor `height`. Nothing anywhere gives a prose field a floor.

**Mark approved the fix as stated:** add `.prose-field` to that shared list. One selector.

**It stays in the shared list on purpose.** The standing project rule is that shared size
tokens stay shared — one value app-wide, split only for a named exception. There is no
named exception: a narrowed desktop window and a wide iPad both want a reachable prose
field, so the union's dual condition (`max-width: 759.98px`, `pointer: coarse`) is already
the right condition and must not be split into a private rule or a second block.

## Discovered at planning — read this before editing

**1. The unexplained 19px is now explained, and the explanation is out of scope.** The
background note asked why a `<textarea rows="2">` renders 19px rather than two lines. It is
not unexplained any more: `app/src/styles/app.css:259-262` declares
`textarea { field-sizing: content; resize: none; }` **unconditionally**. Under
`field-sizing: content` the `rows` attribute is inert — the box sizes to its content — so
an empty field collapses to exactly one line. The touch block already raises
`.ink-field, .prose-field` to `var(--type-note)` (16px) at `app.css:2326`, and
`.batch-margin__field` (1429-1436) sets no `line-height`, so one line lands at roughly
16 x 1.2 ≈ 19.2px. That matches the critique's measurement.

The sketch does not have this problem because **sketch 008 line 141 gives `.prose-field`
three declarations the app's rule dropped**: `min-height: calc(var(--leading-note) * 1em)`,
`padding: var(--gap-hair) 0`, and `line-height: var(--leading-note)`. The app has
`padding: 0`, `line-height: inherit`, and no `min-height`.

**Do not fix that here.** It is a sketch-conformance gap for `.prose-field`'s base rule,
it affects DESKTOP too (where no `min-height` applies and this task's fix will never
reach), and widening this task to cover it would breach CLAUDE.md §3. Record it in the
SUMMARY for Mark. This fix closes the touch-target violation — 44px is a floor, not a
restored two-row prose field.

**2. This fix is a departure from the sketch, and the sketch is the authority.** Sketch 008
line 166 lists the touch `min-height` selectors —
`.chip-toggle, .defect, .check, .seg .opt, .text-control, .btn, .ink-field` — and
`.prose-field` is deliberately absent, while line 167 pairs `.ink-field, .prose-field` for
`font-size`. Sketch 007 lines 176-179 say the same. So the sketch's own prose field at
touch measures about 24px (its `min-height: 1.5em`), also under 44px: **the critique's
finding is a finding against the sketch too.**

Mark approved the app-side fix, so it lands. But the standing rule is that app-side
decisions get drawn back into the sketch rather than left as departure rows. Editing sketch
008/007 is outside this task's file list; the departure is recorded in the CSS comment and
raised in the SUMMARY so Mark can rationalise the sketch in a follow-up.

**3. The fix reaches twelve fields, not four.** `.prose-field` is rendered by
`Headnote.jsx:23` (the intro paragraph), `Method.jsx:150, 158, 228, 255, 459` (lead-in,
instruction, purpose, aside, and the method's own note), `Authored.jsx:24` (an authored
note), `VersionRow.jsx:272` (the reason), and `BatchRow.jsx:511, 524, 607, 730` (the
critique's four). Every one of them gains the 44px floor at a coarse pointer. That is the
intended consequence of keeping the token shared — they are all fields a maker types into
on the same device — but it is a visible change to the recipe-version page at touch, so
the UAT below looks there as well as at the record.

**4. Nothing else pins this selector string.** Grepped: the only three occurrences in the
repo are `cross-cutting.test.js:56`, `:57` and `:86`. `binder.test.js` asserts the @media
count (six) and the allowed media strings — a selector joining an existing rule changes
neither. No live artifact cites `app.css` line numbers; the only citations are in historical
planning docs (including `.planning/.continue-here.md:64`, which names this defect).

**5. Security.** No trust boundary is crossed: no package is installed, no input path,
no network call, no markup rendering. A CSS selector-list addition and two test-assertion
updates. No STRIDE item applies.

## The exact change

**`app/src/styles/app.css`** — inside `@media (max-width: 759.98px), (pointer: coarse) {`,
the block's first rule (the min-height list at ~2293-2299):

```
  button,
  select,
  .ink-field,
+ .prose-field,
  .segmented__option,
  .batch-margin .chip-toggle {
    min-height: var(--touch-min);
  }
```

**Position and why:** after `.ink-field`, before `.segmented__option`. The list runs bare
element selectors first (`button`, `select`), then single-class selectors, then the one
descendant-scoped selector last — an ascending order that reads as intentional. Within the
single-class group, `.prose-field` belongs immediately beside `.ink-field`: they are the
two text-entry fields, and this same media block already pairs them in exactly that order
for `font-size` (`.ink-field, .prose-field`, ~2326). Any other position would either break
the element-then-class order or separate the two fields the block already treats as a pair.

**`app/src/styles/cross-cutting.test.js`** — the two assertions that pin the old string,
updated to pin the new one at the same strictness. Nothing weakened; the point of these
tests is to pin the contract, so they still pin it, at its new value.
