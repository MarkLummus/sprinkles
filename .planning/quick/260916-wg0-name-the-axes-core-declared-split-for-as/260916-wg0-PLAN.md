# Name the axes core/declared split for assistive tech

Impeccable critique issue 5 (P2). Each axis's stops are correctly `role="group" aria-labelledby`
(`AxisMark.jsx:82-83`), and the DEFECT cues 340px below carry `id="defects-core-cue"` /
`id="defects-declared-cue"` and are properly referenced (`BatchRow.jsx:656-658`, `682-684`). The
AXES cues are not: they are bare `<p className="pen-caption axes-cue">` with no `id`, and the
vertical hairline is `aria-hidden`. A screen-reader user hears six axes and never learns that Body
and Oil are "this recipe only" while the other four are "every recipe".

**Mark's decision: per-axis labelling.** Give each cue an `id` and pass it into `AxisMark`, so each
axis's stops group reads `aria-labelledby="{axis name id} {cue id}"`. Chosen because it works
identically in both arrangements, needs no DOM restructuring, and puts the qualifier on the axis
itself — a user navigating axis by axis hears it, rather than only on entering a group.

**Explicitly rejected, do not implement:** group wrappers with `display: contents` at desktop
(`display: contents` has a history of dropping elements from the accessibility tree, which would
silently defeat the fix); and fixing the stacked arrangement only.

## Discovered at planning — read this before editing

**1. The critique's own prescription does not fit, and per-axis is the reason it does not have to.**
Re-verified live. `AxesGrid` renders the axes in two arrangements:

- **Stacked** (`if (below)`, 158-171): `.axes-grid__group` divs DO wrap cue + axes. The wrappers
  carry no `role` and no `aria-labelledby`, so the critique's "point each group's `aria-labelledby`
  at them" would work here.
- **Desktop row-major** (173-192): the two cues (181-182) and all six axes are **flat siblings** of
  `.axes-grid`, interleaved cue, cue, core[0], core[1], declared[0], core[2], core[3], declared[1] so
  CSS grid places them row-major. **There is no group wrapper at desktop**, and that flat order is
  deliberate — the sketch's sixth round established it so tab order follows the eye
  (contract "Keyboard and tab order"; structure reference line 473).

So the group-wrapper prescription cannot be applied at desktop without restructuring the grid. The
per-axis approach sidesteps the asymmetry entirely: the label is attached to the axis, and the axis
renders through one shared code path in both arrangements.

**2. There is no `axes-caption` id to include, so the pair is two ids, not four.** Grepped: unlike
the defects section, which references `defects-caption` as the broader label, the axes have no
section-caption id at all. The broader label for an axis is its own name id, which `AxisMark`
already owns. So the composed value is two tokens, not three.

**3. This restores an unsuperseded contract line.** The structure reference's Core/declared split
bullet ends "**Screen readers hear the cue as part of Body's box.**" (line 158). The 03.3.1 design
achieved that physically, by putting a "Declared for this recipe" caption inside Body's box. The
cue-row redesign superseded the caption's LOCATION (recorded at line 532: *Axes spec*: "the
'Declared for this recipe' caption sits inside Body's box" → the cue rows above) but did NOT
supersede the announcement requirement — and moving the cue out of the box silently dropped it.
This fix meets line 158's requirement without moving any DOM. **It is contract-restoring, not a
contract departure**, so no sketch rationalisation is owed. Record that in the SUMMARY.

**4. One asymmetry to note, not to act on.** The old design put the qualifier only inside Body's box
— declared axes only. Mark's decision labels BOTH groups, so "Every recipe" now trails all four core
axes. That is consistent with the defects section, which references `defects-core-cue` for the core
group too, and it is what Mark asked for. The only cost is verbosity: four extra repetitions per
pass. The UAT below listens for that specifically. **Do not unilaterally drop the core cue to reduce
verbosity** — Mark's decision names both.

**5. Do NOT add `role` to the cue `<p>` elements, and the plan agrees with that constraint.** They
are labelling text, pulled in by id reference. `aria-labelledby` flattens the referenced element's
text content into the group's accessible name regardless of the `<p>`'s own role, so a role adds
nothing; and giving a referenced element a role that makes it independently focusable or announced
is exactly how a qualifier ends up read twice. The defects section sets the same precedent — its
referenced cues are plain `<p>` with an `id` only (`BatchRow.jsx:658`, `684`). No argument to make
against this constraint.

**6. No stylesheet change is needed, and this was checked rather than assumed.** The five rules that
style the cues are all class-based: `app.css:2156` (`.axes-grid__group > .axes-cue`), `2160` and
`2170` (`.axes-grid:not(.axes-grid--stacked) > .axes-cue--core` / `--declared`), `2201` and `2207`
(`.axes-grid__group`, `--declared`). Adding an `id` attribute matches no new selector and changes no
specificity, because no id selector is introduced. `app/src/styles/` must not appear in the diff.

**7. Security.** No trust boundary crossed: no package installed, no input path, no network call, no
markup rendering, no `dangerouslySetInnerHTML`. Two `id` attributes and one accessible-name string.
No STRIDE item applies.

## The exact change

### `app/src/ui/AxisMark.jsx` — an optional `cueId`

```
- export function AxisMark({ axis, value, onChange, onClear }) {
+ export function AxisMark({ axis, value, onChange, onClear, cueId }) {
```

and at the stops group (~81-84), the VALUE only:

```
        className="axis-mark__stops"
        role="group"
-       aria-labelledby={nameId}
+       aria-labelledby={cueId ? `${nameId} ${cueId}` : nameId}
        onKeyDown={handleStopsKeyDown}
```

**The truthy check is the safe default.** Omitted (or `undefined`, `null`, `''`), the output is
exactly `aria-labelledby="axis-name-{key}"` — byte-identical to today, no trailing space — so every
existing call site and test still renders a valid group named by its axis.

### `app/src/ui/BatchRow.jsx` — two ids, and one pass-through

Two module-scope constants immediately above `AxesGrid`'s comment block or between it and the
function, chosen over inline literals because each id string appears at **three** sites (its `<p>` in
the stacked arrangement, its `<p>` in the desktop arrangement, and the `renderAxis` mapping), and the
whole fix is correct only if all three agree:

```
+ const AXES_CORE_CUE_ID = 'axes-core-cue';
+ const AXES_DECLARED_CUE_ID = 'axes-declared-cue';
```

`renderAxis` (~145-156), one added prop:

```
        onClear={() => onClearMark(axis.key, axis.name)}
+       cueId={axis.group === 'declared' ? AXES_DECLARED_CUE_ID : AXES_CORE_CUE_ID}
      />
```

All four cue `<p>` elements take an `id`, `className` first and `id` second (matching
`BatchRow.jsx:658`):

- stacked, ~162: `<p className="pen-caption axes-cue" id={AXES_CORE_CUE_ID}>Every recipe</p>`
- stacked, ~166: `<p className="pen-caption axes-cue" id={AXES_DECLARED_CUE_ID}>This recipe only</p>`
- desktop, ~181: `<p className="pen-caption axes-cue axes-cue--core" id={AXES_CORE_CUE_ID}>Every recipe</p>`
- desktop, ~182: `<p className="pen-caption axes-cue axes-cue--declared" id={AXES_DECLARED_CUE_ID}>This recipe only</p>`

Nothing else on those elements changes — same classes, same visible text, same position.
