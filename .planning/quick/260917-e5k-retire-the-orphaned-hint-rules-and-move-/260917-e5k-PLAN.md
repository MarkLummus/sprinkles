# Retire the orphaned hint rules, and move the version pen's refusal to form scope

Two follow-ups from the Impeccable review of `1333a7e`, approved by Mark on 2026-09-17. They are
independent. Two tasks, two commits, in order.

Item 1 removes three CSS rules that nothing renders, and repoints the two tests pinning them at the
rules that are rendered. Item 2 brings the version pen into line with the batch pen: a refused save
and a failed write speak inside the pen, beside the controls and the kept draft, instead of in the
page region that exists for the save that ends the session.

## Discovered at planning — read this before editing

Every line number below was read live on 2026-09-17 against the current files. They guide; they do
not authorize. Re-grep and take your scope from what you find.

### 1. How the live helper/status selector set was established (Item 1's own gate)

Not guessed. Two greps, both over `app/src`:

```
grep -rn "pen-hint\|batch-margin__hint\|versions__hint" app/src
grep -rnoE "className=\{?[\"'\`][^\"'\`]*(hint|status)[^\"'\`]*[\"'\`]" --include="*.jsx" app/src | grep -v "\.test\."
```

The first returns hits in `app/src/styles/app.css` and `app/src/styles/cross-cutting.test.js` only —
four lines in the stylesheet (628, 1731, 1738, 1743) and two in the test. No JSX renders any of the
three. The last renderer, `VersionRow`'s "Links return after you save or cancel." paragraph, went
in `1333a7e`.

The second returns every helper/status class a component actually renders — **five sites, no more**:

| Site | className | Has a type rule? |
|---|---|---|
| `router.jsx:62` | `page-status` | yes — grotesk, `--type-control` |
| `BatchRow.jsx:620` | `tasting-status pen-helper` | `.tasting-status` has **no rule at all**; the face comes from `.pen-helper` |
| `BatchRow.jsx:826` | `form-status` | yes — grotesk, `--type-control` |
| `PenFoot.jsx:31` | `save-ceremony__status pen-helper` | `.save-ceremony__status` is `margin-right: auto` only; the face comes from `.pen-helper` |
| `PenFoot.jsx:35` | `save-ceremony__hint` | yes — grotesk, `--type-control` |

So the live set for a **type-role** assertion is four rules:

```
'.page-status', '.form-status', '.save-ceremony__hint', '.pen-helper'
```

Three findings that fall out of it, and that the SUMMARY should record:

- **`.pen-helper` is the reason the second block's assertion has to change.** It declares
  `text-transform: none` and `font-style: normal` — the guarantee stated positively. The old test
  asserts the declaration is *absent*, so a naive retarget goes red on the one rule that carries the
  guarantee most widely. Assert the value, not the absence.
- **`.save-ceremony__status` and `.tasting-status` are live class names but not type rules.** Their
  face and size arrive through `.pen-helper` on the same element. Putting either in a
  `font-size: var(--type-control)` assertion fails against a rule that never claimed the role.
- **`.save-ceremony__hint` is live per CONTEXT.md and stays in the set.** Its renderer exists at
  `PenFoot.jsx:35`, gated on a `hint` prop that no current caller supplies (`RecipePage.jsx`'s
  `PenFoot` mount at ~1863 passes no `penHint`). CONTEXT.md locks it as live and out of scope — do
  not edit it, do not "clean it up", and do not let the missing caller become an argument for
  deleting it. It is read by a test and otherwise untouched.

`.field-requirement, .field-error` (~2215) read `--size-small-print` by deliberate decision from
quick task 260916-xbh. They are the field scope, a different role. They stay out.

Nothing in `binder.test.js` or `columns.test.js` counts rules in a way that deleting three of them
disturbs (`binder.test.js:310` counts `@media` occurrences at 6; none of the three sit in a media
block).

### 3. Where the version pen's region goes, and why it reuses `formStatus`

CONTEXT.md offers `PenFoot`'s `status` prop "or an equivalent region belonging to the version pen".
The prop is not available without restructuring: `PenFoot`'s `openPen === 'plan'` branch (~88-108)
renders its own three buttons and never mounts `SaveCeremony`, and `SaveCeremony` hardcodes "Save
batch". Mounting it for the version pen would be a redesign, not a move.

So: the equivalent region, in the pen, mirroring the batch pen's own — `VersionRow.jsx`'s
`openPen === 'plan'` branch, immediately above `.headnote__ceremony` (~131). The pen's fields, then
its status, then its act. It sits in the front matter beside the Version field the refusal's focus
already lands on, and it unmounts with the pen, which is exactly the property the page scope exists
to escape for the *successful* save.

The channel is the existing `formStatus`, not a new state. `formStatus` **is** the form scope — the
todo's middle row — and the two pens can never both be open: `RecipePage.jsx` mounts `BatchRow`
behind `{mode !== 'developing' && ...}` (~1745), and `BatchRow`'s own `.form-status` renders only
inside its `mode === 'recording'` branch. Exactly one `.form-status` element exists at a time.
`announce`'s default target is `'form'` and it persists unless passed `selfClear: true`, so
`persist: true` is honoured by construction.

### 4. House style for the tests

`renderToStaticMarkup` from `react-dom/server`, node environment, no jsdom, no testing-library, no
click driver (`VersionRow.test.jsx:1-14`, `RecipePage.test.jsx:1-22`). Nothing here can press Save.
Item 2's coverage is therefore two-sided: the markup test proves the pen owns a region, and a
source-text guard proves the routing into it. `cross-cutting.test.js` already sets the precedent for
reading a source file as text and asserting the contract it states.
