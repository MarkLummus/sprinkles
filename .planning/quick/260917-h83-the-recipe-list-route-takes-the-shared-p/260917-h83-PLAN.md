# The recipe list route takes the shared page gutter

`4bcac2f` gave four boxes one left edge through `--gap-page` and recorded the one route it did not
reach: the list. `RecipeList.jsx` returns a bare fragment, so `.recipe-list__transfer` and the list
itself sit flush at 0 at every width — on the app's entry screen, the one route that looks unframed.
This closes that gap by adding a fifth consumer of the same property. It adds no token, no breakpoint
and no at-rule; where the value lives and why was settled one commit ago and is not reopened.

One task, one commit.

## Discovered at planning — read this before editing

Every line number was read live on 2026-09-17 against the current tree; every claim marked MEASURED was
executed, not reasoned. They guide, they do not authorize (#3786) — re-grep and trust the file.

**The route's states.** Four branches, three of which paint: the populated list, the empty store
(`renderRows([])` is a real tested branch), and the import-error list nested inside the transfer bar.
The fourth (`versions === null`, :66) returns `null` and paints no element at all, so it has no edge to
place. A wrapper around the fragment's two children therefore covers every state the route can show —
see `must_haves.key_links` for the branch-by-branch reading.

**`RecipeList.test.jsx` is not in this diff.** It renders `RecipeRows`, not `RecipeList`, and asserts
only `<li>` counts and substrings. The wrapper lands above `RecipeRows`. Nothing there goes red.

**The baseline is measured, not quoted:** `npm --prefix app test` → 34 files, 982 tests, run at planning
time on a tree clean under `app/` (only untracked `.planning/` files present).

**The name is `.list-page`** — taken from DESIGN.md:215 and app.css:15, which both already call this
route "the list page". It pairs with `.recipe-page` and shares no class token with `.recipe-list`, so it
collides with nothing and no `.recipe-list…` selector newly matches.
