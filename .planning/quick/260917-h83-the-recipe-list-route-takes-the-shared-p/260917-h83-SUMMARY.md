# The recipe list route takes the shared page gutter — Summary

The list route (`/`) now shares `--gap-page` — the same token `.recipe-page`,
`.running-head`, `.not-found`, and `.page-status` already read — closing the
one gap 260917-gjo (`4bcac2f`) recorded and left: the list was the app's
entry screen and the one route that looked unframed.

## What changed

- **`RecipeList.jsx`** — the bare fragment that opened at the `return`
  (previously `<>...</>`) became `<div className="list-page">...</div>`.
  Its two children (`.recipe-list__transfer` and `<RecipeRows .../>`) kept
  their order, props, and relative structure — only the wrapper element
  changed. Nothing else in the file changed.
- **`app.css`** — one new rule, `.list-page { padding: var(--gap-page); }`,
  placed directly above `.recipe-list`. One declaration, the same one-value
  shorthand `.recipe-page` carries, commented in prose only (no `name: value`
  shape, to avoid the count-gate/token-map trap 4bcac2f already hit once).
- **`cross-cutting.test.js`** — four edits: the shared-gutter test widened
  from four to five boxes with a new `.list-page` assertion; its enclosing
  describe title updated to five; the no-media-override guard's
  `guardedSelectors` gained `.list-page`; one new assertion (reading
  `RecipeList.jsx` as source through a new `RECIPE_LIST_JSX_PATH` /
  `recipeListJsxSource` pair, mirroring the existing `MAIN_JSX_PATH` /
  `mainJsxSource` pair) pins that `className="list-page"` appears exactly
  once in the rendered component.
- **`tokens.css`** — comment-only amendment inside `--gap-page`'s existing
  comment: the enumeration of consumers gained the list route's page body,
  and "four boxes, one gutter" became "five boxes, one gutter". The
  declaration itself (`--gap-page: var(--gap-xl);`) is untouched.

## The route's paint states

`RecipeList.jsx` has four branches, only three of which paint:

1. `versions === null` (line 66) — returns `null` before any element
   exists. This branch paints nothing, so it has no edge to place and the
   wrapper cannot be "missing" there.
2. `versions === []` — the empty store — paints `.recipe-list__transfer`
   plus an empty `<ul class="recipe-list">`.
3. `versions` non-empty — the same transfer bar plus the recipe rows.
4. Import errors (set at import-time on invalid JSON or a validator
   rejection) — rendered as `.recipe-list__import-errors` nested *inside*
   `.recipe-list__transfer`.

The new `.list-page` wrapper sits around the fragment's two children (the
transfer bar and `<RecipeRows>`), so states 2, 3, and 4 are all inside it —
one wrapper covers every state the route can actually show.

## `.recipe-list__import-errors`'s padding stays

Its `padding-left: var(--gap-m)` (app.css) is a bullet-marker indent, not a
page gutter, for two reasons: (a) unlike `.recipe-list`, that `<ul>` does not
reset `list-style`, so it renders discs and the padding replaces the
browser's own ~40px marker indent with the project's own; (b) it sits two
levels inside the new wrapper (`.list-page` > `.recipe-list__transfer` >
`ul`), so it can never draw the page's left edge. After this change the
bullets sit at gutter + 20px, which is the expected shape for an indented
list inside a page gutter. Out of scope; left untouched.
