Grounded facts (verified by the planner in a scratch spike against HEAD, React 19.2.8, jsdom 30.1.1, Vitest 5.0.0):
- jsdom never reports validity.badInput on a number input; its ValidityState has no badInput state. To model the browser's report for a lone minus (value '' with badInput true, per 03.5-31-SUMMARY.md line 147), shadow the property on the node with Object.defineProperty(input, 'validity', { configurable: true, value: { badInput: true } }). readSignedInput reads event.target.validity.badInput, and event.target is that same node.
- React tracks an input's value through an instance-level value property. A plain input.value assignment updates React's tracker too, so React then sees no change and onChange never fires. To move the DOM value the way the browser does, call the prototype setter: Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set.call(input, v).
- A native 'input' event always reaches onInput, and reaches onChange only if the value moved since the tracker last saw it. A native 'change' event reaches onChange (if the value moved) and never onInput. That is how the two paths are isolated.
- jsdom provides WheelEvent. A bubbling 'wheel' event dispatched on the focused input reaches React's onWheel, which blurs it. jsdom never steps a number input on wheel, so "value unchanged" is trivially true there; the blur is the meaningful assertion.
- Setting globalThis.IS_REACT_ACT_ENVIRONMENT = true at the top of the file silences React's "The current testing environment is not configured to support act(...)" warning, which otherwise prints twice per mount.
- Vitest filters are relative to app/: npm --prefix app test -- --run src/ui/BatchRow.test.jsx runs that file (159 tests). The form app/src/ui/BatchRow.test.jsx matches no files and exits 1.
- Baseline at HEAD: 54 test files, 1501 tests, all passing. git status --porcelain app/ prints nothing.
