<objective>
Hide the Instructions section (`section.method-region`, its "Instructions" heading and its "Before you start" subhead) when it would show nothing. Mark agreed on 2026-10-03 ("Option 1 is good"): hide the whole section. Sid saw the empty section on Strawberry v2 and v2.1, Coconut v1 and v2, Standard Base, Underbelly and Mocha v0.

Purpose: an "Instructions" heading over an empty list reads as missing content. Leaving the section out is the convention the page already follows: the margin's advisories render nothing when there are none (RecipePage.jsx comment at ~606). The print brief does the same: "side 2's *This recipe only* group is absent, not an empty heading" (.impeccable/surfaces/route-print-recipe-sheet.md line 74).

**The decision for each mode.** The planner read Method.jsx 553-865, Authored.jsx and RecipePage.jsx 600-660, 975-1090 and 1964-2136. The rule is: render the section when `mode === 'developing'`, or the steps passed to Method are non-empty, or beforeYouStart has at least one note.

| State | Steps Method receives | Controls when the method is empty | Decision |
|-------|-----------------------|-----------------------------------|----------|
| reading, with or without a batch in view | `readingVersion.method` (removed steps filtered out) | none: changed lines hang on steps | hide when there is no step and no note |
| Show changes | `version.method` unfiltered, so removed steps still show struck | none | hide when the unfiltered method is empty and there is no note. A version whose only steps are removed keeps the section, struck. |
| recording or amending | `readingVersion.method` | none: the strike and line controls (StepRecordingControls) exist only per step, and NoteList is plain text outside the pen | hide when there is no step and no note |
| developing pen | `version.method` | none today (see the flag below) | always keep, per the orchestrator's instruction "the pen shows it empty" |
| print | the same DOM as the reading view | none | hide (the element is absent) |

**Flag for Mark: the pen premise does not match the code.** The task says the maker "adds the first step or note" in the pen, but the pen has no add-step or add-note control. A grep of Method.jsx, Authored.jsx and RecipePage.jsx finds none. NoteList only offers a textarea and "remove" for existing notes, and StepPenBody only edits existing steps. So in the pen, an empty version shows "Instructions" and "Before you start" with nothing beneath them. The plan keeps the pen as instructed, because the explicit test list and Strawberry v2.1 pen check require it. If Mark wants the pen to hide the section too, the change is one line: drop the `mode === 'developing'` arm of showsMethodRegion.

**What the layout change affects.**
- At 984 and above, the grid is `'ingredients side' / 'method side'`. Below 984 it is `band / ingredients / side / method / foot` (app.css lines 424-435 and 2316-2327).
- An explicit grid row with no item still keeps its gutters. Hiding the section alone would therefore leave one extra row gap: 20px (`--gap-m`) below 984 and 32px (`--gap-l`) above. Task 1 measures that gap before Task 2 closes it.
- Task 2 closes it with a `.recipe-page--no-method` modifier that drops the method row, at the base and inside the 983.98px block.
- `.side-region` never moves. Below 984 it sits above the method row; at 984 and above it starts on the ingredients row.
- `.method__before`'s graduation rule lives inside the section, so it leaves with it.
- No code scrolls to, focuses or links to `#method-step-*`.
- The print block (~2718) carries no grid rule, so print inherits the same layout.

**Sketch and brief audit (report only, nothing overridden).** No board in .planning/sketches/011-recipe-route-c draws an empty Instructions section. Every board that shows Instructions shows the olive-oil steps. 393-all-folded draws Instructions as a closed fold; its README row calls it "exploration… Not a decision". **Two observations outside scope** (Mark decides; neither is changed here):
