<objective>
Go to batch opens a closed Batch fold, then lands on the Batch heading (sketch 011 decision 50, decided by Mark 2026-10-05; Mark's List row build-go-to-batch-opens-fold).

Today the Batch fold (quick 261004-uyd) keeps its state inside BatchRow. A maker who has pressed Hide and then uses Go to batch lands on a closed head. This is the Go to batch row from 724 to 1365 and the phone's Go to batch: the same `GoToBatch` element, which CSS hides from 1366. After this plan, Go to batch opens the fold, then focus lands on `h2#batch` below the sticky bar with its ring whole.

How: reuse the two mechanisms already there, with no second one.
- The fold stays one `useFold(true)`. Its state moves up into RecipePage, where Balance's fold already lives (RecipePage.jsx, `useFold(sheetTwoColumns)` above the early returns).
- The jump stays `handleGoToBatch`, which increments `focusBatchAttempt`, so BatchRow's existing landing effect focuses h2#batch. The handler opens the fold first, in the same React update. So the body is shown before the landing focuses the heading, and the browser scrolls on the open page.

Why the state moves up, and not a new prop plus an effect in BatchRow. An effect that opens the fold would run in the same commit as the landing effect, so focus would land while the body is still hidden. The browser would then scroll on a shorter page. A render-time state change would avoid that, but it is fragile under the app's StrictMode. Lifting has a precedent and keeps the order plain.

Why the amendment save is not touched. It shares `focusBatchAttempt` (RecipePage.jsx, the two lines after `onPageStatus(batchSavedStatus(record))`). A Correct from a closed fold returning closed is undecided and out of scope. Only `handleGoToBatch` opens the fold.

Not in scope: a Correct from a closed fold returning closed; moving to another batch reopening the fold; the table head, Sheet rows, tab ring, hairlines, More's items, Import errors, the notice; `GoToBatch.jsx` and `useFold` themselves; any CSS. No probe: at focus time the DOM is the open-fold landing that 261004-uyd G7 already measured. The new jsdom test pins that the body is shown at the moment of focus.

Output: two test commits and one code commit, plus the SUMMARY (not committed; the orchestrator's docs commit takes it).
