<objective>
Re-order the Search by Sheet code failure lines and fold the blank line into the wrong-length line. Mark decided this on 2026-10-12. It amends quick task 261012-ck1.

Today the order is blank, then another character, then U, then length. The new order is:
1. Wrong length, which now includes blank. The line is 'A Sheet code has eight letters and numbers. This one has N.', so an empty field reads 'This one has 0.'.
2. Another character outside the alphabet that is not U: 'Sheet codes use only letters and numbers.'
3. A U: 'Sheet codes never use the letter U.'
4. 'No version has this code.' for a well-formed code nothing matches.

N counts by code point, so an emoji is one symbol.

Purpose: the person holding a printed sheet first learns whether they typed the right number of symbols, which is the most common slip. Only then are they told about a stray mark or a U. The words are the whole signal, with no colour (UX1-03, PRINT-04).

Output: codeProblem re-ordered, with blank merged into length and code-point counting. The blank constant and case are removed from the Search component. Both test files are updated to the new order, with an emoji case added.

Out of scope: normaliseCode, codeSymbols, findVersionsByCode, handleSubmit, the store-error line and every other file under app/. No CSS, token, markup, link or button change. Executors write nothing to Mark's List.
</objective>
