<objective>
Make Home's 'Next version' link (Tasted standing) land on the latest version page with the Next version pen already open, so starting a next version takes one tap instead of two. Mark decided this on 2026-10-12 (Mark's List row decide-home-next-version-link-opens-pen, answer 'Open the pen straight away').

Purpose: today the link goes to the version page and the maker must then press Next version a second time. The new flag reuses the existing route-state mechanism the band's Record a tasting uses (startTasting), and opens the pen through the button's own handler, so everything the button gives (the copied Sheet title, draft keeping, Escape and Cancel) stays identical.

Output: a route-state flag on one Link, one consume-once effect in RecipePage, unit tests on both sides, and a WebKit tap probe in this quick task's directory.

Decisions made in this plan (Claude's discretion, record them in the SUMMARY):
1. Flag name: `startNextVersion`, mirroring `startTasting`.
2. Consume-once mechanism, reused exactly from the startTasting effect (app/src/ui/RecipePage.jsx lines 1176-1199). A `useRef(false)` consumed guard covers StrictMode's double effect and re-runs. `navigate({ pathname: location.pathname, search: location.search }, { replace: true, state: null })` replaces the history entry's state, so Back, Forward and reload carry no flag. Both run before the pen opens, and the effect waits for `draftRestoreDone`, so a kept draft always gets there first.
3. What "a kept draft for this recipe exists" means here. (a) A draft kept on this version is decided by the existing restore: a fitting one reopens its own pen (mode is no longer 'reading', so the flag opens nothing); a stale one is deleted by the restore and the flag then opens a fresh pen. (b) Any kept draft record on another version of the same recipe, of any kind, means the flag opens no pen and the page shows as today. This is the cautious reading of the task's rule. A draft on another recipe's version does not count.
4. HomeLead renders `<RowActions entry={entry} />`, so it is covered by the one Link change. It has no separate Next version link. RecipeHistory, BatchRow and VersionRow have no Home link to change.
</objective>
