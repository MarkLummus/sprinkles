<objective>
Fix Mark's List bug `bug-pen-note-delete-then-edit-provenance`.

## The bug

`removePenNote` (app/src/domain/penDraft.js ~394) filters a note out of `draft.authored[listKey]`, so every later note moves up one index. `setPenNoteText` (~381) then compares the edited note with `version.authored[listKey][index]`, using the note's CURRENT index. Remove note 0 of two and the survivor (originally note 1) is compared with the removed note. Two things go wrong:

- Typing the survivor back to its own text clears its marker.
- Typing the removed note's text into it gives it the removed note's marker.

Either way, a wrong `inheritedFrom` reaches the saved version.

## The fix (chosen design, with the options weighed)

- **Option A: seed each note's origin when the pen opens** (in `penDraftFromVersion`, on each note or in a list beside the notes). REJECTED. It changes the stored draft of every pen that opens, even when no note is removed. The 05 walk records the drafts store payload, including `authored` notes of exactly `{ text, inheritedFrom }`, at the `version-pen-kept-draft` steps `after-debounce` and `reloaded`, so MATCH 94 would break. It would also change behaviour when no note was deleted.
- **Option B: stamp an `origin` field on each surviving note at removal time.** REJECTED. `penFieldsFromDraft` and `penDraftVersion` pass `penDraft.authored` through as is, so the save path would have to strip the field. That means editing `penFieldsFromDraft`, and penDraft.test.js line 337 pins `fields.authored` to the draft's own object.
- **Option C: CHOSEN.** A draft-level map `penDraft.noteOrigins`, shaped `{ [listKey]: [originIndex, ...] }`.
  - It is absent until the first removal.
  - Only `removePenNote` writes it, filtering it in step with the note list.
  - `setPenNoteText` reads `draft.noteOrigins?.[listKey]?.[index] ?? index`.
  - `penFieldsFromDraft` and `penDraftVersion` pick their fields by name, so the key cannot reach a saved record and nothing on the save path is edited.
  - With no removal there is no key: the draft, the stored draft, the saved record and the walk are byte-identical to today.

  The item says "make each draft note carry what it was inherited with (... or its original position)". Option C carries the original position beside the list rather than on each note object, for the save-path reason above. Record this as a stated deviation in the SUMMARY.

## Kept drafts (decided explicitly)

- `DRAFT_SHAPE_VERSION` stays 1. Bumping it would make every kept draft fail `draftMatchesVersion` and be deleted quietly, which loses the maker's ink.
- `fitsPlanShape` in app/src/domain/draft.js is NOT edited. It reads only `note.text`, so drafts with or without `noteOrigins` both restore. `carriesUnsafeKey` already walks every object in the record, `noteOrigins` included.
- A draft stored before this change has no `noteOrigins`:
  - If it has no removal, its positions still line up, so the comparison is correct.
  - If it already had a removal, the draft cannot say which note it lost. It keeps today's by-position comparison. That cannot throw, because every current index lies inside the version's list.
  - It is not migrated. The project prefers a reset over migration work when no live data depends on it, and the window is one kept draft that spans this deploy with a removal already made.
  - Task 1 tests this case.

## Context the executor should know

No app code path creates a non-null marker today: the seeds carry `inheritedFrom: null`, and `createChildVersion` copies whatever the parent had. So the bug reaches a saved record only through notes imported with a marker. No seeded note can show the marker, so there is no visible device check. The walk and the tests are the evidence.

Purpose: a note's provenance marker reflects the note's own origin, whatever the maker removed first.
Output: the fix in penDraft.js, six domain cases in penDraft.test.js, three store round-trip cases in a new app/src/store/pen-note-roundtrip.test.js, and a SUMMARY.
