<objective>
Close WR-02 of the Phase 5 code review (`.planning/phases/05-split-the-recipe-page/05-REVIEW.md`, lines 103-116). Today `stripComments` in `app/src/ui/RecipePage.shell.test.js` (lines 15-17) deletes everything after any `//` on a line, and removes `/* ... */` before that. A `//` or `/*` inside a string therefore hides the code after it. As a result `const u = 'http://x'; setDraft(null);` passes three checks: "RecipePage.jsx holds no draft setter (D-12)", the one-place reset counts, and "no dangerouslySetInnerHTML". Those source-text tests are the only guard on the page split's shape, so their false negatives must close. This change is test-only and touches one file.

## The helper (measured at planning, 2026-10-14)

Replace the body at lines 15-17 with one pass that matches a string before a comment. Because the regex matches leftmost, a string that starts before a `//` or `/*` consumes it, so the marker stays code. A comment that starts before a quote consumes the quote in turn. Group 1 is the string. The replacer keeps it, and the replacer turns every comment into the empty string.

```js
// A string is matched before a comment, so a // or /* inside one stays code (WR-02).
const STRING_OR_COMMENT = /('(?:\\.|[^'\\\n])*'|"(?:\\.|[^"\\\n])*"|`(?:\\[\s\S]|[^`\\])*`)|\/\*[\s\S]*?\*\/|\/\/[^\n]*/g;

function stripComments(source) {
  return source.replace(STRING_OR_COMMENT, (_match, literal) => literal ?? '');
}
```

These were measured on a scratch copy of the six sources and the planned test file:
- **Unchanged output on today's sources.** RecipePage.jsx, usePenDraft.js, useRecordDraft.js, penDraft.js, recordDraft.js and IngredientTable.jsx strip to text byte-identical with the old helper's output. The 24 existing tests keep passing for that reason, not by luck.
- **The planned test file runs 30 tests, all passing.**
- **Under the old helper,** exactly the five new string cases fail (5 failed, 25 passed).
- **Under an identity helper,** the real-comments control fails.

## Why not the review's suggested one-liner (Claude's discretion, stated)

The review proposed keying on the character before `//`. That still treats `"a // b"` and `` `${base}//x` `` as comments, and it keeps the block pass that eats `'/*' ... '*/'`. Measured: 3 of the 5 string cases still fail under it. The item asks that `//` inside a string no longer read as a comment, so this plan uses the string-aware single pass.

## Known limits (stated, not fixed)

Regex literals and JSX text are not tokenised. A regex literal that ends in an escaped slash, or a JSX apostrophe sharing a line with a string, can still misread one line. The old helper had both limits too. None of the six sources hits either today, which is why their output is byte-identical. Fixing these would take a real tokenizer, which this item does not ask for.
