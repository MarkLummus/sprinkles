<objective>
Fix Mark's List bug `bug-kept-draft-note-origins-unchecked`, which came from the Phase 5 security audit (.planning/phases/05-split-the-recipe-page/05-SECURITY.md, "Notes From The Audit").

## The bug

Quick task e8a (commit 737d2be) added `penDraft.noteOrigins` to the plan draft. For each note list, it records where each surviving note sat in the version the pen opened on. `fitsPlanShape` (app/src/domain/draft.js:190-219) never checks it. So a kept draft with `noteOrigins: {beforeYouStart: [99]}` passes `draftMatchesVersion`. The next note edit then reaches `setPenNoteText` (app/src/domain/penDraft.js:384-393), which reads `version.authored[listKey][99]`. That is undefined, so reading `.text` from it throws a TypeError inside the state updater.

## What a legitimate noteOrigins looks like (read from the code)

- **Absent.** `penDraftFromVersion` never writes the key, and neither does `setPenNoteText`. A draft with no removal therefore has no noteOrigins, and neither does any draft kept before 737d2be. Absent (`payload.noteOrigins === undefined`) must keep passing.
- **Written only by `removePenNote`** (penDraft.js:403-410). On the first removal it starts from `draft.authored[listKey].map((_, i) => i)`. On later removals it starts from the existing `noteOrigins[listKey]`. Either way it filters the notes and the origins at the same index. So the value is always a plain object `{ [listKey]: [integer, ...] }` where:
  - every entry is an integer from 0 up to the version list's length minus 1, so it points at an existing version note;
  - the array is exactly as long as the draft's own list for that key. The pen has no way to add a note: `NoteList` in app/src/ui/Authored.jsx offers edit and remove only, and nothing else writes `authored`. So nothing ever makes the two lengths differ, and an origin is never null.
  - an empty array is legitimate. It means every note was removed (the draft list is `[]` too).
- **The only list key the app writes is `beforeYouStart`.** RecipePage.jsx:1660 passes `listKey="beforeYouStart"`, and `validateVersion` in app/src/store/transfer.js:506 requires `version.authored` to hold exactly that list. The rule below does not hard-code the name. A list key is known when the version's `authored` holds it as an own key whose value is an array, which today means `beforeYouStart`. The own-key test refuses names such as `toString` that only exist on Object.prototype. `carriesUnsafeKey` already refuses `__proto__`, `constructor` and `prototype` earlier in `draftMatchesVersion`.
- **Ordering and distinctness are not checked.** The app always writes strictly increasing origins. A duplicate or out-of-order origin still points at an existing note and cannot throw. A rule for it would go beyond what the bug asks for.
- **Why length equality is in the rule.** The bug row asks for in-range integers. Length equality is the one further clause, and it is needed to close the crash. `setPenNoteText` falls back to the note's own index when `noteOrigins[listKey][index]` is missing (`?? index`). If the origins array were shorter than the draft's list, a trailing note would fall back to its own index, which can sit past the end of the version's list. The app never writes such a draft, so the clause rejects nothing the app writes.

## Out of scope (flagged, not fixed)

There is a sibling case with no noteOrigins: a draft whose `beforeYouStart` list is longer than the version's. On an edit at an index past the version's list it takes the `?? index` fallback and throws the same way. The app cannot write it, because the pen cannot add notes. The bug row is about noteOrigins, so this plan leaves that case alone, and the SUMMARY names it as a possible follow-up row for Mark.

Purpose: a kept draft the pen cannot safely edit is refused on restore and deleted quietly, as every other unfit draft already is. It never crashes the pen later.
Output: `fitsNoteOrigins` in app/src/domain/draft.js and a new describe block in app/src/domain/draft.test.js.
