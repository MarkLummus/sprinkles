## Decisions

- **R-1 (re-review WR-01).** `rowFromLibraryRecord` throws `TypeError('library record entry needs a composition of finite numbers')` when `entry.composition` is null, not an object, an array, or has a non-finite value. `{}` passes, as in `validateRow` and `validateLibraryRecord`. The check sits after the entry check and before the name check. `transfer.test.js` pins builder and import check to the same verdict for nine compositions, each with an explicit expected result.
- **R-2 (re-review IN-01).** Accepted keys 2, 0, -3 give 3, 1, 1; refused keys 2.5, 2**53, '1' make `nextStepKey` throw a RangeError. The old combined test is replaced by two `it.each` blocks.
- **R-3 (first review IN-01).** `createChildVersion` spreads `Object.fromEntries` over the five keys the parent owns, at the position of the old five lines, so key order is unchanged for seeded parents. Premise correction found at planning: only `olive-oil-ice-cream-v1` owns a version-level `targets`. The other 18 seed versions do not, so their children no longer own `targets: undefined`. No reader can see the difference (no `in` or `hasOwn` check on those keys, `diff.js` reads `targets ?? {}`). The child of oliveOilVersion keeps all five keys by reference.
- **R-4 (first review IN-02).** The specifier regex now accepts either quote with a back-reference (`(['"])([^'"]+)\1`, read from `match[2]`) and the bare-import check uses `['"]`, fixed in place in `newRecipe.test.js`, `stepKeys.test.js` and `versionRow.test.js`. No helper, no new file.
- **R-5 (first review IN-03).** `createRecipe` stores `versionLabel.trim()`. Divergence to note: the pen's save path (`penDraft.js` through `createChildVersion`) still stores a child's label as typed. Uniqueness is unaffected because `versionLineUnique` trims both sides. The pen path is not changed because that would be maker-facing.
