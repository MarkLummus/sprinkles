<objective>
Fix Mark's List row `bug-stale-draft-survives-pen-opened-during-read`. Mark answered `fix`.

The bug: in app/src/ui/useKeptDraft.js, the restore effect handles a matching stored draft that arrives after the maker has already opened a pen. That is the late-read branch, `if (modeRef.current !== 'reading')`, at lines 126-131. It returns without recording that a draft is still in the store. The persist effect's clean-pen delete (lines 185-193) runs only when `draftStoredRef.current` is true. So if that pen is cleared back to clean, the stored draft is never deleted, and it reopens on the next visit.

The fix: in that branch, set `draftStoredRef.current = true` before `setDraftRestoreDone(true)`. Then a pen that goes clean deletes the stored record, and a pen that stays dirty overwrites it on the next persist. The hook's own comment for that branch already states this rule: "A pen the maker opened while the read was out wins over the stored one; the persist effect then keeps whichever is open." The fix makes the code do what the comment says.

Purpose: the core value says a maker gets back what they actually did. A draft the maker abandoned must not come back as if it were kept.
Output: two new tests in app/src/ui/useKeptDraft.test.jsx, a one-line code change in app/src/ui/useKeptDraft.js, and one `fix(draft):` commit.

Planner contributions: security, schema-gate, assumption-delta and ai-integration do not apply to a one-line hook fix. None apply.
</objective>
