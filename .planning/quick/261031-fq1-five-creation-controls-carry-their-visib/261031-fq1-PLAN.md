<objective>
Mark answered `bug-p11-label-in-name-mismatches` with Fix (2026-10-31). Five controls in the creation editor have an accessible name that does not contain their visible label, which fails WCAG 2.5.3 Label in Name. A voice-control user who says "Add target" has nothing to match.

Each name gets the visible words verbatim, case included. The name's extra context comes after them, or before them where the step's existing "Step N, ..." pattern already sits there. The visible words do not change: sketch 014 decision 8 settled them for the inline controls, and decision 11 for the boxed ones. Decision 8 had also left every aria-label alone. Mark's Fix on this bug changes these five, and no others.

The strings, settled here (HEAD db1b2c06):

| Control | Where | Visible | Name before | Name after |
|---|---|---|---|---|
| Add target | `app/src/ui/CreationSteps.jsx` line 151 | Add target | `Step ${number}, add a target` | `Step ${number}, Add target` |
| Preview toggle, closed | `app/src/ui/CreationSteps.jsx` line 156 | Preview step | `Step ${number}, preview the step` | `Step ${number}, Preview step` |
| Preview toggle, open | `app/src/ui/CreationSteps.jsx` line 156 | Hide preview | `Step ${number}, hide the preview` | `Step ${number}, Hide preview` |
| Add step (on a step) | `app/src/ui/CreationSteps.jsx` line 273 | Add step | `Step ${number}, add a step after it` | `Step ${number}, Add step after it` |
| Move up (row) | `app/src/ui/IngredientTable.jsx` line 296 | Move up | `Move ${name} up${inStep}` | `Move up, ${name}${inStep}` |
| Move down (row) | `app/src/ui/IngredientTable.jsx` line 306 | Move down | `Move ${name} down${inStep}` | `Move down, ${name}${inStep}` |
| Add to step (row) | `app/src/ui/IngredientTable.jsx` line 315 | Add to step | `Add ${name} to a step` | `Add to step, ${name}` |

Why these shapes:
- The step's names keep the "Step N, ..." lead that every other step control has ('Step 1, remove', 'Step 1, move up'), so the visible words come second.
- The row's names start with the visible words, and the ingredient and the step follow, as Mark proposed.
- The visible words are copied verbatim, capital first letter included. Mark asked for matching case "where it costs nothing". Speech output does not voice case, and voice control matches without regard to case.
- The step's sibling names stay lower case ('Step 1, add purpose', 'Step 1, move up'). They already contain their visible words once case is ignored, and they are out of scope.

The neighbours, checked as asked:
- A row's Remove, named `remove ${name}` at `IngredientTable.jsx` line 289, passes when case is ignored.
- A target's Remove, named `Step ${number}, remove target ${index + 1}` at `CreationSteps.jsx` line 143, also passes when case is ignored.
- Both stay as they are. The new tests prove that both pass.

Purpose: the creation editor meets WCAG 2.5.3 for the five controls Mark's bug row names, and a test keeps it that way.
Output: two source files with six aria-label lines changed, four test files following the names, and two new Label in Name tests.
