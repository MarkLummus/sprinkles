<objective>
Fix bug-next-version-cancel-focus-after-save (Mark approved it on Mark's List). After arriving on a version from a save (history state focusVersion), Next version then Cancel puts focus on the version heading instead of the Next version opener. Make the arrival landing happen once, so Cancel returns focus to Next version. Write the failing test first.

Root cause, reproduced in jsdom at planning HEAD 4e678dfa (scratch probe, app untouched): VersionRow.jsx has two effects keyed on mode. The Develop focus-return (about lines 95-106) focuses Next version when mode leaves 'developing'. The arrival landing (about lines 137-144) focuses the identity heading whenever focusVersionOnMount is true and mode is 'reading'. On Cancel, mode returns to 'reading', both effects run in declaration order, and the landing runs last, so the heading wins. The probe printed "after cancel: H2 Version 1 · 50 g oil · 800 g · Latest".

The fix, measured on a patched scratch copy: seed a ref from focusVersionOnMount and spend it on the effect's first run, whatever the mode. A ref that is set only when the landing happens is not enough: with a pen already open on the first run (a kept draft restored before the row draws), it would still land on the first Cancel. The probe showed that variant failing and the chosen one passing, also under StrictMode (main.jsx renders inside StrictMode).

A consequence, by the same mechanism: Save over this version on a page that arrived with focusVersion sets mode back to 'reading' the same way Cancel does, so focus will go to Next version there too. That is where it already goes on a page reached without the arrival state. Today the arrival page lands on the heading. The D-27 landing is for a saved child, and Save over this version creates none. Record this in the SUMMARY. Do not add a test or code for it.

BatchRow.jsx, as the batch asked: its landing (about lines 573-580) does not have this defect on Cancel. Its dependencies are focusBatchOnMount and focusBatchAttempt, with no pen state. useBatchRecording.js sets focusBatchAttempt to null when a pen opens (about lines 121 and 297), and handleCancelRecording sets it to null again (about line 505), so the value does not change on Cancel. The landing does not re-run, and the Correct and Record focus-returns stand. Do not change BatchRow.jsx in this item.

Purpose: the maker's keyboard place survives a cancelled Next version. On the iPad with the Magic Keyboard, Tab after Cancel goes on from Next version, not from the heading.
Output: a new jsdom test file (committed first, red), then a small change to one effect in VersionRow.jsx (green). Two commits, both naming bug-next-version-cancel-focus-after-save.
</objective>
