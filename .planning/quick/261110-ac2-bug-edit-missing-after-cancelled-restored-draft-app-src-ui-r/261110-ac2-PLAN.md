<objective>
Fix the Mark's List bug bug-edit-missing-after-cancelled-restored-draft (approved fix).

Root cause, read at batch base 4e678dfa: useRecipeData.js (lines 20-24, 65-81) reads every kept draft once at page open into `drafts`, and nothing changes that list afterwards. RecipePage.jsx line 181 computes `editState` with editStateFor({ version, versions, batches, drafts }); editStateFor (app/src/domain/firstVersion.js 50-56) returns null whenever any record under the version's id is in that list. A Next version draft kept from an earlier visit is in the list and is restored into the pen by useKeptDraft. Cancel (useVersionPen.js handleCancelDeveloping, line 69-78) calls the writer's discardDraft, which deletes the record from the store (useKeptDraft.js 70-93, deleteDraft(versionId, 'pen')), but the page's list still names it, so editState stays null and Edit is missing until reload. The record pen has the same path: useBatchRecording.js handleCancelRecording (line 501-) calls the same discardDraft, so a restored Record batch draft hides Edit after Cancel the same way. Save over (useVersionPen.js 249-258) also calls discardDraft without leaving the page, so it is fixed by the same change.

Fix (Claude's discretion, recorded): the page hands both pens a discardDraft of its own that calls the writer's discardDraft and, once that delete has resolved, drops this version's pen-family record from the drafts list through a setDrafts that useRecipeData now hands back. Done at the one seam both pens already share, so neither pen hook changes. The list is trimmed only after the delete resolves, never before: while the record may still be stored, Edit must not be offered (the T-11-56 rule that Edit never shows while a disqualifying draft exists), because an edit opened over it would write its edit draft on the same version key.

The waiting-draft band line and the History rail draft node (asked in the batch notes): no discarded draft lingers there. waitingPlanDraft (RecipePage.jsx 336-347) excludes every record whose versionId is this page's version (line 338), so it only ever names a draft kept on another version of the recipe; this page's Cancel and Save delete only this version's own key. The band line (VersionRow draft prop, line 421) and the rail's waitingDraft node (line 440) therefore never name the draft this page just discarded, and useRouteIntents.js line 72 likewise reads only other versions' drafts. The trim leaves other versions' records alone, so those surfaces read exactly as before.

Noticed, not fixed (report in the SUMMARY, do not change): useKeptDraft.js 245-253 quietly deletes a kept pen draft that no longer fits its version, and that record also stays in the page's list, so Edit would be missing until reload there too. It is a different trigger from this row; it is left for Mark to triage as its own row.

Line numbers drift once sibling 261110-abz lands on RecipePage.jsx (around 93 and 371); find every site by content.

Purpose: on a first version with no batch, cancelling a restored draft gives the maker Edit back straight away.
Output: three new tests (red without the fix), setDrafts handed back by useRecipeData, the page's discardDraft wrapper. Two commits: the red tests, then the fix.
