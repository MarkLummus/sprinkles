# Sketch 004: Tiered tastings

## Design Question
Shaped 2026-09-10 with Mark: a batch record simplifies from an unbounded list of full tastings to one primary tasting (full detail: date, temperature, all axis marks, melt test, words, next-time note) plus up to 3 additional light entries (date, marks, one note line only), capped at 4 tastings total. Neither the sketch nor `route-recipe-batch.md` has drawn how these two tiers sit together in the batch row's reading state. The rules bind: no color, no icon, no badge — form and weight only (No-Verdict Rule).

Mark's brief for the feel: a light entry should read as **a small, deliberate log entry** — not a scribble, not a full-weight duplicate of the primary tasting.

## Variants
- **A: Same cell-grid, smaller instance** — a light tasting gets the same running-head-plus-cells shape as the primary, just with fewer cells and a smaller figure size, plus one note line beneath.
- **B: One-line log entries** — light tastings drop the cell grid entirely and read as a single line each: date, marks inline, the note in quotes, all under one "Also tasted" head.
- **C: Compact ledger table** — light tastings sit in a borderless table, one row per tasting (date / marks / note), dotted rules between rows.

## What to Look For
- Does the primary tasting still read as the record's main event, or does a light entry beside it compete for attention?
- At "Primary + 3," does the row start to feel long or cluttered? Which variant holds up best at the cap?
- Is it obvious, without any color, which entry is the full tasting and which are quick add-ons?
- Try "Not yet evaluated" — does "Taste again" make sense as the label before any tasting exists, or does the batch need its first tasting called something else?
- Cycle through Primary → Primary+1 → +2 → +3: does "Taste again" disappearing at the cap read as a natural stop, or as a missing button?
